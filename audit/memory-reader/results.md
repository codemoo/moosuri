# 동명이인 장기 대화와 기억 비교

2026-11-20에 합성 인물 한서진 두 명의 기록으로 검증했다. 천문반과 도예반 대화에 501턴씩 교대로 저장했다. 같은 이름의 인물에 대해 서로 다른 보관함 표식, 반납 요일, 작업실을 기록했다. 정답과 정답 턴 번호, 검색어, 질문 셋은 모델 호출 전에 [고정 입력](world.json)에 지정했다. 추출기에는 질문·정답·검색어를 전달하지 않았다.

## F22 동명이인 대화 회상

질문마다 같은 계정에 새 대화를 열었다. 표준 서버에서 사용하는 SQLite의 대화 검색을 모든 소유 대화 범위로 실행하고, 반환된 상위 5개 이내의 턴을 반환된 revision으로 읽었다. 정답 턴 ID가 포함됐는지와 해당 결과를 받은 독자가 정답 문자열을 정확히 반환했는지를 따로 채점했다. 보관함 표식 질문에는 같은 표현의 최근 활동 기록 다섯 개가 앞섰다.

| 질문 | 정답 턴 뒤의 기록 수 | 정답 근거 순위 | 원문을 받은 독자 |
|---|---:|---:|---|
| 천문반 한서진의 보관함 표식 | 1,000 | 상위 5개 밖 | 확인 불가 |
| 천문반 한서진의 반납 요일 | 100 | 1 | 화요일, 정답 |
| 도예반 한서진이 신청한 작업실 | 11 | 2 | 흙빛-28, 정답 |

정답 근거 Recall@5는 2/3, 원문 독자의 최종 사실 정확도는 2/3이었다. 검색 및 반환된 턴의 revision 고정 읽기를 합친 p95는 156.2ms였다.

## F54 세 가지 기억 조건

같은 세 질문을 기억 없이, 과거 대화 검색 결과로, 구조화한 기억 검색 결과로 각각 물었다. 각 질문에서 조건 순서를 순환시켰다. 추출기 한 번에 1,002턴 전체를 주고 최대 12개 원문을 번호로 고르게 했다. 선택된 원문은 표준 저장소의 기억 쓰기로 저장했다. 두 검색 모두 같은 고정 검색어를 받았고, 독자에게 제공한 근거는 최대 5건·4,096바이트였다. 모든 독자는 같은 모델과 시스템 지시, 질문 및 답변 형식을 사용했다. 출력 상한은 512토큰으로 설정했고 CLI 예산 상한은 독자당 USD 0.10, 추출 1회 USD 0.50이었다.

| 독자에게 제공한 근거 | 사실 정답 | 확인 불가 | 일반 입력 토큰 | 캐시 생성 입력 | 캐시 읽기 입력 | 출력 토큰 | 질의 p95 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 없음 | 0/3 | 3 | 6 | 1,966 | 0 | 21 | 2,436ms |
| 대화 검색 원문 | 2/3 | 1 | 6 | 2,293 | 0 | 20 | 2,454ms |
| 구조화한 기억 검색 | 3/3 | 0 | 6 | 2,126 | 0 | 20 | 2,332ms |

토큰은 조건별 세 번의 독자 호출에 대해 CLI가 보고한 합계다. 질의 지연은 해당 질문의 로컬 검색과 CLI 프로세스 왕복 시간을 합했다. 구조화 조건의 사전 추출은 추가 1회로, 일반 입력 2·캐시 생성 입력 336·캐시 읽기 입력 35,551·출력 92토큰과 2,742ms가 들었다. 여섯 개의 원문을 골랐고 SQLite에 기억으로 쓰는 데 2.75ms가 더 들었다. 나머지 두 조건의 사전 추출 호출은 0회였다.

합성 저장·검색은 Rust 및 SQLite에서, 추출과 최종 답변은 실제 Claude CLI의 `claude-sonnet-5-5`·medium에서 실행했다. 원래 제품 에이전트의 도구 선택과 자동 추출 스케줄은 이 실험 범위 밖이다. 대화 응답 본문과 완료 상태는 고정 fixture로 만들었다. 계정별 합성 DB는 새로 생성했고 모델 세션은 호출마다 새로 열었다. 초기 실패 시에도 추출을 호출했으므로 같은 입력이 공급자 캐시에 남았을 수 있다. 공급자 캐시 초기화나 추출 한도 소진은 시험하지 않았다. 표본은 질문 세 개이며 각 조건을 한 번씩 관측했다. p95는 nearest-rank 방식으로 이 표본의 최댓값이다. 요금과 제품 전체의 정확도·지연은 추정하지 않았다.

재현하려면 Rust 도구와 인증된 Claude CLI, Python 3.10 이상이 있는 환경에서 아래 명령을 실행한다. 실행기는 로컬의 고정 합성 입력만 모델에 전달한다. Rust 단독 검사는 `MOOSURI_SYNTHETIC_TURN_NUMBERS='[]'`로 추출 없이 실행할 수 있다.

```sh
python3 audit/memory-reader/run.py
MOOSURI_SYNTHETIC_TURN_NUMBERS='[]' cargo test --locked -p moosuri-store --lib export_namesake_reader_inputs -- --ignored --nocapture
```

첫 실행은 같은 새 대화에 후속 질문을 접수하려다 진행 중 요청 충돌로 끝났다. 추출 호출 1회가 이때 추가로 발생했다. 각 질문에 독립된 새 대화를 쓰도록 실행기를 수정한 뒤 측정했고, 질문·근거·정답·채점 기준은 유지했다. 기록한 결과는 완료된 한 세트에 대한 측정이다. [호출별 측정값](observed.json)

## 같은 질문으로 수정판 재검증

첫 측정에서 천문반 보관함이 빠졌던 문제를 재현한 뒤 검색어가 실제로 들어 있는 회원의 대화 중 현재 질문의 한정어가 겹치는 기록을 우선하도록 수정했다. 같은 점수의 기록은 최신 순으로 정렬한다. 정답 턴이나 질문별 예외 규칙은 제품에 넣지 않았다.

같은 1,002턴, 검색어, 세 질문, 모델과 추론 강도로 추출 1회와 독자 9회를 새로 실행했다. 세 문항의 정답 근거는 모두 1위였고 원문으로 답한 모델은 세 사실을 정확히 반환했다. 이 표본에서 원문 Recall@5와 최종 정확도는 모두 2/3에서 3/3이 됐다.

| 제공 근거 | 정답 | 일반 입력 / 캐시 생성 / 캐시 읽기 / 출력 토큰 | 질의 p95 |
| --- | ---: | --- | ---: |
| 없음 | 0/3 | 6 / 1,966 / 0 / 21 | 2,150 ms |
| 대화 검색 원문 | 3/3 | 6 / 2,290 / 0 / 20 | 6,512 ms |
| 구조화한 기억 | 3/3 | 6 / 2,126 / 0 / 20 | 2,230 ms |

구조화한 기억의 사전 추출은 별도 1회로 2,840ms, 원문 여섯 건의 저장은 3.15ms였다. 추출 토큰은 일반 입력 2, 캐시 생성 336, 캐시 읽기 35,551, 출력 79였다. 세 질문으로 얻은 p95는 가장 오래 걸린 질문의 값이다. 관측된 질의 시간은 공급자의 응답 대기를 포함한다. [수정판 호출별 측정](observed-ranked.json)

대화문에서 정답 후보를 고르는 비용도 따로 측정했다. 4,096턴 모두가 검색어에 일치하고 정답이 가장 오래된 조건에서, 유효한 상위 후보의 본문·의존성만 정밀하게 확인하도록 변경했다. 같은 기기의 세 번 측정에서 검색 중앙값은 563.25ms에서 106.19ms로 줄었다. 원래 세 질문의 정답 순위는 모두 1위를 유지했다. [측정 조건과 재현 명령](../../openspec/changes/recall-owned-conversations/tasks.md)
