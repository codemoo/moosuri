# 맡긴 조사에서 비공개 보고서까지

현재 사용자 요청에 조사·읽기·비교와 문서 저장을 함께 명시하면 기존 미션이 지원 자료를
읽고 계산한 뒤 비공개 문서 하나를 저장한다. 예: “저장 자료를 읽고 견적을 비교·계산해서
보고서로 저장해 줘”. 현재 요청만 보는 의미 분류가 명확한 위임으로 판단한 경우에만
`private_report` 확인 기준을 붙인다. 자료 안의 저장 지시는 권한이 아니다. 맡긴 일 화면의
“저장할 비공개 보고서 제목”으로도 같은 출력을 직접 요청할 수 있다.

기존 저장 자료·설정한 공개 웹·명시적으로 위임한 연결 Gmail 읽기를 사용한다. 실제 읽기
영수증과 성공한 정확 계산을 결과에 연결한다. 저장 자료의 숫자는 `evidence_calculate`로
실제 검색·원문 읽기 영수증과 현재 요청의 값에 묶을 수 있다. 일반 decimal 계산은 산술만
증명하며, 자료를 먼저 읽었다는 이유로 그 숫자를 계산에 사용했다고 표시하지 않는다.
계산을 요청한 미션은 계산 영수증 없이 문서를 저장하지 않는다. 계산을 요청하지 않은
비교 보고서에서는 계산 단계가 생략될 수 있다. 연결·원문·공개 웹의 기존 범위는 유지된다.

계획은 사용자에게 최대5개 제목을 보이고, schema1 계약은 읽기·비교·계산·문서의 안정된
4개 내부 단계를 저장한다. 단계마다 목적, capability, 입력 slot, 실제 receipt, 선행 단계,
산출물, 검사 조건과 상태를 기록한다. 계약은 기존 run·소유자·현재 acceptance revision과
처음 접수한 tool profile 해시에 묶인다. 과거 문자열 계획에는 계약이나 저장 권한을
소급해서 만들지 않는다. 조건을 바꾸면 새 acceptance의 계획과 새 영수증이 필요하다.

마지막 결과 검사는 기존 artifact writer를 사용해 실제 문서 ID·revision·링크와 미션 결과를
한 SQLite transaction에 저장한다. 안정된 mutation UUID로 재시작·응답 유실 뒤 같은
문서를 중복 생성하지 않는다. 실제 읽은 자료의 전체 의존성과 기존 외부 provenance를
이어받으며, 자료·연결·원래 미션 기록의 철회는 파생 문서와 그 문서에서 만든 자료까지
전파된다. 복원한 실행이나 문서로 옛 쓰기 권한을 되살리지 않는다.

문서 저장은 내용의 품질을 증명하지 않는다. 출처별 주장·누락·충돌과 비교 결과는 별도
검토 상태이며, 화면은 실제 문서 링크와 “검토 필요”를 함께 표시한다. 이 단위는 외부 발송,
공유 파일 업로드나 기존 문서 편집 권한을 추가하지 않는다. 실제 계정이나 모델의 의미
이해 능력 검증과 합성 Store/Runtime/UI 검증은 별개다.
