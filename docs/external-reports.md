# 외부 자료를 읽고 문서로 저장하기

새 도구 대화에서 “Gmail과 이번 주 Calendar를 확인하고 회의 준비 보고서로 저장해 줘”,
“공개 자료를 읽고 비교 보고서를 문서로 저장해 줘”처럼 **지금 보낸 요청**으로 문서 하나를
만들거나 수정한다. 이미 같은 대화에서 완료한 지원 읽기를 이어 “이 결과를 보고서로
저장해 줘”라고 요청할 수도 있다. 저장 확인은 실제 문서 ID·버전·링크다.

저장된 자료와 함께 설정한 공개 HTTP 읽기/검색, 연결한 자기 Gmail 검색·본문·스레드·지원
첨부 읽기, 자기 기본 Calendar 읽기를 사용한다. 사용 가능한 연결과 도구가 범위이며,
새 계정이나 권한을 만들지 않는다. 이전 Calendar 변경·작업 결과는 읽기 영수증이 아니므로 문서 근거로 저장하지 않는다. 별도 일상 승인창은 없다. 문서 쓰기 단계에서 메일 초안·
발송·Calendar 변경·브라우저·native credential 미리보기·대화 회상은 사용하지 않는다.

기존 단일 문서 권한, 최대2048 UTF8바이트 채팅 본문·4096바이트 전체 인수, 정확한 제목/선택한
수정 대상, 유일한 수정 anchor, 현재 revision CAS와 모델6회/도구12회 한도를 유지한다.
기존 목표/요청·약속의 외부 직접 읽기 저장은 추가하지 않았다. 일반 편집기로 저장된 문서를
고치거나 그 문서에서 새 기록을 만들면 기존 근거와 철회 의존성도 이어진다.

## 실제로 남는 근거

문서의 **저장된 외부 읽기 근거**와 Markdown/인쇄 HTML은 실제 originating run·step·call,
읽기 종류, typed 요청과 요청/결과 SHA256을 보여 준다. 모델이 만든 인용이나 호출 성공
문장은 이 근거를 만들지 않는다. 메일/Calendar 계정 credential이나 외부 본문을 별도 근거
테이블에 복사하지 않는다. 원래 typed 도구 영수증과 해시로 정확한 관측을 식별한다.
이 내용은 그 계정의 비공개 자료이며 일반 진단/export와 구별한다.

문서당 실제 외부 읽기 근거는 최대64개다. 일부 페이지·잘린 본문·검색 snippet은 읽었던
범위만 증명하며, 보고서 의미의 정확성이나 외부 서비스의 현재 상태를 보증하지 않는다.
외부 변경을 자동 감시하거나 나중에 재검증하지 않는다. 기존 읽기에서 결과 불명·철회·
지원하지 않는 외부 문맥이 섞이면 저장하지 않고 현재 연결로 다시 읽도록 안내한다.

## 수정·철회·복구

문서 수정은 유효한 원래 읽기 근거를 보존한다. 이전 문서 쓰기 본문·비공개 checkpoint·
확인문은 버전 교체에서 은퇴하며, 독립적인 원래 읽기 영수증을 문서 수정 자체로 철회하지
않는다. 실제 연결 해제, 근거/실행 철회나 원래 대화 삭제는 파생 문서의 모든 관련 버전·
제목·본문·export와 그 문서에서 이어진 답변을 철회한다. 철회·삭제한 버전의 읽기 요청 문구도 지우고 식별자·해시만 보존한다. 사용자 로컬 다운로드는 회수하지 않는다.

외부 읽기 뒤 저장한 문서는 원래 대화를 삭제하면 철회된다. 외부 근거가 없는 독립 문서의
기존 대화 삭제 계약은 유지한다. 복원은 외부 근거 문서를 보수적으로 철회하며 cached text나
옛 계정 연결로 되살리지 않는다. 복원 뒤 현재 사용자가 새 요청으로 다시 읽고 저장한다.

Schema54 이전의 진행 중인 대화에는 새 권한을 더하지 않는다. 합성 Store/Runtime/UI 검증과
실제 계정·모델의 이해력 검증을 구분한다. 구현/검증 상태는
[작업 기록](reviews/2026-11-15-external-reports.md)을 따른다.
