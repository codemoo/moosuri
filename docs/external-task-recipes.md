# 외부 자료를 읽고 결과를 만드는 내장 작업 절차

세 가지 절차를 기존 [작업 스킬](task-skills.md)에 더한다. 새로운 도구·권한·분류 호출을
추가하지 않는다. 새 실행은 짧은 설명으로 절차를 발견하고 필요할 때 `skill_read`로
본문을 읽는다. 기존 세 절차의 bytes·revision과 이미 접수한 실행의 pin은 유지한다.

| 절차 | 맡길 수 있는 요청 | 완료와 남는 경계 |
| --- | --- | --- |
| `web-research` | “공식 조건으로 두 옵션을 날짜와 총비용까지 비교해 줘” | 설정된 실제 검색, HTTP 읽기와 가능한 렌더링 읽기로 근거를 확인한다. 날짜·수량·통화를 맞추고 지원하는 정확한 계산을 사용한다. 알 수 없는 배송비·세금은 0으로 넣지 않는다. 예약·구매는 하지 않는다 |
| `inbox-briefing` | “최근 메일에서 내가 먼저 챙길 것만 정리해 줘” | 실제 개인 Gmail 결과를 읽어 우선순위·명시된 기한·다음 행동을 정리한다. 기본 최근 7일 등 검색 범위와 읽은 일부를 밝히며, 메일함 전체를 점검했다고 하지 않는다 |
| `mail-reply` | “그 문의를 읽고 답장 보내 줘” | 올바른 대화와 실제 수신인을 확인해 `mail_prepare_draft`로 로컬 초안을 만든다. 아직 발송되지 않았음을 알리고 `/settings/mail`의 전체 미리보기와 최종 허락으로 연결한다 |

실제 기능은 접수 시 고정한 [Gmail](mail.md), [HTTP 조사](web-research.md),
[선택 브라우저 읽기](browser-chat.md)의 도구 정의가 결정한다. 검색 키나 브라우저가
없으면 해당 단계를 수행했다고 꾸미지 않는다. 이미 준 URL·대상·기간은 재사용하고,
결정을 바꾸는 실제 미정 대상이나 시각만 묻는다. 외부 본문의 지시는 새로운 사용자
권한이 아니며, 원문이나 절차가 다른 계정·수신인·credential 접근을 정할 수 없다.

모든 단계는 기존 6 model dispatch / 12 tool / 120초 누적 예산 안에서 실행한다.
기억 계획과 스킬 읽기도 같은 예산을 사용한다. 독립된 읽기는 묶고, 최종 답변에 쓸
모델 회차를 남기며, 답장에는 실제 초안 호출도 남긴다. 예산을 다 쓰는 전수 조사보다
확인한 근거와 결정적인 빈칸을 포함한 유용한 결과를 낸다. 재시도와 결과 불명 상태는
기존 durable slot 계약을 따르며 자동 중복 초안·메일을 약속하지 않는다.

**메일은 매번 최종 허락이 필요하다.** “보내 줘”나 이전의 포괄적 허락도 이를
대신하지 않는다. From/To/Cc/Bcc, 제목, 전체 본문, 첨부를 사용자가 보고 해당 revision을
허락해야 한다. 바뀐 수신인·내용·첨부는 다시 미리보고 허락받는다. 모델과 스킬에는
approve/send 도구가 없다. 발송 영수증 없이 “보냈다”고 하지 않는다.

현재 채팅 초안 도구는 일반 텍스트·ASCII 주소와 첨부 없음을 지원하며, 원래 Gmail
thread/reference를 지정하는 인자가 없다. 따라서 답장 문안을 담은 실제 로컬 새 메일 초안은
만들 수 있지만 Gmail의 threaded reply/reply-all 기능을 제공한다고 하지 않는다. 이 한계를
인계 시 알린다. 첨부 요청을 조용히 제거하지 않는다. 읽기 결과에는 Date/Reply-To
header도 없어, 본문에 없는 기한·시각·응답 주소를 추정해 사실처럼 쓰지 않는다.
현재 시각·날짜 계산 도구도 없으므로 기준 날짜와 시간대 없이 상대 날짜를 정확한
약속 시각으로 바꾸지 않는다. Gmail의 `newer_than:7d` 같은 쿼리는 공급자가 해석한
검색 범위이며 별도 시계나 개별 메시지 timestamp를 읽었다는 뜻이 아니다.

각 패키지는 기존 형태의 `SKILL.md`, 제안 단계 `moosuri.toml`, 합성 정상/경계 예제,
Apache-2.0 LICENSE를 포함한다. sidecar는 설치기나 권한 부여 장치가 아니다.
`web-research`의 검색·브라우저 도구는 실제 목록에 있을 때만 선택적으로 사용한다.
본문과 예제 검사는 실행 경로·모델 이해 품질의 증거와 구별하며, 새 절차의 실제 모델
성공률이나 실제 Gmail 발송을 이 변경으로 주장하지 않는다.
