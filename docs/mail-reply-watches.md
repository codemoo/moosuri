# 메일 답장 기다리기

이 대화에서 실제로 읽은 Gmail 메일이나 발송이 확인된 메일에 **다음 답장 감시**를
연결한다. 일반 자료 변경 감시는 [task monitors](task-monitors.md)를 따른다.
이 기능은 저장된 자료의 수집을 기다리지 않고, 해당 Gmail 대화만 직접 확인한다.

- 대화에서 `답장 오면 알려줘` 또는 `메일 답장 오면 알려줘`라고 말한다. 기본은
  30분마다, 최대7일이며 첫 답장을 찾으면 종료한다. `5분마다 답장 오면 알려줘`,
  `30분마다 답장 오면 알려줘`, `1시간마다 답장 오면 알려줘`도 지원한다.
- 메일이 여러 개면 같은 대화의 **메일 답장 기다리기** 카드에서 선택한다. 카드에서
  5/30/60분과 최대1/7/30일을 선택할 수 있다. 대상이 없으면 먼저 메일을 읽는다.
- `메일 감시 상태`, `메일 감시 중지` 또는 카드의 **감시 중지**로 관리한다.
  여러 감시가 있으면 중지할 카드를 선택한다. 단순히 기다리겠다는 말은 새 등록으로
  처리하지 않는다. 기존 감시가 있을 때만 계속 진행 중이라고 안내한다.
- 결과는 원래 대화의 본문 미리보기와 소식함에 표시한다. 허용한 Push는 기존
  조용한 시간·소식 끄기 설정을 따른다. Push에는 일반 안내만 넣고 메일 본문은 넣지 않는다.

새 메일이 없으면 **모델 호출0회, 모델 토큰0**이다. Gmail API는 예약 시각마다
조회하며, 로컬 작업 대기열은5초마다 확인한다. 5초마다 Gmail이나 모델을 호출하는
구조가 아니다. 읽음 표시·라벨 변경, 내가 보낸 메일, 임시 보관 메일은 새 답장이 아니다.
조회 실패는 무변화로 기록하지 않고 최근 성공 시각과 오류를 구분한다.

이번 구현은 새 답장의 **실제 본문을 제한된 길이로 보여주는 방식**이다. 변경이 생겨도
모델을 자동 호출하지 않는다. 의미 요약·답장의 관련성 판단·후속 외부 행동은 자동으로
수행하지 않는다. 본문은 최대4개×4096바이트, 직렬화 전체24KiB이며 첨부파일은 포함하지
않는다. 대화512개 메시지 또는 새 답장4개 한도를 넘거나 기준 메일이 사라지면 검토가
필요한 중단으로 알린다. 최대16개 감시를 동시에 허용한다. 일시적 실패는 제한적으로
재시도하고 반복 실패6회 또는 확정 범위 오류는 상태 확인을 요청한다.

감시는 원래 메일을 관측한 시점의 메시지 ID들에 묶인다. 그 뒤 등록/첫 확인 전에
도착한 답장도 확인한다. 계정별로 분리되고 일반 로그아웃 후에도 지속되며, 중지·대화
삭제·연결 해제·계정 권한 변경·복원은 이전 결과의 게시를 막는다. 완료 결과를 닫으면
미리보기와 해당 알림도 더 이상 표시하지 않는다. 요청 재전송·재시작은 새 감시나 중복
알림을 만들지 않는다. 조회는 중복될 수 있는 읽기 작업이며 알림 저장과 관측 완료는
한 트랜잭션이다.

현재는 **서버 OAuth Gmail**의 완료된 일반 대화 읽기와 확인된 발송 영수증을 대상으로
한다. native companion의 기기 전용 메일, 임의 검색 조건 감시, 다른 메일 대화나 전체
편지함, 전화 발신, 자동 의미 요약은 포함하지 않는다. 다자 메일 대화에서는 해당 대화의
새 수신 메일을 보여주며 특정 발신자의 의미상 답장만 분류하지 않는다. 자동 메일 발송은
하지 않으며 모든 발송은 기존 최종 미리보기 승인을 거친다.
