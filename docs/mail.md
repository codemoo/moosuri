# 개인 Gmail과 발송 확인

Gmail 연결은 사용자별이다. 공용 LLM 설정과 분리하며, 관리자가 다른 사용자의
메일함이나 초안을 열 수 없다. 구현·시험 범위의 정본은 [현재 상태](status.md)다.

## 설치자와 사용자

독립 셀프호스팅은 설치자가 OAuth 웹 앱을 한 번 준비한다. 같은 설치의 가족·친구는
각자 **Google 계정 연결**에서 로그인·승인하면 되며 Google Cloud 프로젝트를 따로 만들지 않는다.
현재 moosuri는 공용 OAuth 중계 서비스를 운영하지 않는다. n8n도 [Cloud의 managed OAuth와
셀프호스팅의 custom OAuth](https://docs.n8n.io/integrations/builtin/credentials/google/oauth-single-service/)를
구별한다. [Manus의 연결 화면](https://help.manus.im/en/articles/12231777-how-can-i-use-manus-connectors)은
서비스가 준비한 커넥터에 사용자가 로그인하는 방식이다. 이 차이를 설치 안내에서 명시한다.

Google 연결 뒤 [자료 연결](data-connections.md)을 따로 설정하면 허용한 메일 범위를 자동 수집한다.
연결 자체로 과거 메일 전체를 자동 수집하지 않는다.

## 설치 관리자 설정

관리자로 로그인하고 **Google 앱 설정** (`/admin/google`)을 연다. 설치자는 한 번만
준비하며 다른 회원은 자신의 계정 연결만 수행한다.

1. Google Cloud 프로젝트에서 Gmail API를 사용 설정하고 OAuth 동의 화면을 구성한다.
   가족·친구와 쓰는 External/Testing 앱이면 연결할 사람을 테스트 사용자로 추가한다.
2. OAuth 클라이언트를 **웹 애플리케이션**으로 만든다. 마법사의 **콜백 주소 복사**로
   얻은 주소를 승인된 리디렉션 URI에 정확히 등록한다. 주소는 서버의 `--origin`으로
   결정하며 `https://YOUR-HOST/api/v1/mail/oauth/callback` 형식이다. 로컬 개발만
   명시적인 loopback HTTP를 허용한다.
3. 내려받은 웹 클라이언트 JSON을 마법사에서 선택하고 **파일과 콜백 확인**을 누른다.
   16KiB까지 받으며 파일 형식·콜백 일치만 검사한다. 이 단계는 Google API 활성화,
   동의 화면·테스트 사용자나 실제 secret의 유효성을 확인하지 않는다.
4. **이 설치에 저장**하면 별도 설치 키로 secret을 암호화한다. 바로 연결에 사용할 수
   있고 서버를 재시작해도 유지된다. secret은 응답이나 화면·브라우저 저장소에 남기지
   않는다. 운영 환경의 파일 등록은 HTTPS에서만 사용한다.
5. **내 Google 계정 연결**로 본인의 동의를 마친다. **내 연결 프로필 확인**은 본인
   계정 주소만 확인한다. 메일 읽기·발송·자동 수집을 실행하지 않는다. 다른 회원의
   메일 연결을 관리자가 대신 확인할 수 없다.

Google 앱 생성·동의 화면·검증 정책은 설치자가 자신의 프로젝트에서 관리한다.
[웹 서버 OAuth 안내](https://developers.google.com/identity/protocols/oauth2/web-server)처럼
scheme·대소문자·마지막 슬래시까지 리디렉션 URI가 일치해야 한다. External 앱의
Testing 상태에서 이 Gmail 권한으로 발급받은 갱신 토큰은
[7일 후 만료된다](https://developers.google.com/identity/protocols/oauth2#expiration).
계속 사용할 앱의 게시·검증 조건도 Google에서 확인한다.

## 설정 변경과 운영자 파일

같은 클라이언트 ID의 secret은 기존 개인 연결을 유지하며 교체할 수 있다. 진행 중인
Google 로그인은 완료·취소되거나 만료(10분)될 때까지 설정 변경을 막는다. 다른 앱이나
콜백으로 바꾸려면 기존 앱을 사용하는 개인 연결을 각 소유자가 해제해야 한다.
다른 회원 연결이 있다는 이유로 그 회원의 주소나 토큰을 관리자에게 공개하지 않는다.
늦은 토큰 갱신·오류·수집 결과는 변경된 설정에 반영하지 않으며 이미 모은 자료와
checkpoint는 보존한다. 서버 origin을 바꾸면 콜백을 갱신하기 전 새 연결이 차단된다.

파일을 사용하는 기존 운영 방식도 유지한다. Google JSON을 저장소 밖에 서비스 계정
소유의0600 일반 파일로 두며 symlink는 받지 않는다.

```sh
moosuri --data-dir /private/moosuri serve \
  --bind 127.0.0.1:3210 --origin https://YOUR-HOST \
  --google-client-file /private/google-client.json
```

이 옵션이 있으면 **운영자 파일 모드**가 명시적으로 우선하며 웹 저장은 거절한다.
파일을 바꾸려면 운영자가 파일을 교체하고 서버를 재시작한다. client secret을 CLI
인자 값이나 Git에 넣지 않는다. 마법사의 입력 JSON은 인증한 관리자 요청으로만
받으며 재노출하지 않는다. 파일 등록 성공을 실제 Google 연결 성공으로 표시하지 않는다.

## 각 사용자의 Google 연결

로그인한 사용자가 **메일 → Google 연결**에서 자신의 계정을 승인한다. 현재 요청하는
scope는 `gmail.readonly`와 `gmail.send`다. 초안은 무수리에 저장하므로 Gmail 초안함을
수정하는 `gmail.compose` 권한을 요청하거나 Gmail 초안 저장 완료라고 표현하지 않는다.
Google callback은 cookie 없는 외부 GET을 처리하고, 원래 로그인 세션의 same-origin
완료 요청이 계정·state·PKCE·만료를 검증한 뒤 연결을 완성한다.

OAuth 토큰은 별도 설치 키로 암호화한 **서버 관리 connector credential**이다.
사용자만 복호화하는 개인 볼트와 같은 보호를 제공한다고 말하지 않는다. 토큰은
모델 입력·도구 결과·웹 DTO·오류 본문에 반환하지 않는다.

## 읽기와 초안

연결한 메일을 검색하고 본문 또는 thread를 읽을 수 있다. 채팅의 모델 도구는
`mail_search`, `mail_read`, `mail_thread`, `mail_prepare_draft`까지다. 연결은 실행 접수
시점에 개인 계정과 epoch로 고정한다. 연결을 해제하면 진행 중인 읽기와 그 결과의
후속 답변·미발송 초안도 철회한다. 이미 읽은 자료가 새 발송 허락을 만들지 않는다.

현재 발신은 연결 계정의 기본 주소, ASCII 이메일 주소 목록과 일반 텍스트 본문을
지원한다. From/To/Cc/Bcc, 제목, 전체 본문과 첨부 없음을 확인 화면에 표시한다.
첨부파일·HTML 발신·별칭·표시 이름이 포함된 주소는 지원한다고 가정하거나 조용히
제거하지 않는다. 필요한 경우 현재 지원 범위를 안내하고 입력을 거절한다.

읽기에는 크기·개수 제한이 있다. thread 일부나 복수 inline 본문 중 일부만 반환하면
잘린 결과임을 명시한다. 표시된 일부를 메일 전체라고 요약하지 않아야 한다.

## 반드시 확인하고 보내기

“이메일 보내 줘”라는 채팅도 먼저 로컬 초안을 만든다. 사용자가 전체 수신인과 내용을
보고 **허락하고 보내기**를 눌러야 발송 대기 상태가 된다. 모델에게 approve/send
도구는 없으며, 일반 조회마다 별도 승인 단계를 추가하지 않는다.

- 확인 화면은 동결한 MIME bytes·thread·Message-ID의 digest와 revision에 연결된다.
  승인 요청은 새 본문을 받지 않는다. 편집 중이나 저장 응답을 기다리는 동안 이전
  초안의 승인 버튼과 처리 함수 모두 차단된다.
- 내용·수신인·연결이 바뀌면 새로운 미승인 revision이다. 늦은 응답이 새 상태를
  덮어쓰지 않으며, 철회된 초안의 본문과 수신자는 열린 편집기에서도 제거된다.
- 별도 worker가 현재 권한과 연결을 확인하고 발송 commitment를 먼저 저장한 뒤
  실제 동결한 bytes를 한 번 보낸다. 일반 채팅 재시도가 메일을 재발송하지 않는다.

## 결과의 의미

| 표시 | 의미 |
| --- | --- |
| 발송 허락 대기 | 무수리 로컬 초안. 아직 발송 허락도 발송도 없음 |
| 허락됨 · 발송 대기 | 표시한 정확한 revision이 승인됨 |
| Gmail에 발송 요청 중 | commitment가 저장됐으며 결과를 기다리는 상태 |
| Gmail 발송 접수 | Gmail의 message/thread 영수증을 받음. 상대 수신·열람 확인이 아님 |
| 발송 결과 불명 | 응답 유실 또는 발송 중 재시작 등으로 성공 여부를 확정할 수 없음 |
| 거절·취소·만료 | 해당 미발송 초안의 실행을 종료함 |

commitment 이후에는 자동 재발송하지 않는다. 늦은 실제 영수증은 원래 작업에 보존한다.
결과 불명 뒤에는 원래 Message-ID로 보낸편지함을 읽기 전용 조회한다. 자동 조회는 원래
commitment 시각 기준 즉시·15초·120초·600초의 최대 네 번이며 재시작으로 예산을
초기화하지 않는다. 사용자의 **보낸편지함 다시 확인**은 작업별 1분 간격의 인증된
조회이며 새 발송 허락을 요구하거나 발송을 재시도하지 않는다. 마지막 확인 시각과
후보·일치·불명 상태를 표시한다.

전체 검색에서 후보가 정확히 하나이고 SENT·ID·thread 및 원래 동결한 전체 지원 MIME
증거가 일치할 때만 **일치 메일 관찰**을 기록한다. 기존 **발송 결과 불명** 상태와 실제
발송 응답 영수증은 별개다. 후보 없음은 검색 지연·누락일 수 있어 실패 증거가 아니다.
복수 후보·다음 페이지·Bcc 누락·추가 헤더/부분·잘림·변경된 본문은 확정하지 않는다.
원래 증거가 없는 과거 작업은 더 약한 후보 조회만 제공하며 가져온 후보를 원래 증거로
소급 저장하지 않는다. Message-ID는 공급자 idempotency나 상대 수신·열람 증거가 아니다.

v1 비교는 CRLF/LF·헤더 줄접기·생성 Date만 정규화한다. 전체 지원 헤더와 인코딩된
본문을 보수적으로 비교한다. Gmail이 보통 추가할 수 있는 Received·DKIM·X-Google
등의 헤더나 인코딩·Bcc 변환도 허용 목록 밖이면 거절하므로, 실제 보낸 메일이 자주
불명으로 남을 수 있다. 이는 실제 계정에서 별도 확인할 한계다. 연결 철회·계정 상태 변경·원문
철회 후 늦은 조회는 게시하지 않으며 복원된 조회 권한은 격리한다. 새 발송은 언제나
새 최종 내용 확인과 명시적 허락이 필요하다.
이미 전송된 메일을 연결 해제나 로컬 삭제로 되돌렸다고 말하지 않는다.

원문 삭제·기억 망각·대화 삭제는 아직 발송하지 않은 파생 초안과 승인을 폐기한다.
연결 철회는 SSE의 기존 전달 잠금과 함께 처리하여 철회 직후 늦은 본문이 전달되는
경쟁을 막는다. 이 잠금을 Gmail 네트워크 요청 전체에 걸쳐 잡지는 않는다.

실제 Google 계정의 OAuth·발송 시험은 별도 운영자 설정과 구체적인 수신인/내용의
사용자 허락이 필요하다. 개발 시험은 합성 자료와 loopback HTTP만 사용했다.
자세한 외부 실행 계약은 [external work](external-work.md)를 따른다.

불명 발송 조회의 설계와 합성 검증은 [reconciliation change](../openspec/changes/reconcile-unknown-gmail-send/proposal.md)와
[검증 기록](reviews/2026-11-14-gmail-reconciliation.md)에 있다. Gmail provider 초안 CRUD·선택 compose 동의와 승인된 고정 예약 발송은 아직 별도 구현 대상이다.
