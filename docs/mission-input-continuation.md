# 맡긴 일에서 필요한 정보 답하기

원래 업무 카드에서 빠진 값·추가 맥락·판단 기준에 답하고 같은 일을 이어갈 수 있다.
받는 사람 이메일 하나, 일정 날짜(YYYY-MM-DD)·시작 시각(HH:MM)·길이(1–1440분),
최대4000자의 일반 답변, 실제로 읽은 저장 원문이나 기존 일정 중 선택을 지원한다.
일반 답변은 처음 맡긴 일의 자료와 기준을 보완하며 새로운 외부 작업·계정·수신인·제목
권한을 만들지 않는다. 기계적으로 확인할 수 없는 답변·판단 기준은 결과에서 직접 검토한다.

입력 후 원래 업무/run이 남은 단계부터 이어진다. 이미 완료한 읽기·계산, 원래 계정/
모델/도구, 확인 기준,6model/12tool/최대2repair 한도와 종료 시각을 유지한다. 대기 중에는
모델을 호출하지 않고 실행 자리를 반환한다. 다른 업무가 진행 중이면 답변을 저장하고
앞선 업무가 끝난 뒤 기존 접수 순서에 따라 재개한다. 기다린 시간도 원래 종료 시각에
포함된다. 같은 acceptance의 각 지원 질문 종류는 한 번만 받을 수 있다.

선택지는 모델이 만든 임의 문자열이 아니다. 실제 현재 회차의 완료된 읽기 receipt,
원문 ID/revision 또는 일정 ID/ETag에 묶인2–5개 후보만 표시한다. 표시 이름은 Store가
관측 자료에서 만든다. 원문이 바뀌거나 철회되면 오래된 답변으로 재개하지 않으며,
다른 원문으로 자동 대체하거나 읽기를 조용히 반복하지 않는다. 같은 이름의 일정이
여럿일 때는 실제로 고른 한 일정만 기존 날짜 이동 원장에 연결하며, 실행 직전 달라진
ETag나 삭제된 대상은 기존 provider 검사에서 거절한다.

질문은 새로고침 뒤에도 같은 카드에 남는다. 네트워크 응답이 유실되면 같은 입력과
요청 ID로 다시 확인할 수 있고 다른 내용으로 같은 ID를 쓰면 거절한다. 만료·취소·철회·
복원 뒤에는 오래된 답변으로 자동 재개하지 않는다. 복원은 입력 대기·답변 권한을
지우고 미완료 grant를 격리한다. 유효 결과와 중단 이유를 확인한 뒤 새 요청을 맡길 수 있다.

반복 읽기 업무도 현재 회차에 한해 일반 정보/원문 선택을 기다릴 수 있다. 답변은 다음
회차나 반복 template에 복사되지 않으며 반복 쓰기 권한을 추가하지 않는다. 기존 반복
업무의 정지·철회·만료는 대기와 소식도 차단한다.

답변이 필요하면 기존 소식함과 opt-in WebPush에 일반 소식 하나를 남긴다. 누르면 원래
업무 카드로 돌아온다. 질문을 임시 알림 예약으로 만들지 않으며 새 schedule/회차를
생성하지 않는다. 일반 일회 업무는 업무별 소식 끄기를, 반복 회차는 기존 반복 업무의
소식 설정을 따른다. 조용한 시간에는 소식함에만 남는다. 답변·취소·만료·철회 후에는
소식과 아직 보내지 않은 push를 억제하며, 클릭할 때도 현재 계정/세션을 다시 확인한다.
이미 provider가 수락한 push를 원격으로 회수하는 기능은 아니다.

메일은 기존 MailAction을 준비하며 최종 수신인·본문·첨부 여부·시각을 정확한 메일
화면에서 매번 보고 허락해야 발송한다. Calendar도 기존 UUID/ETag/receipt 원장을
유지한다. 결과 불명 외부 작업을 질문 대기로 바꾸거나 자동 재전송하지 않는다.

검증은 합성 SQLite·loopback Runtime·React/service-worker 경로다. 실제 provider/기기
수락이나 실모델 이해 품질을 뜻하지 않는다.
