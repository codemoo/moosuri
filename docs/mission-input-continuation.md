# 맡긴 일에서 필요한 값 답하기

현재 요청에 이미 허용한 일회성 메일 초안 또는 기본 개인 Calendar 작업에서 필요한 값이
없으면 원래 업무 카드가 질문을 보관한다. 지원 값은 받는 사람 이메일 하나, 일정 날짜
(YYYY-MM-DD), 시작 시각(HH:MM), 일정 길이(1–1440분)다. 입력 후 같은 업무가 남은 단계부터
이어지며 이미 완료한 읽기·계산, 원래 계정/모델/도구, 확인 기준, 호출 한도와 종료 시각을 유지한다.
대기 중에는 모델을 호출하지 않고 실행 자리를 반환한다. 다른 업무가 진행 중이면 답변을
저장하고 앞선 업무가 끝난 뒤 기존 접수 순서에 따라 재개한다.

질문은 새로고침 뒤에도 같은 카드에 남는다. 네트워크 응답이 유실되면 같은 입력과 요청 ID로
다시 확인할 수 있으며 다른 내용으로 같은 ID를 쓰면 거절한다. 만료·취소·철회·복원 뒤에는
오래된 답변으로 자동 재개하지 않는다. 기다린 시간도 원래 종료 시각에 포함된다.

답변은 빠진 값만 채운다. 원래 명시한 수신인/날짜/시각/길이를 교체하거나 CC/BCC, 답장 thread,
일정 대상/제목/계정/종일 여부, 새로운 실행 권한을 추가하지 않는다. 날짜 이동은 기존 유일한
대상·ETag 조건을 유지한다. 원래 값이 이미 있거나 지원하지 않는 모호함이면 이 경로로 다시
질문하지 않는다. 보고서/일반 자유 답변·반복 작업·충돌한 원문/일정 대상 선택은 후속 범위다.

메일은 기존 MailAction을 준비한다. 최종 수신인·본문·첨부 여부·시각을 정확한 메일 화면에서
매번 보고 허락해야 발송한다. Calendar도 기존 UUID/ETag/receipt 원장을 유지한다. 결과 불명
외부 작업을 질문 대기로 바꾸거나 자동 재전송하지 않는다.

현재 한 번 맡긴 일에 대한 일반 알림 발행 경로는 없으며 원래 카드에서 질문을 확인한다.
기존 예약/회차 알림을 다른 목적의 임시 예약으로 만들지 않는다. 검증은 합성 SQLite·loopback
Runtime·React 경로이며 실제 provider/기기 수락이나 실모델 이해 품질을 뜻하지 않는다.
