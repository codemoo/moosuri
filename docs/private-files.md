# 개인 파일 첨부

채팅 입력 옆 **파일 첨부**에서 `.txt`, `.md`, `.markdown`, `.csv`, `.json`, `.pdf`를 고른다.
텍스트 파일당 최대24KiB, PDF는2MiB이며 이미지와 합해 한 메시지에 최대4개다. Rust가 비어 있지 않은
실제 UTF-8과 제어 문자 부재를 확인하고 JSON은 구문도 검사한다. CSV/Markdown은
원문 텍스트로 읽는다. PDF는 아래의 제한된 텍스트 추출을 지원한다. 오디오/STT·Office·일반 바이너리는 아직 지원하지 않는다.
지원하지 않는 형식을 텍스트로 읽었다고 표시하지 않는다.

파일별 진행률·취소·같은 원본 재시도가 있으며, 이미지 준비와 별도로 업로드한다.
업로드 중 글을 보내면 준비된 첨부만 전송하고 나머지는 입력 옆에 남는다.
전송 응답을 받지 못한 경우 같은 요청 다시 제출은 처음 선택한 ID/revision을
유지한다. 나중에 선택한 다른 파일로 바꾸지 않는다. 이미지의 기존 준비·vision
검증 경로도 유지한다. 글 없이 파일만 보내는 방식은 아직 지원하지 않는다.

**내 이미지·파일 보관함**에서 완료된 원본을 다시 첨부하고, 대화 말풍선이나
보관함의 **원문 미리보기**로 텍스트를 확인한다. HTML처럼 보이는 내용과 Markdown은
실행·렌더링하지 않고 글자로 표시한다. **원본 다운로드**는 업로드한 바이트를 그대로
돌려준다. 브라우저 저장 이름에는 표시용 basename을 쓰고 서버의 다운로드 헤더는
고정된 `document.txt` 또는 `document.pdf`와 `attachment`/`nosniff`를 사용한다. 이름·확장자가 내용의
실행 권한을 부여하지 않는다. 모든 원문/미리보기 API는 현재 계정을 검사하고
`no-store`이며 service worker에 개인 파일을 저장하지 않는다. 관리자는 다른
사용자의 원문을 읽을 수 없다.

파일 질문에는 정확한 immutable revision, 원본 SHA256, 추출 텍스트의 UTF-8 바이트 구간
`[0, extracted_text_bytes)`와 전체 추출 텍스트가 **자료**로 모델에 전달된다. 새로 선택한
파일을 먼저 포함하고, 후속 질문에서는 같은 대화에서 최근에 선택한 유효한 자료까지
최대4개를 보낸다. 업로드한 날짜가 아니라 마지막으로 대화에 첨부한 순서를 따른다.
다른 대화나 현재 요청 이후의 첨부가 재시도 문맥에 끼어들지 않는다.
한 번에 새로 선택한4개 원문은 모두 전달한다. 원문은 현재 사용자 명령과 구별한
별도 data message이며, 문서 속 지시는 기억·문서·알림 변경이나 외부 도구 권한이
아니다. 첨부에서 이어진 대화에서는 기존 이미지 경계처럼 모든 도구와 지속 쓰기를
제한한다. 모델에 근거의 byte/revision/digest 인용을 요청하지만 생성된 인용의
정확성을 별도 검증했다고 주장하지 않는다.

모델 메시지64KiB/요청512KiB 한도를 실제 encoder로 확인한다. 선택한 원문과 현재
요청은 유지하고 필요할 때 가장 오래된 완전한 대화부터 제외하여 연속된 최근
문맥을 남긴다. 이 경우 모델에 이전 대화가 빠졌음을 사용자에게 알리도록 한다.
24KiB는 JSON 재직렬화에 필요한 여유를 포함한 한도다. NUL 및 LF/CR/TAB 외 제어
문자는 미리 거절하며, 따옴표·역슬래시가 가득한4개 원문도 합성 loopback에서 확인한다.

보관량은 이미지와 공유하는 계정당64MiB이며 원본·추출 텍스트·thumbnail을 합한다.
진행 중 업로드는 기존의 보수적인 이미지 크기로 예약하고, 삭제 tombstone을 포함한
ID는4096개까지다. 파일 삭제는 원본·추출 텍스트를 없애고 해당 원문에서 파생된
응답/후속 문맥을 철회한다. 삭제·취소가 먼저 도착하면 늦은 업로드 완료가 되살리지
못한다. 다운로드/미리보기가 늦게 끝나도 삭제·계정 전환 후 화면으로 전달하지 않는다.

원본과 완료된 추출은 SQLite에 함께 저장되어 암호화 봉인 export/restore에 포함된다.
삭제 tombstone은 journal replay와 함께 보존하고, 재시작/복원 때 미완료 업로드는
`retry_required`로 격리한다. 복원 전 세션/업로드 lease는 다시 사용할 수 없다.
복원한 보관함에서 원본을 확인하고, 완료되지 않은 파일 항목의 **원본 다시 선택**으로
처음 파일을 고르면 같은 UUID로 재시도한다. 서버는 처음 이름·digest와 다른 원본을
거절한다. 이미 완료된 응답을 놓쳤다면 같은 원본의 준비 영수증만 돌려준다.

이 경로는 F10/F14의 제한된 UTF-8 파일과 PDF 텍스트 처리다. 녹음/STT, 이미지 OCR,
일반 바이너리 parser, 파일의 자료 모음 등록/자동 기억 추출, source-derived 지속 쓰기,
실모델 파일 답변 품질, 전체 미디어/P7 완료는 포함하지 않는다. 운영 배포와 실제
개인 파일 검사는 하지 않았다.

## PDF 텍스트 읽기

암호가 없는 텍스트 PDF를 첨부하면 페이지 순서대로 글자를 추출한다. 보관함의
**텍스트 미리보기**는 추출한 글자를 보여 주며, 원본 다운로드는 업로드한 PDF 바이트를
그대로 돌려준다. 페이지 표시가 붙고 모델에 전달되는 바이트 위치는 **추출 텍스트**를
가리킨다. PDF 원본 바이트 위치나 표/그림의 시각적 이해를 증명하지 않는다.
이미지만 있는 스캔본은 읽을 수 있는 글자가 없다고 안내하며 필요한 페이지를 이미지로
첨부할 수 있다. 암호는 받지 않는다. 미지원 암호화·잘못된 파일·분량 초과·시간 초과는
구분해 안내하고 이미 적은 메시지와 원래 업로드 UUID를 유지한다.

현재 지원 범위는 페이지의 직접 텍스트와 해석 가능한 글꼴 매핑이다. 텍스트를 담은
Form XObject, Type3 글꼴, 지원하지 않는 문자 매핑이나 그래픽 상태의 글꼴 전환은
부분 텍스트를 완료로 저장하지 않고 미지원 안내를 돌려준다. 정상적인 빈 페이지나
이미지 페이지가 섞여 있어도 직접 텍스트를 읽을 수 있다. 이미지 OCR·양식 필드·주석의
텍스트 추출과 정확한 표/열 배치 복원은 지원하지 않는다.

추출은 순수 Rust `lopdf0.47.0`을 사용하는 별도 Moosuri 프로세스에서 수행한다.
서버가 고정한 현재 실행 파일만 호출하며 파일/모델 입력으로 프로그램이나 인자를 고르지
않는다. 문서 바이트는 stdin, 고정 JSON 결과는 stdout으로 전달하고 환경변수·설치 경로·
DB·로그·네트워크를 전달하거나 사용하지 않는다. PDF 링크·스크립트·첨부·양식을 실행하지
않고 추출 글자도 React에서 일반 텍스트로 표시한다. 이 경로는 OS 사용자 격리 또는
악성 운영자에 대한 sandbox라는 주장이 아니다.

한 번에 최대50페이지, 추출 글자24KiB, 페이지 합산/글꼴 매핑 압축 해제32MiB, 실제 객체20,000개,
페이지 연산50,000개, 페이지/그래픽 중첩32단계, 전체 처리10초, CPU5초다. Linux에는 자식 주소 공간512MiB 제한도 적용하고 출력은64KiB로
제한한다. 초과 문서를 일부 읽은 뒤 전체를 읽었다고 저장하지 않는다. macOS 검증에서는
주소 공간 제한을 적용하지 않으며 Linux 운영 검증과 구분한다. 서버는 동시에 두 개의
파일 업로드/추출만 처리하지만 이미지 준비와 채팅 전송은 독립적으로 동작한다.

기존 사용자/세션·digest·삭제 tombstone·원본 재시도·철회·복구 계약을 그대로 사용한다.
PDF가 포함된 문맥도 자료로만 사용하며 새로운 도구나 지속 쓰기 권한을 얻지 않는다.
PDF 지원에 새로운 DB migration은 필요하지 않다. Rust 서버 library를 따로 내장할 때는
배포 소유 실행 파일을 `ServerConfig::with_pdf_extractor`로 설정해야 하며, 기본 CLI는
자기 실행 파일을 자동으로 지정한다. 별도 Python/Poppler/시스템 PDF 설치는 필요 없다.
