# 저장한 기록에 근거한 제안

예약·소식 화면은 명시적으로 저장한 요청·약속 중 날짜가 없는 기록에
**다시 살펴볼 날짜를 정해 보세요**라는 제안을 보여 준다. 실제 기록 제목과
날짜가 없다는 이유, 현재 소유 기록을 여는 링크가 있다. 링크는 기존 기록 편집기를
열며 날짜를 저장하거나 업무를 실행하지 않는다.

지원하는 제품 주제는 `followup_review`(날짜 없는 요청·약속 검토) 하나다.
request/promise/waiting_for_reply의 requested/committed/waiting 상태이고 기록 자체가
muted가 아니며 due/review/snooze가 모두 없을 때만 해당한다. 지난 날짜가 있는 기록,
완료·취소·숨긴 기록, 목표·문서의 내용을 해석해 새 제안을 만들지 않는다.
의미 분류·관심사 추정·임의의 모델 주제·일반 자율 실행은 지원하지 않는다.

## 저장에서 확인까지

명시적 기록 저장 뒤 약1분부터 기존 로컬 알림 worker로 제안을 전달한다. 현재 유효한
소유 기록만 참조하며, 실행 시 모델·classifier·외부 provider 호출은 없다.
업그레이드·복원·화면 열기·idle poll은 과거 기록을 검색해 제안을 채우지 않는다.
동시에 pending이거나 현재 소식함에 보이는 제안은 계정별 최대5개다. 한도가 찬 동안
저장한 기록은 자동 대기열에 넣지 않는다. 자리가 난 뒤 그 기록을 직접 다시 저장하면
현재 조건으로 판단한다. 읽음만으로 자리가 나지는 않으며 개별 숨김·수정·철회는 자리를
비운다. 일반 소식함의 페이지와 숨긴 기록 조회는 기존 정책을 따른다.

각 기록은 안정적인 제안 identity를 가지며 평생 한 번만 발행한다. 저장 ACK 재시도,
재시작·시계 후퇴·제목 변경·숨긴 뒤 편집으로 같은 제안을 다시 발행하지 않는다.
아직 발행하지 않은 제안의 편집은 옛 claim을 먼저 차단하고 현재 버전에 연결한다.
발행한 뒤 기록이 바뀌면 옛 내용·링크를 지우고 숨기며 새 제안으로 재생하지 않는다.

## 개별 숨김, 주제 끄기, 조용한 시간

카드의 **숨기기**는 그 제안 하나에만 적용한다. **이 주제 제안 끄기**는 서로 다른
기록과 이후 제목·버전에도 같은 제품 주제를 적용한다. 날짜를 명시해 저장한 followup
알림과 일반 예약의 source mute는 이 제안 주제와 별개다. 화면의 **제안 주제**에서
**이 주제 제안 다시 받기**로 해제할 수 있다. 해제는 미래 발행에만 적용하며 숨긴
제안·꺼 둔 동안의 소식을 재생하거나 업무를 재개하지 않는다.

inbox와 opt-in Push는 같은 notification identity와 저장 transaction을 사용한다.
조용한 시간은 소식함 제안을 유지하면서 Push를 억제한다. 주제를 꺼 둔 동안 발행한
제안은 영구 source suppression으로 소식함과 Push에서 제외한다. 끄기 이전의 소식함
카드는 남지만 그 Push는 이후 해제에도 다시 전송하지 않는다. 이미 dispatch한 실제
결과는 보존하고 passive display·retry 권한을 영구 차단한다. 외부 기기에 이미 표시된
알림을 회수하지는 못한다. Push payload에는 기존 opaque ID만 들어간다.

## 소유·철회·복구

제안은 일반 reminder의 현재 소유자·auth epoch·계정 상태 검사와 회차 영수증을
재사용한다. 내부 제안/주제 schedule은 일반 예약 목록·한도·채팅 대상 선택·수동 제어에서
제외한다. 새 모델·도구·메일·Calendar·브라우저 실행 권한을 만들지 않는다.

기록 수정·삭제·완료·취소·mute와 전이 근거 철회는 같은 Store transaction에서
미발행 회차와 queued/claimed Push를 차단하고 옛 제목·내용·참조를 지운다. 계정 삭제는
tenant 자료 정리로 주제·제안 sidecar를 포함해 삭제한다. schema0057은 backfill 없이
추가되며 normal open과 offline restore에서 함께 적용한다. 복원은 기존 schedule/Push
quarantine을 적용한다. 주제 설정은 남고, 과거 알림은 다시 실행하지 않는다. 미발행
기록을 현재 소유자가 다시 저장할 때만 현재 조건으로 새 미래 authority를 만든다.

실제 휴대폰 수신·일반 의미 기반 proactive 효용·더 많은 제안 주제는 이 범위 밖이다.
