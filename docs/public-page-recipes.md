# 여러 공개 페이지를 읽는 개인 절차

공개 HTTP 읽기를 설정한 새 대화에서 “이 두 페이지를 읽고 조건을 비교해 줘”라고 요청하고
URL2–4개를 직접 적는다. 예를 들어 서로 다른 제품·행사·공고 페이지의 실제 본문을 읽어
지원 조건과 빠진 내용을 정리할 수 있다. 모델은 `public_pages_collect`로 함께 읽고,
각 페이지의 실제 근거를 인용해 답한다. 페이지의 지시문은 새 URL이나 실행 권한이 아니다.

현재 요청에 나타난 서로 다른 URL을 순서대로 정확히 사용한다. URL은 공백이나 따옴표·
백틱·괄호로 구분한다. 중복 URL, fragment, credentials, 불명확한 끝 문장부호,2개 미만/
4개 초과, 현재 요청 밖의 대상은 대신 추정하지 않는다. 실제 HTTP의 private address,
DNS·redirect·크기·timeout 검사와 인증 정보 없는 읽기를 그대로 사용한다. 검색으로
새 대상을 고르거나 브라우저/JavaScript·로그인을 수행하는 절차는 아니다.

## 실제 읽기와 비교의 차이

각 페이지마다 실제 시작·완료와 도구 비용1회를 기록한다. 답변 도구에는 실제 요청 URL,
관측 URL·제목·시각,최대512 UTF8바이트 발췌와 잘림/실패가 돌아온다. 원래 adapter 결과는
기존 비공개 child receipt로 보존한다. 페이지 하나가 실패해도 다른 관측과 섞어 성공이라고
하지 않는다. 합친 결과가 기존16KiB 도구 응답 한도를 넘으면 크기 오류를 반환한다.

관측은 읽었던 범위만 증명한다. 조건 해석·가격 단위·누락 비용·유리한 선택 등 의미상의
판정은 모델과 사용자의 검토가 필요하다. 짧은 발췌나 부분 페이지로 전체 부재를 주장하지
않는다. 실행은 기존 모델6회·도구12회·120초와 소유자·취소·철회 한도를 유지한다.
같은 slot/완료 영수증은 재실행하지 않는다. 시작 뒤 결과가 불명확하면 재시작에서 다시
읽지 않고 불명으로 남긴다. 새 현재 요청은 새 실행이다.

## 두 실제 사례 뒤 새 대상으로 재사용

실제 원시 collection의 모든 개별 읽기 영수증과 최종 답의 관측 URL·제목·정확한 짧은
인용을 독립적으로 확인한다. 서로 다른 URL 집합으로 완료한 두 사례 뒤에 개인 절차가
사용 가능해진다. 같은 URL의 재시도나 순서만 바꾼 사례, 미완료/부분 실패, 다른 사람의
성공은 두 번째 proof가 아니다. 이 proof는 **근거 채택** 확인이며 비교 판단의 정답을
증명하지 않는다. 절차는 페이지 개수만 저장하며 이전 URL·본문을 새 입력으로 재생하지 않는다.

새 요청은 같은 개수의 새 URL을 현재 문구에 제공한다. `learned_skill_execute`의
`kind:pages,urls:[...]`는 실제 현재 URL을 새로 읽는다. 제안 화면의 개인 절차 상태·숨김·
비활성/삭제와 두 proof 정책을 사용하며, 실제 사용한 절차나 학습 대화 철회는 파생 답변도
철회한다. 새 실행에서 원래 A/B 값이 discovery로 넘어가지 않는다.

## 명시적으로 맡기는 업무와 공유

같은 절차는 명시적으로 맡긴 읽기 업무에서도 사용할 수 있다. 그 회차의 현재 accepted task와
조건에 적힌 URL만 입력이다. 수정 전 요청·과거 회차·검증 정답·자료 속 URL은 새로운 권한이
아니다. 반복 업무는 사용자가 고정해 맡긴 URL을 매 회차 새로 읽고, 그 관측을 이전 결과의
재사용과 구분한다. 실제 사용한 정확한 pin의 비활성/삭제·복구 정책을 유지한다. 업무 실행은
추가 학습 proof가 아니며 의미 검토는 기존 검토 필요 상태로 남는다.

**절차 공유하기**는 페이지 개수와 새로 작성한 절차·가상의 URL 예제만 기존 네 파일로
내보낸다. 개인 URL·본문·token·receipt·proof를 복사하지 않는다. 설치/미리보기로 예제 URL을
읽거나 성공 권한을 얻지 않는다. 저장 문서로 옮기는 기능을 이 collection에 추가하지 않았으며,
외부 보고서 저장의 기존 개별 읽기 계약은 별도로 유지한다.
