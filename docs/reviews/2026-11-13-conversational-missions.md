# 대화형 읽기 업무 검증

공개 기준 `cff9b1d`에 schema29의 현재 요청 해석·업무 생성/제어·실제 접수 영수증을
통합했다. 명확한 요청은 추가 승인 없이 저장하고 누락된 시각이나 불명확한 대상만 묻는다.
일회성·반복 업무의 기존 범위·모델·예산·철회·복구 계약과 고정 알림 우선순위를 유지한다.
메일·브라우저·Calendar·볼트 실행 권한은 추가하지 않는다.

최종 독립 검토와 Linux 검증이 사용한 소스 manifest는751개 파일이며 SHA256은
`e48109c29fff5d33dad590d8add8c96997b460113f45672c66003aa93a8b0c84`다.
검증 후 수락 상태·제한·이 기록만 문서에 반영했다. 최종 독립 검토에서 이 범위에 남은
P1/P2 결함은 없었다. 이는 모든 비서 기능 또는 임의 자연어의 품질 보증이 아니다.

## 발견한 결함과 수정

| 발견 | 수정·관측 기준 |
| --- | --- |
| 새 로그인으로 미적용 요청을 다시 실행할 가능성 | 원래 세션 digest/인증 세대를 고정하고 계획·응답 확정·적용·재시도에서 검사. logout/relogin 재시도는 새 업무0개 |
| 명시된 분·요일·날짜·시간대와 다른 제안 | 현재 인용문의 지원 civil components 전체를 고정 시각/시간대와 대조. 잘못된 분·날짜·요일은 저장0개, 명시한 IANA 시간대 우선 |
| 선택한 업무와 명시한 다른 이름 충돌 | 실제 소유 target/revision과 전체 이름이 일치해야 적용. 이름/선택 모두 없으면 소유 업무가 하나라도 다시 묻기 |
| 확인문 저장 실패가 만료·철회 전이도 rollback | 권한/대상 검사 후 실행 guard만 별도로 확정. 실제 제어·영수증·확인문은 함께 적용하거나 취소 |
| 자연스러운 위임/재개 후보 누락 | 날짜·시각, 한국어 위임 어간, 영어 재개 표현의 비용 라우팅을 보완. cue 자체는 실행 권한이 아님 |
| ISO 날짜와 공백 뒤 시각을 합쳐 잘못 파싱 | 날짜를 먼저 분리하고 명시된 날짜를 반복 규칙으로 대체하지 않음 |

첫 독립 후보13개에서11개가 진입했고, 이후 별도 새 후보4개도 처음에는2개만 진입했다.
수정 뒤 각각13/13·4/4가 진입했으나 구현자에게 노출된 회귀 사례다. 같은 새 묶음의 일반
메시지2개는 분류를 우회하고 시간 표현이 있는 부정 사례2개는 해석기로 진입한다.
이 수치는 후보 라우팅이며 의미상 요청 판단 정확도나 unseen 성적이 아니다.

## 실제 검증 범위

| 검증 | 결과 |
| --- | --- |
| Native Store 대화 업무 | 21개 통과 |
| Native agent 합성 실제 loopback | 2개 통과 |
| Native 정적/빌드 | core/store/agent/server all-target Clippy `-D warnings`, CLI build, DTO export 일치 통과 |
| 독립 Store probes | 기존 결함/정상 대응10개 통과, 이름 없는 제어의 별도 확장 검사 통과; 서로 겹치는 검사 포함 |
| Linux 실제 통합 소스 | missions77, schedules24, restore9, migrations5, agent2, HTTP1 통과와 Clippy 통과; 필터 간 중복 가능하므로 합산하지 않음 |
| React | ChatPanel·MissionChatContinuity·Missions·App의 집중 검사, TypeScript와 production build 통과 |
| 실제 Chrome,390×844 | 로그인·일반 대화·09:15반복 업무 생성·선택 후 정지·빠진 시각 안내·일회 계산 결과0.3과 실제 계산 영수증·새로고침 후 유지 확인 |
| 대화 연속성 | 응답 생성/업무 선택 중 미전송 초안 보존, 일반 메시지의 추가 업무 분류 호출0회 확인 |

브라우저 검증은 실제 Rust/SQLite/React와 scripted loopback provider를 사용했다.
일회 계산의 기본 확인 기준은 `user_review`여서 정답/계산 영수증이 있어도 ‘검토 필요’로
남는 것을 확인했다. 실제 휴대폰·Google·실모델 언어/지연/비용 평가는 수행하지 않았다.
최초 비로그인 세션 조회401 외에는 관측한 앱 오류가 없었다.

최초 통합 Linux 실행은 추출 소스의 보존된 mtime 때문에 이전 core 빌드 산출물을 재사용해
새 타입을 찾지 못했다. 추출 소스 시각을 갱신하고 실제 해시를 검증한 최종 실행은 위7개
단계 모두 통과했다. 제품 소스를 완화하지 않았고 최초 실패 로그를 보존했다.
React build에는 기존500kB 초과 chunk 경고가 남는다.

대화의 여러 턴 명확화, 넓은 날짜/숫자/시간대 표현, 실모델 unseen 의미·속도 평가는 후속이다.
OpenSpec은 이 미완료 범위를 남겨 archive하지 않는다. 운영 서비스·수집기·cron·DB는
변경하지 않았고 GitHub Actions/자동 CI도 계속 비활성이다.
