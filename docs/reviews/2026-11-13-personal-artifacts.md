  현재 사용자 지시에서만 쓰기 권한을 정하고 실제 저장 결과로 완료 메시지를 만든다.
- 최종 macOS 집중 검사: Store10·에이전트4·실제 HTTP2 통과. 저장·편집·다른 계정 차단·
  초안 충돌·철회·삭제 복구·같은 기록을 나중 대화에서 수정하는 흐름을 확인했다.
- Linux x86_64 Rust1.89의 격리 컨테이너에서 관련25개 검사 통과:
  기록 Store10, 삭제 journal7, agent4, HTTP2, 지연 응답 철회1, CLI 설치/HTTP/재시작1.
  소스/vendor는 해시 확인 후 읽기 전용, 실행 네트워크는 차단했다.

## 발견해 고친 결함

독립 검토 AR-1은 문서 commit 뒤 고정 완료 메시지를 쓰기 전에 중단되는 틈을 찾았다.
재시도 때 기존 tool slot은 없어지고 모델이 다시 초안을 만들 수 있었다. 문서 변경,
tool 결과·계수, 완료 메시지와 Completed 상태를 **한 SQLite transaction**으로 묶었다.
확인문 저장에 강제 SQL 실패를 넣으면 전부 rollback되고, 성공 ACK를 버린 뒤 재시작하면
같은 ID/revision의 완료 영수증을 읽는다. 새 모델 호출로 재접수되지 않는다.
이 수정은 독립 재검토를 통과했다.

실제 최종 화면 build를 내장한 Linux CLI 설치 검사도 다시 통과했다.

실제 모바일 화면에서는 긴 편집기가 작업 영역 밖으로 잘리는 문제를 찾았다.
헤더는 고정하고 편집 영역만 스크롤하도록 고쳤으며 입력창·체크박스·버튼을 정리했다.
날짜는 기기 시간대를 표시해 입력받고 UTC로 저장한다.

## 현재 한계

- 채팅은 한 요청에 기록 하나, 본문2048바이트/전체 tool input4096바이트다.
  큰 편집은32KiB 편집기에서 한다. 기존 기록은 정확한 제목 또는 사용자 선택으로
  지정하며 의미 기반 대상 선택·일괄 수정·목표 자동 완료는 제공하지 않는다.
- 원문/기억/기록의 전달된 전체 근거를 물려받는다. 직접 이메일·웹·브라우저 문맥의
  기록 저장은 그 근거 철회 연결이 없으므로 거절한다. 자료로 수집한 근거는 사용할 수 있다.
- 자연어 날짜 해석·알림 실행은 이 기록 기능의 범위가 아니다. 채팅의 새 날짜는 명시적
  UTC 표기만 지원하므로 일반 사용자는 현지 날짜 편집기를 이용한다.
- 미리보기·인쇄 HTML은 escape된 텍스트다. 풍부한 Markdown 렌더링, 이미 내려받은 파일의
  원격 삭제, 물리적 DB 삭제, 실모델 의미 품질 점수를 주장하지 않는다.

새 migration은 자동 기억14→삭제 의도15→개인 기록16 순이다. journal coverage 기준15와
자동 기억의 망각 억제를 유지한다. 새 dependency는 추가하지 않았다. 운영 배포는 별도이며
기존 서비스·수집기·cron·개인 데이터는 변경하지 않았다.
