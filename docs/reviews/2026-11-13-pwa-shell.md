# PWA 공개 화면 수락 기록 — 2026-11-13

범위는 기본 채팅에서 시작하는 설치 가능한 공개 shell과 연결 상태 UX다. 공유받기,
첨부·녹음·Web Push와 실제 iOS/Android 설치는 이 단위에 포함하지 않는다.

## 동작과 검증

- 실제 production build의 HTML·JS·CSS·아이콘만 고정 목록으로 캐시한다. 서비스 워커
  테스트4개는 익명 설치, 실패한 부분 캐시 정리, private API/files·외부 URL·POST 배제,
  온라인 개인 응답 비저장, 오프라인 공개 fallback과 이전 버전 정리를 검사했다.
- React 전체133개가 통과했고, 독립 검토 후 추가한 초기 로딩 재연결 경쟁 회귀1개와
  관련 App/PWA24개를 다시 통과했다. TypeScript 두 구성과 production build도 통과했다.
- macOS와 격리 Linux x86_64에서 실제 CLI 초기화→내장 manifest/icon/worker MIME→
  HTTP 로그인→재시작/세션 여정이 통과했다. Linux는 Rust1.89.0, network none,
  읽기 전용 소스와 nonroot container이며 운영 서비스 배포를 수행하지 않았다.
- 합성 계정으로 실제 Chromium에서 캐시의 공개 파일 목록, 연결 전후 초안 유지,
  서버가 없을 때 공개 shell 시작, 재연결 뒤 세션 확인을 확인했다. API 응답은 캐시하지 않는다.
- 새 워커가 waiting에 머물며 열린 탭을 강제 갱신하지 않는 것과, 탭을 모두 닫고 다시
  열었을 때 새 버전 활성화·이전 캐시 제거를 확인했다. 임의로 skipWaiting을 호출하지 않았다.
- 처음 원본1254px PNG를 manifest에 직접 선언하자 Chromium이 적합한 아이콘이 없다고
  판단했다. 원본 pixels를 바꾸지 않고512px scalable SVG에 bytes를 내장하도록 빌드를
  수정했다. 전용 일반 Chrome 프로필에서 manifest parsing 오류0개, 설치 가능성 오류0개,
  설치 아이콘 존재와 로그인 뒤 **앱으로 설치** 버튼 노출을 확인했다. 실제 모바일 OS 설치
  시험으로 간주하지 않는다. Apple touch icon은 원본 PNG이며 기기 검증은 후속이다.

## 독립 검토와 수정

검토자는 고정한25개 파일의 캐시·계정·업데이트·빌드 경계를 읽었다. 초기 요청이 pending인
동안 online 이벤트가 먼저 오면 재시도가 누락되는 P2를 발견했다. 로딩 중인 최초 부팅도
다시 시작하고 이전 request scope를 폐기하게 수정했다. 지연된503이 새 화면을 덮지 않는
회귀 시험을 추가하고 별도 재검토했다. P0/P1 캐시·계정 격리 결함은 발견되지 않았다.

검토 중 확인한 `/app/skills` 직접 접속 경로 누락은 다음 community 통합 단위에서 처리한다.
이 단위에는 그 화면이 아직 없다. 지원 범위는 [PWA 안내](../pwa.md), 생성 자산 출처와
최종 prompt는 [자산 제작 기록](../design-assets.md)에 있다. CI는 사용자 지시로 비활성이다.
