# Static community catalog generation

Implemented a source-only release generator for R26/R27/F67 and community task2.5. `moosuri skills catalog --repository URL --commit FULL_SHA --package DIRECTORY [--package DIRECTORY...] --output NEWDIR` validates an explicit selection, fetches matching public GitHub commit/tree/blob objects through the existing fixed adapter, validates the same four-file instruction subset as installation, and atomically writes complete static artifacts. No Store/user/installation/private learning source is opened. No Git/hooks/scripts, remote publishing, runtime auto-consumer or activation was added.

The reusable `skill_author::catalog` API accepts a validated Selection, not user-provided downloaded bytes or an asserted commit carrier. Only the existing adapter can construct its downloaded package input. Maximum16 packages, per-source existing12-request/2MiB/30s and32KiB/file/64KiB bounds, total120s and8MiB output bounds. Diagnostics are static and do not echo source text, filenames/paths supplied by the user, credentials or network response bodies.

Artifacts are existing external v2 JSON envelopes named by their existing length-framed source+directory+commit+name+files content digest. `catalog.json` sorts directories, declares canonical source commit and compatible public metadata, and records a separate SHA-256 of each envelope's actual JSON bytes. There is no timestamp, local source path or self-referential index commit. Curated v1 envelope/pin semantics and six known committed file sets remain unchanged. Hashes are not safety, license-rights or successful-execution certification.

Output shares the author CLI's descriptor/no-follow path traversal, app-data marker rejection, private sibling staging, file/directory sync, Linux/macOS non-replacing rename and conservative tracked-inode cleanup. Acquisition/compatibility failure creates no destination; conflict/staging failure cannot replace prior output. A parent-sync failure after successful rename can leave a complete directory to inspect. Generated files are reviewable local release artifacts; current installation still uses the GitHub source UI with the same exact public source selection.

## Independent review repairs and integrated acceptance

Independent review rejected the first freeze because the old shared authoring primitive accepted0777 non-sticky output parents. A deterministic syscall interleaving replaced the staged pathname after inode comparison and published a foreign incomplete directory through the real no-replace rename. This was a source/syscall model, not an end-to-end distinct-UID CLI exploit. The old binary also accepted actual mutable-parent init output. Original freeze, probe and review evidence are retained.

The repair retains a pinned descriptor for every existing ancestor and validates root/current-effective-UID ownership at each step. Group/world-writable directories require sticky mode; sticky does not exempt foreign owners or later children. The full pinned chain and staging directory are checked again before publication and conservative failed-staging cleanup. The CLI never chmods existing directories. Root/current-UID concurrent path/permission changes remain trusted operator actions; name-based rename is not claimed to exclude that actor.

Unix mode bits alone do not represent macOS ACL delete-child/permission grants. On macOS the bounded native descriptor ACL inspection accepts deny-only ACLs (including the normal home-directory delete denial) and rejects grant/unknown ACL entries. Linux rejects detected access/default POSIX and NFSv4 directory ACL attributes rather than inferring their principal trust; inspection errors fail closed with a fixed diagnostic. ACL text/principals are never printed. These local Unix checks do not certify arbitrary filesystem permission policies.

Added regressions cover writable non-sticky ancestors above a private repository, unchanged destination/permissions and pre-network catalog rejection; normal owned sticky temp authoring; foreign-owner sticky/nonsticky policy (actual filesystem case when root can chown); full-chain permission change before publish and conservative cleanup; macOS grant-ACL rejection and deny-only support. Original actual-process tests also retain normal repository/no-replace behavior. The first repaired source also rejected macOS directories with no extended ACL: native inspection returns NULL/ENOENT, including for ordinary root ancestry. Independent native ABI probes exposed this before publication. The final macOS branch recognizes absent ACLs while retaining grant rejection and fail-closed handling for other inspection errors. Original review findings and probes remain retained.

Final repaired validation passed on Rust1.89: macOS CLI units5, actual-process tests10 (including ordinary empty-ACL init/check, deny-only support and grant rejection), and CLI all-target Clippy. Linux passed build, actual distinct-UID ownership probing, installer/author9, adapter4, CLI units5, actual-process9 and affected all-target Clippy. The separate root-capable container setup ran the CLI as UID1000 and confirmed owned/root-sticky acceptance plus rejection of all five mutable/foreign ancestry cases; it modified only disposable container tmpfs. The pre-repair build admitted all five invalid cases. This demonstrates permission-policy enforcement, not a claimed raced end-to-end exploit. Linux ACL rejection was source-reviewed; no real Linux ACL fixture was run.

Independent re-review accepted the final source and Linux evidence; the root then completed the required macOS compiled gates. Only the platform-gated absent-ACL branch differs from the Linux-tested source. The earlier actual public GitHub generation proves immutable source/artifact acquisition and determinism for the unchanged generator; the final output-path repair is covered by the rebuilt filesystem gates. No runtime catalog consumer, private learned export, hosted registry, signing or automatic activation is claimed.
