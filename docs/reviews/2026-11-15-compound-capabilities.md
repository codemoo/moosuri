# Compound assistant capability integration

This unit joins the previously published report/account-wait work with separately
granted native Gmail reads, composed existing actions, private structural learning
and selected browser inputs. It is a development preview, not a stable release or
production cutover. CI remains disabled.

## User outcomes

- Native Gmail model search, selected message/thread and PDF/UTF-8 attachment reads
  wait in the original chat or explicitly delegated mission. Actual signed
  run/step/call/nonce identities, original model/counters/deadlines and withdrawal
  dependencies survive device wait and resume. Legacy display-only mail never
  becomes model evidence. Named accounts cannot fall back to an unrelated opaque
  grant. Durable rotating settlement cursors prevent older offline waits from
  starving later results. Default-off capability/probe boundaries remain.
- Requested local and Gmail provider drafts and primary solo-event creation/date
  moves use the existing MailAction/Calendar ledgers. The original card shows the
  actual draft/action status even after inference expiry. Mail approval remains
  exact and human; no send or approval tool was added. Uncertain effects retain
  their original identity and are not dispatched again.
- Two independent owner-adopted source/calculation/report or local-draft outputs
  qualify a supported private structural recipe. Fresh execution reads new sources
  and uses current recipients/body/intent. Approval and send are not replay nodes.
  Source/action/proof withdrawal and actually used schedule pins retain their
  invalidation rules. Export reconstructs public structure with synthetic examples.
- A human-selected server page becomes one fresh private source in the original
  task, without resetting its budget. The separate trusted-device browser owns a
  temporary private profile and inherited CDP pipe; its projection is only bounded
  page count and lifecycle metadata. It has no model/server browser capability,
  DOM export, vault autofill or website login/read adapter.

Normal open and sealed restore now apply migrations60–68 in order, including the
report/draft adoption tables. Restore removes qualification, browser-derived
sources, connection waits and native authority; it does not revive pending effects.
The generated web contracts include all integrated owner/card/selection types.

## Independent review and repairs

Independent reviews covered native grants and actual task continuation, composed
effects, report and draft qualification, selected server pages, and native browser
process/journal boundaries. Material findings were repaired and re-reviewed:

- Invalid/stale selector input no longer suspends a valid local Google grant;
  actual account/scope/credential failure still retires it.
- Shared English/Korean explicit-account handling preserves account intent.
  Durable bounded sweep positions handle later native reads/receipts even with
  more than64 older non-progressing slots.
- Calendar creation/move authority comes from a narrowly supported event-object
  command, with the same operation in original/current/quoted owner intent.
  Creating a report/table/note or meeting summary cannot authorize an event.
  Prepared effects block acceptance reinterpretation; the old action remains
  visible instead of disappearing from completion checks.
- Immutable adoption route identity prevents editing another graph from stealing
  old proof. Normal `approved → dispatch_committed → sent` preserves an unchanged
  draft's preparation proof; unknown/error/edit/withdrawal still invalidates it.
- Local lock retires the unlocked vault before fallible browser-journal work.
  A real journal write failure cannot leave the unlock object available to polling.

No material finding remains open in those reviewed boundaries. Site-specific
browser automation is outside the reviewed implementation.

## Actual-model development check

A newly authored synthetic battery-budget mission ran through the actual application,
SQLite Store and `gpt-6.1-terra` at `high` using the previously authorized official
local sign-in. The temporary transport admitted only application tools; other native
capabilities were disabled. The initial sandbox startup failed during the model
probe and produced no scored mission. The bounded same setup outside that development
sandbox connected successfully without exporting authentication material.

The first live mission failed to save its report: it repeated successful searches
and exhausted the original six-model-call budget. The runner previously supplied
input/results as nested encoded JSON strings. They now become structured JSON in
mission context, with instructions to continue from completed receipts and return
its requested final report for verification. Stored receipts, evidence identities,
request authority and all budgets remain unchanged.

On a fresh database, the same case then performed one search, one source read and
one two-step decimal workflow, returning `18 × 42.75 − 45 = 724.5` and saving the
requested private report revision. It used five model dispatches including planning,
completed in26.613 seconds through the temporary bridge, and correctly remained
`partial` with `review_required=true` for its explicit human semantic check. No mail
action was created. Three calls had unknown token usage; no full token/cost or speed
claim is made. The failed baseline is retained separately. This is a same-case
post-fix development result, not a new holdout score or general quality guarantee.
Related ordinary/connected/native mission and page-collection Runtime fixtures
verify the structured context through the real transport/Store path. Personal-subscription
fixtures were updated from nested result strings and obsolete raw-message mock responses
to structured receipts and the adapter's actual Gmail `format=full` response. The final
three personal-mission Runtime scenarios passed with zero provider writes.

## Limits and remaining work

The local browser has **no actual website adapter or password/TOTP automation**.
First choose the real site, exact read outcome and dedicated test account, then
pin its official API alternative, policy and independently reviewed projection.
GitHub metadata already has an official API adapter and should use that route.
Arbitrary forms, payments, purchases, calls and government submissions remain
unavailable.

Real Google OAuth/scope behavior, Gmail preservation of operation-marker/raw MIME,
mobile/device deployment, official signed distribution, broad independent model
holdout and production cutover are separate acceptance work. Synthetic execution
does not certify narrative quality, real-provider eligibility or delivery success.
