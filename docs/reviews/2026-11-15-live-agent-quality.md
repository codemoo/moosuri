# 실제 모델 개발 평가 — 2026-11-15

GPT-6.1 Terra / high로 현재 Rust 앱·HTTP·SQLite의 실제 동작을 평가했다.
기억 명령 분류는 실모델36건 모두 일치했다. 최초 비서 시나리오11개는
독립 의미 검토에서9개 성공, 기억 삭제1개 실패, 그 실패에 따른 망각 확인1개 실패였다.
추가로 학습한 계산 절차의 새 대화·위임 업무 재사용을 실제 실행 영수증으로 확인했다.
이것은 작은 개발 평가이며 출시 품질 점수나 독립 holdout 결과가 아니다.

- 공식 Codex CLI0.168.0의 기존 ChatGPT 로그인, 매 스레드에서 확인한
  `gpt-6.1-terra` / `high`. compatible 평가 profile의 effort는 null이며
  실제 공식 런타임의 high와 구분한다.
- 합성 계정과 전용 SQLite만 사용했다. 개인 메일·원문·볼트·운영 DB·cron을
  사용하지 않았고 실제 메일 발송은0건이다. 인증정보는 공식 런타임 안에 남았다.
- 앱·플러그인·shell·hooks·memory·하위 에이전트·MCP를 비활성화하고
  빈 MCP tool 목록을 확인했다. 원시 모델 trace·인증정보·개인 경로는 공개하지 않는다.

[이전 진단](2026-11-14-live-quality-probe.md)의 직접 dynamic-tool 왕복에서는
도구 결과를 인정한 뒤 최종 답변이 비는 현상이 계속 관측됐다. 모델의 기본 지침을
유지한 단독 시험 하나는 통과했지만 앱 경유와 다른 확인값에서는 재현되지 않았다.
이 결과를 기본 지침이나 확인값 형식의 인과적 해결로 해석하지 않는다.

이번 앱 평가는 별도로 검증한 **공식 이력 재입력 경로**를 사용한다. 실제 모델이
요청한 도구를 앱이 실행하고, 실제 호출/결과 쌍 전체를 새 스레드에 넣은 뒤 마지막
실제 결과를 `turn/start.toolOutput`으로 한 번 더 전달한다. 마지막 자료의 반복,
매 회차 새 스레드, 기본 Codex 지침은 평가 조건의 일부다. native dynamic-tool
continuation이나 출시된 구독 adapter와 동일한 전송·비용·성능을 주장하지 않는다.
앱의 text/tool capability probe를 실제로 통과했고 DB capability를 직접 변경하거나
빈 답변을 합성하지 않았다.

## 기억 명령 분류

공개41-case 개발 corpus를 현재 `memory_intent` 요청과 Rust production parser로
실행했다. **실모델36/36**, 모델을 부르지 않는 cue routing **5/5**가 일치했다.
미실행·parser·transport 실패는 없었다. 결정/action/clarification과 parser의
형태·원문 출처 검사를 평가하며 모든 fact/subject/target의 의미 정확도나 실제
저장 결과를 이 수치에 포함하지 않는다. 이 분류 시험은 호출을 포착한 뒤 중단하므로
위 앱 평가의 도구 결과 재입력과도 다른 조건이다.

## 스킬·업무·예약 확장

두 개의 별도 실제 계산으로 개인 합계 절차를 학습했다. 이2개는 자격 형성
setup이며 아래 업무 성공 수에 합치지 않는다.

| 최초 확장 시나리오 | 결과와 판정 경계 |
| --- | --- |
| 새 숫자의 개인 절차 재사용 | 성공: 최종 합계와 실제 learned parent/child 영수증 |
| 지속 위임 업무 | 성공: `achieved`, 실제 learned 영수증·후보 근거, 학습 proof 수 불변 |
| 예약된 개인 절차 실행 | `unknown`/시간 초과. 알림 생성은 업무 성공으로 계산하지 않음 |
| 사용한 스킬 철회 | 전제 미충족: 위 예약이 스킬을 사용하지 못했으므로 종속 정지 시험으로 채점할 수 없음 |
| 배송비가 빠진 비교 | `outcome_unknown`/시간 초과. 의미 추론 실패로 단정하지 않음 |
| 대화로 미래 자료 읽기 위임 | **실패:** 모델 호출 전에 고정 알림으로 저장, 실제 읽기 업무 없음 |

스킬 재사용의 성공은 해당 관측 시점의 실제 영수증을 기준으로 한다. 뒤의 철회
시험에서 스킬을 끄자 앞서 그 스킬에 의존한 대화·업무 출력이 철회됐다. 다시 켜도
과거 결과가 자동 복원되지는 않는다. 최초 성공과 이후의 자료 가용성을 구분한다.

시간 초과 뒤 같은 평가 bridge의 대기가 후속 요청을 지연시킬 수 있어, 별도
진단에서는 공식 호출 한도를24초로 제한하고 내용 없는 단계 관측을 추가했다.
예약된 계산은 새 실제 due 회차에서 `achieved`·실제 learned child 영수증으로
완료됐고, 배송비 미상 비교도 실제 두 원문을 읽고 미상을 설명했다. 최초 실패를
이 진단 성공으로 교체하거나 합쳐 성공률을 올리지 않는다. 한도 변경이 성공의
유일한 원인이라는 인과 주장도 하지 않는다.

같은 삭제 문구의 별도 진단은 다시 `protocol_failed`였다. 이 요청은 기억 분류기
전에2-tool 업무/Calendar 분류로 들어갔다. 단순 “아침” 단어를 시간 위임 신호로
취급하는 비용 분기가 불필요한 선행 분류를 만든다. 실제 저장은 수행되지 않았고
다른 기억은 보존됐다.

## 수정 후 별도 실모델 수락

미래 자료 읽기를 고정 알림으로 처리하는 분기를 수정하고, 업무 해석의 시간 신호를
보완했다. 단순 “아침 운동” 주제는 불필요한 업무/Calendar 분류를 거치지 않으며
“아침에”·반복·구체적인 시각은 유지한다. 실행 순서·pristine admission·기억 권한이나
메일 승인 규칙은 바꾸지 않았다. 고정 알림, 인용·금지 표현, 이메일 발송을 제거한
축소 업무를 저장하지 않는 경계를 함께 검증했다.

같은 Terra/high와 공개된 평가 조건으로 실패와 관련된3개만 다시 실행했다.
**3/3이 해당 후속 조건을 통과했으며 최초9/11과 합치지 않는다.**

| 후속 사례 | 실제 결과 |
| --- | --- |
| 아침 운동 기억만 삭제 | 대상 tombstone, 원문 version·검색 행0개, 출퇴근 기억 보존 |
| 새 대화의 삭제 후 회상 | 삭제한 활동이나 해당 근거를 반환하지 않음 |
