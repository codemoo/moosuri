# 새 합성 업무의 실모델 개발 평가 3차

공개 기준 `1a45045`를 독립 작성한 새 합성 세계5개·요청9개에서 평가했다.
자료의 근거와 정확 계산을 담은 보고서, 충돌·누락 자료의 검토 보고서,
소유자 기억 정정과 새 대화 회상, 같은 업무의 계산 조건 정정,
근거 계산 A/B 학습 뒤 새C 재사용을 포함한다.

실행 전에 요청과 별도 판정 기준을 고정했다. 보고서 확인 조건은 문서 제목과
사람 검토 요구만 전달하며, 계산 정답은 모델에 전달하지 않는다. 모든 요청의
실패·미실행을 남기며 연결이나 모델 응답의 숨은 재시도는 없다.
이5세계×1회는32세계×3회 pilot나 출시 holdout를 대신하지 않는다.

## 고정 조건

- 기준 소스 `1a450451b84d65a738c4b7442f4cdca5c99eb92a`.
- 모델 `gpt-6.1-terra`, effort `high`, 기존 공식 로컬 로그인.
- 세계마다 새 앱·SQLite·소유자/별도 계정. 자료와 계정은 전부 합성이며 실제 메일이나 외부 작업을 수행하지 않는다.
- 이전 평가와 같은 임시 공식 이력 재입력 연결을 사용한다. 제품 구독 연결이나 운영 지연을 측정하는 시험은 아니다.
- 입력 SHA256 `267b2f249aac968d6b587d3b101bc9f91c8feadfcd8619614cbcc91304a026b7`.
- 판정 기준 SHA256 `7917e053fa97950f53b1342bb04ceee4e99615cb93789772d3ce36349fd24df1`.
- 연결 전체 한도120호출·개별 호출24초. 원래 앱의 모델/도구/업무 예산을 유지한다.

## 최초 결과와 보완

최초9개 요청을 모두 실행했다. 독립 의미 판정은7/9, 저장 상태·실제 근거·학습 재사용을
포함한 엄격 판정은3/9였다. 세계 전체 통과는 각각3/5,2/5였다. 정확 보고서와 계산B는
내부 산술 결과는 맞았지만 호출 한도를 소진해 최종 답변을 내지 못했다. 보고서도 저장되지 않았다.

숫자 사례6개에서 호출한 `evidence_calculate`7회는 모두 `invalid_input`이었다.
요청의 마지막 수치가 `4.08을`, `2.64야`, `1.95로`, `3.27로`, `6.41로`, `8.36으로`처럼
한글에 붙어 있었다. **사례 작성자가 기존 문서의 구분자 지원 범위를 넘겨 성공을 기대한
한계가 있다.** 이 최초 결과를 기존 계약 위반만으로 설명하지 않는다. 자연스러운 사용을
지원하기 위해 실제 허용 문법을 확장했다.

현재 요청의 완전한 숫자 뒤에 유한한 한글 조사·단위·서술 어미가 올 수 있게 했다.
숫자의 앞 부호/경계, 정확히 한 번 등장하는 현재 인용, 원문 identity/revision과 실제
읽기·계산 영수증 검사는 유지한다. 단위 환산이나 임의 한글 수사 해석은 하지 않는다.
독립 검토에서 `4만`을4로 읽을 수 있는 문제를 발견해 고쳤다. 배수를 뜻할 수 있는
단독 `만`은 거절하고 `4개만`처럼 단위가 먼저 있는 명확한 경우만 허용한다.

## 같은 사례의 수정 후 재실행

입력·정답 hash를 유지하고5개 세계를 새 DB에서 한 번씩 전부 재실행했다. 독립 판정은
의미9/9·엄격9/9, 세계5/5였다. 수정에 사용한 사례의 회귀 결과이며 새 holdout 점수가 아니다.

| 사용자 결과 | 최초 엄격 통과 | 수정 후 엄격 통과 | 실제 확인 |
| --- | ---: | ---: | --- |
| 근거·정확 계산 보고서 |0/1|1/1|원문2개·근거 계산259.35·문서1개 저장, 보험 비용 미정을 구분|
| 충돌·누락 자료 보고서 |1/1|1/1|서로 다른 원문과 모르는 값을 보존한 문서1개|
| 기억 정정·새 대화 회상 |2/2|2/2|같은 기억 revision2 정정과 새 대화 읽기, 다른 계정 보존|
| 같은 업무의 계산 조건 정정 |0/2|2/2|실제 원문 재조회와 현재 조건의182.73→205.53|
| 계산 A/B 학습→새C |0/3|3/3|서로 다른 두 proof로 사용 가능해진 절차를 새 자료에서 실제 실행|

C는 실제 `learned_skill` 호출과 사용 기록을 남겼다. 자식 검색/읽기가 새 소유자 자료를
다시 읽었고 정확 계산 `31.74 × 11 − 8.36 = 340.78`을 수행했다. 단순 산술 자식 기록이나
모델의 성공 선언을 스킬 사용으로 세지 않았다. 다른 계정에는 학습 절차가 생성되지 않았다.
두 보고서의 실제 문서 본문은 미션 결과와 같고 소비한 원문2개의 revision에 연결된다.
사람 검토를 요구한 두 업무는 문서가 저장된 뒤에도 `partial/review_required`를 유지했다.
모든 원문과 다른 계정의 자료는 보존됐고, 실제 메일 작업·예약 생성은0개였다.

## 검증과 한계

변경 경로의 Linux 근거 계산 Store4개·실제 Runtime1개와 Clippy를 통과했다. 독립 검토의
배수 모호성 수정과 서술 어미 추가 뒤에는 실제 Store의16개 입력 변형을 포함한 회귀1개와
Clippy를 최종 Linux 소스에서 다시 통과했다. 소스 archive hash는
`f4efd2fe7b7505e46ecaeef6753a36102a33c40247955d2c4bc7a6b4029470eb`다.
실제 모델의 최초 바이너리 hash는
`5343690af1d062d997c97f86d848453f7fa859bd9e01159ccadaf03367f0e30f`,
수정 후는 `de43aff091dd5867f78ba878e4a353f457f63168d5277b8c2c3e9e72a6a4cbc2`다.

최초 업무 모델 호출42회에서 수정 후32회로 바뀌었다. 연결 확인을 포함한 임시 bridge는
57회/47회였다. 관측한 중앙 전체 시간은20.633초/17.032초지만 작은 같은 사례의 반복이며
운영 속도나 통계적 개선을 주장하지 않는다. 입력/출력 사용량 누락은 각각34/42회와22/32회다.
누락을0으로 채우거나 비용 절감으로 계산하지 않는다.

정확 보고서의 `calculation_required` 표시는 요청의 산술 표현을 포괄하지 못해false였다.
이번 산출물에는 실제 근거 계산이 있고 고정 판정을 통과했지만, 더 넓은 자연어 계산 필요성
판정은 남은 개선으로 기록한다. 임의 한글 표현·전체 의미 품질·실제 구독 배포·provider/device·
출시 수락을 이9건으로 완료 처리하지 않는다. 최초 실패·사례 계약 한계와 수정 후 결과를
따로 보존하며, 개인 인증값·DB·원문 trace는 공개하지 않는다. CI는 계속 꺼둔다.
