# Native Google INBOX counts acceptance

P8/F69 adds one default-off typed Google adapter alongside GitHub. The device
locally unlocks the selected independent vault item, refreshes OAuth through fixed
Google endpoints, verifies actual scopes and the pinned subject/email against
UserInfo and Gmail profile, then returns only four bounded INBOX label counts.
No provider strings, email, token, message content, Calendar or write operation
crosses that projection. This does not replace the separate personal Gmail OAuth
connector used for collection, reading and approved sends.

The initial independent review found two defects: topic substrings could admit a
negated/translation request, and updated archive credentials could not reconnect
before the old grant expired. R1 implements a finite affirmative whole-message
grammar with actual forced-tool zero-job/dispatch rejection cases, and explicit
same-vault/item/account revision/key-epoch refresh with retained-work reconciliation,
unchanged expiry and pending-CAS/registration-ACK recovery. Existing commitments
keep their exact old identities; entered provider requests are not replayed.

Native R0 evidence covers the actual refresh/identity/profile/INBOX failure matrix,
real encrypted archive grant/execution and no-secret receipt journal, independent
old signed-byte golden vectors, actual original-chat waiting/restart/reuse/cancel,
typed HTTP settings/default-off, GitHub and original-session compatibility, generated
types, React3/type/build and affected all-target Clippy. Focused R1 checks passed
the real encrypted archive revision/root refresh, actual Store registration-ACK/CAS
and retained commitments, forced-tool nonaffirmative runtime rejection, positive
original-chat completion and grammar cases; affected all-target Clippy passed.

Root integrated all41 frozen R0 hashes. Its pinned offline Linux capsule passed
Google native3, credential chat/profile compatibility, actual Google original-chat
completion, Store literal/original-session, typed HTTP/default-off, all-target
Clippy and the default assistant/companion build. R1 was then integrated with all41
hashes matching. Only affected R1 behavior/build gates are rerun; unchanged R0
checks remain evidence for their exact unchanged source.

Actual isolated Chrome with the production React build and synthetic API confirmed
separate GitHub/Google lists, four displayed counts and the failed-request retry
flow. The existing device settings page was clipped on mobile because it lacked
an internal scroller. R1 reuses `admin-scroll`: at390x844 the main area is768px,
content1459px, overflow auto, and scrolling leaves the header at y0. The resulting
screenshot was inspected. React request-identity tests and actual Rust lifecycle
tests establish same-request replay; browser UI observations do not substitute
for real Google or native-device acceptance. An initial browser attempt used stale
Vite dev modules; the accepted check used the current production build.

No DB migration, dependency, production credential/account/provider access, deployment
or CI change. Strict actual scopes, known local subject/email, finite chat grammar,
single selected account per device and source-built companion remain explicit
experimental limits.

Independent R1 review accepted both repairs with no new material finding; the full
patch and all41 frozen file hashes matched. The final integrated offline Linux
