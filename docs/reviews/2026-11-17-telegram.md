# Telegram transport · 2026-11-17

R30/F71 adds an optional private-text transport alongside the PWA. One encrypted
installation bot serves independently paired accounts. Runtime supervision owns
one long poller and sender; no webhook or public endpoint is added. Existing
chat admission, model execution, tools, live instructions, cancellation and final
mail-preview approval remain authoritative.

Pairing hashes, bot revision, session authority, account epoch, update offset,
run references and delivery commitments are persisted in schema75. Pairing is
one-use/ten-minute and requires a full authenticated web session. Its independent
channel session survives ordinary browser logout; revocation/restore fences it.
Input admission and offset advancement commit together. Unknown sends remain
unknown after restart; explicit 429 alone schedules a bounded resend. Notifications
are opt-in generic links, respecting inbox ownership, read/mute/quiet status.

Independent boundary review covered account pairing, authentication, storage,
transport, revocation and restore. A targeted follow-up identified a completed
parent chat hiding an active delegated task from `/stop`/`/status`, and web retries
losing their Telegram delivery tracking. Both were fixed through existing mission
cancellation and the chat retry transaction; regression outcomes passed and the
reviewer found no remaining material defect in those deltas.

Native outcomes passed:
- Five Telegram Store contracts cover private one-use pairing, multiple accounts,
  duplicate input, browser logout, expiry/epoch, generic notification mute,
  uncertain send/reopen, disconnect/restore, delegated cancellation and retries.
- One synthetic HTTP end-to-end scenario uses the real Bot API connector,
  supervised agent and model stream. Duplicate updates create one model call;
  typing, 429 delayed retry, stored conversation/web link and disconnect are checked.
- 61 shared chat cases, 4 live-instruction cases, 4 schema cases, and one each
  for restore-schema, full restore and encrypted backup passed. The registry test's old schema74 assertion
  was updated to75; migration checks validate every supported predecessor.
- Three React settings tests cover secret-input clearing, pairing/preferences/disconnect
  and delayed responses across accounts. Type checking, embedded web build and
  scoped all-target Clippy passed.

Isolated Linux passed the same Telegram transport and Store outcomes, scoped
chat/live-instruction/schema/backup/restore checks (43 cases in total) and Clippy.
Its initial run retained the old version-assertion failure; a new verified snapshot
reran only the corrected registry suite. Production sources and web assets were
unchanged between those snapshots. The original failure remains in local evidence.

Direct-entry checks then caught missing embedded-app routes for `/admin/telegram`
and `/settings/telegram`: in-app navigation worked but refresh/direct access did
not. Both routes now serve the same public application shell, while unknown paths
still return404 and private APIs retain authentication. The focused native and
Linux entry test passed; final packages include the corrected CLI.

Release builds passed for macOS ARM64/Intel and Linux x64/ARM64. Packaged Linux
x64 and ARM64 QEMU execution passed initialization, embedded web, synthetic login,
disabled Telegram settings, graceful stop and doctor. macOS ARM64 executes its
probe; Intel is cross-built. Signed installer publication is the remaining step.
Live Telegram account/device acceptance has not been performed. No real bot
credentials or messages were used. CI stays off. Text/private chats are supported;
attachments/audio/groups and detailed approval/task cards remain web features.
