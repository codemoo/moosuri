# Kiri 회원 화면 개편 작업 대장

회원은 자기 서비스·대화·기억·맡긴 일을 관리하고, 설치 관리자는 회원과 엔진을 관리한다. 11월 20일 로컬 개편판과 같은 날 확인한 공개·운영 상태를 기록했다. [화면별 시나리오](2026-11-20-kiri-scenarios.md) · [제품 기능 71개의 시나리오와 근거](../../audit/feature-journeys.tsv)

| 9. 맡긴 일 | 로컬 검증 | 자기 브라우저 업무 목록에서 저장 결과·상태 이력·원래 대화로 복귀한다. |
| 10. 초대 자동 준비 | 격리 Linux 검증 | 두 웹 초대, 용량 부족·증설·재시도, 회원 로그인과 최초 비밀번호 변경을 확인했다. |

| 12. 공개 데모 | 로컬 브라우저 검증 | 비회원이 합성 대화 세 개를 체험하고 회원 로그인으로 이동한다. |

## 작업별 워크로그

### 1. 서비스 연결

- 11월 20일 · 목록에 서비스별 연결 계정과 상태를 표시하고 상세에는 읽을 수 있는 범위를 표시했다. 설치 관리자는 Google 설정을 열고 기존 서비스로 돌아갈 수 있다.
- 합성 Google 동의 성공·취소, 응답 유실, 목록 열람 시 받은편지함을 읽지 않는 경로를 검사했다. 운영 Google 앱 등록 후 실계정 동의와 첫 조회가 남았다. [연결 절차](../../deployment/kiri/google.md)

### 2. 회원 관리

- 11월 20일 · 이름·이메일·상태로 회원을 찾고 초대 접수 번호를 복사할 수 있게 했다. 선택한 회원의 권한·정지 변경과 확인 결과를 한 흐름에서 볼 수 있다.
- 초대 응답 유실 후 동일 요청 확인, 마지막 관리자 보호, 키보드로 변경을 취소했을 때의 초점 복귀를 검사했다. [회원 관리 검증](../../web/src/PersonalAdmin.test.tsx)

### 3. 엔진 관리

- 11월 20일 · 현재 적용된 모델·추론 강도·요청 허용 상태와 저장할 값을 구분했다. 다른 관리자가 먼저 설정을 바꾼 경우 최신 값을 다시 읽는다.
- 관리자 설정의 저장·충돌 복구와 일반 회원의 엔진 주소 접근을 검사했다. [엔진 검증](../../web/src/PersonalEngineSettings.test.tsx)

### 4. 대화 이어가기

- 11월 20일 · 대화 목록을 날짜별로 묶고 미전송 초안을 표시했다. 대화 제목 옆에서 현재 작업을 확인한다. 작성 예시는 입력창에 넣은 뒤 수정해 보낼 수 있다.
- 목록 조회 실패 후 재시도와 예시 선택 시 자동 발송이 발생하지 않는 흐름을 검사했다. [대화 검증](../../web/src/PersonalPreview.test.tsx)
- 실제 로컬 모델이 출력 한도를 다 쓰고 빈 본문으로 종료했을 때의 오류를 수정했다. 회원은 새로고침 뒤에도 미완료 상태를 볼 수 있다. 숫자·시각을 되묻는 대화는 모델별로 답의 정확도와 전송·저장을 확인했다. [실제 모델 대화](2026-11-20-kiri-scenarios.md#실제-로컬-모델-대화)
- 긴 대화에서는 회원별 요청 한도와 실제 전송 크기에 맞춰 최근 턴을 전달한다. 저장 이력은 모두 남고, 현재 입력이 너무 길면 전송 전 안내와 수정할 초안이 남는다. [세 가지 긴 대화 검증](2026-11-20-kiri-scenarios.md#긴-대화와-한-번의-모델-요청-한도)

### 5. 기억 편집

- 11월 20일 · 기억 목록에 작성 중인 초안과 마지막 저장 시각을 표시하고, 상세에서 수정 이력별 시각을 확인할 수 있게 했다.
- 작성 도중 메뉴를 오간 후 초안을 다시 열고, 저장된 기억을 수정해 이력을 확인하는 흐름을 검사했다. [기억 검증](../../web/src/PersonalMemories.test.tsx)

### 6. 화면 이동

- 11월 20일 · 커넥터 상세·Google 설정·관리 탭을 브라우저 방문 기록과 연결했다. Google 동의 후 새로고침할 때 상세를 잃는 문제와 목록 복귀 시 진입 메뉴를 잃는 문제를 수정했다.
- 개편 초기에는 Chrome 360·390·1366px에서 탐색을 확인했다. 후속 수락에서는 Chrome과 WebKit 360·390·1440px에서 로그인·업무·동의·회원 관리·데모를 조작했다. 실물 iOS·Android의 PWA 재진입은 남아 있다. [탐색 계약](../../openspec/changes/isolate-account-runtime/specs/account-runtime/spec.md)

[1440px 대화](2026-11-20-member-desktop.png) · [390px 업무 상세](2026-11-20-task-mobile.png)

### 7. 소스 공개

- 11월 20일 · 초기 UI 커밋 `9c116fa` 뒤의 대화·관리·브라우저·복구 수정까지 무수리 로컬 main에 반영했다. 자동 승인 검토에서 공개 저장소 전송에 대한 명시적 승인을 요구했다.
- 재개 조건은 해당 소스를 공개 GitHub에 보내는 데 대한 사용자 승인이다. 이후 원격 main에 UI 커밋이 포함됐는지 확인하고 이 항목을 닫는다.

### 8. 운영 배포

- 11월 20일 · Linux 게이트웨이 후보를 빌드하고 로컬과 서버의 웹 진입 파일 해시 일치를 확인했다. 운영 전환에는 회원 DB와 레지스트리 백업, 게이트웨이·브로커·회원 실행본의 공동 절체가 필요하다. 현재 운영 실행본은 `4fd6a01`이다.
- 최종 제품 소스 `fc4611a`의 Rust 1.89 Linux 릴리스 실행 파일 SHA-256은 `b15c90ee24b69f0e176a967c3ce69fb9f6ca960b493a31afa3a772c47ab5da25`다. Linux 실행 파일이 내보낸 API 타입과 로컬 웹 타입이 일치했다. 최종 Linux 저장소 회귀 11건과 macOS 게이트웨이·브로커 회귀 28건이 통과했다. 게이트웨이·브로커 검사를 병렬 실행한 첫 시도에서 세 회원 초기화가 Busy를 반환했고 같은 바이너리로 순차 실행했다.
- 재개 조건은 운영 전환에 대한 사용자 승인이다. 전환 후 공개 HTTPS의 HTML·CSS·JS를 빌드와 대조하고 주요 화면을 확인한 뒤 배포 결과를 기록한다.

### 9. 맡긴 일

브라우저 업무의 목록과 상세에서 원래 요청, 다음 차례, 결과, 상태 변경 시각을 확인한다. 오래된 업무의 원래 대화까지 페이지를 넘겨 정확한 턴으로 이동한다. 스키마 89가 기록하지 않은 시각은 미기록으로 표시한다. 미션·예약·후속 모니터의 표준 서버 이관은 전환 작업표에 열려 있다. [맡긴 일 시나리오](2026-11-20-kiri-scenarios.md#맡긴-일)

### 10. 초대 자동 준비

설치자가 UID와 용량 한도를 설정하면 호스트 타이머가 웹 초대별 저장공간과 프로필을 준비한다. 운영자가 최초 비밀번호를 입력한 뒤 회원이 첫 로그인에서 변경한다. 같은 초대를 다시 처리해도 기존 볼륨과 비밀번호가 유지됐다. [Ubuntu와 Kiri 게스트 실행 기록](../../deployment/kiri/linux-vm-smoke/onboard-worker-evidence.json)

### 11. 공급자 사용 한도

OpenRouter 관리자 조회는 등록된 키와 연결 버전에 묶인다. 공식 응답에서 0과 미제공을 구분하며 Claude·ChatGPT 등의 구독은 공식 사용량 화면을 안내한다. 한 탭의 완료 결과가 뒤이어 열린 탭의 조회로 사라지던 문제를 수정했다. 설치 레지스트리 v7이 만료까지 요청별 접수증을 보존한다. [한도 확인과 운영 절차](../../deployment/kiri/admin.md) · [시나리오](2026-11-20-kiri-scenarios.md#관리자-openrouter-사용-한도)

### 12. 공개 데모

회원 자료나 모델 호출 없이 시간표·기억 정정·맡긴 일의 합성 대화 세 개를 보여 준다. 브라우저 크기 두 가지에서 예시 전환, 연습 초안 폐기, 회원 로그인 진입을 확인했다. [검증과 공개 화면](../../audit/standard-journey-checks.md#f18-합성-미리보기)

### 13. 표준 서버·볼트·이전

제품 기능표의 71개 기능을 217개 시나리오로 검증했다. 196건 통과, 7건 부분 확인, 11건 실환경 대기, 3건 후속 범위다. 동명이인 두 명의 1,002턴 기록에서 같은 질문 3개의 원문 검색·정답이 2/3에서 3/3으로 개선됐다. 만료된 볼트 인증 코드의 표시·복사를 차단했고, 구버전 백업 오류 수정 후 스키마 47에서 90으로 네 중단 지점을 거쳐 복구했다. 이미지가 포함된 대화에서 명시적인 알림 명령이 대기열에 남던 문제도 수정했다. 관련 일정·미디어 회귀 63건이 통과했다. ## 개편 중 발견해 해결한 문제

| 발견 당시 동작 | 수정 후 확인 |
| --- | --- |
| A 전송 뒤 B를 쓰다 A가 거절되면 원문이 사라짐 | 거절된 A와 작성 중 B가 새로고침 뒤에도 분리되고, A만 동일 번호로 재시도된다. |
| 초대 응답 유실 후 화면을 나가면 접수 확인이 사라짐 | 같은 관리자 세션에서 동일 요청으로 결과를 확인한다. 활성 회원도 표시 이름으로 찾는다. |
| 엔진을 재개해도 다른 화면을 거친 채팅이 잠김 | 대화 복귀와 창 포커스에서 현재 상태를 확인한다. 늦은 상태 응답은 최신 값을 덮지 않는다. |
| Google 동의 뒤 이전 화면 대신 빈 대화로 이동 | 동의 성공·취소 뒤 브라우저 뒤로·앞으로 가기로 상세·목록·출발지에 도달한다. |
| 설정에서 뒤로 가면 관리자 대신 커넥터 목록이 열림 | 설정의 뒤로 버튼은 진입 화면으로 돌아간다. 커넥터 열기는 목록을 연다. |
| 오래된 업무의 원대화 첫 페이지에 해당 턴이 없음 | 이력 페이지를 읽어 해당 턴에 초점을 맞춘다. 만료된 직접 조작 상태도 다시 확인한다. |
| 모델이 본문을 만들기 전에 출력 한도에 도달하면 결과 불명으로 표시됨 | 원래 요청에서 확인된 미완료 상태를 복원하고, 모델 재호출 없이 회원에게 표시한다. |
| 이미지가 있던 대화에서 명시한 알림 명령이 계속 대기함 | 일정 변경 없이 설명을 한 번만 저장한다. 일반적인 이미지 질문은 모델로 이어진다. |
| 이미지 대화에서 설치 모델을 구독 연결로 바꾸면 알림 명령에도 이미지를 다시 선택하라고 안내함 | 알림은 회원의 기존 요청을 확인하고 고정 응답으로 끝난다. 이미지를 실제로 사용하는 일반 질문에서는 연결 권한을 다시 확인한다. |
