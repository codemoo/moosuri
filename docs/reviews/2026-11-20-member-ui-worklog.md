# Kiri 회원 화면 개편 작업 대장

**상위 목표**는 회원이 자기 서비스와 대화를 관리하고, 설치 관리자가 회원과 엔진을 운영 웹에서 관리할 수 있게 하는 것이다. 구현 기준은 `9c116fa`다. 아래 기록은 2026년 11월 20일 인계 시점 기준이다.

| 작업 | 상태 | 완료를 판단하는 결과 |
| --- | --- | --- |
| 1. 서비스 연결 | Google 왕복 수정 · 실계정 확인 남음 | 회원이 서비스별 권한과 계정을 확인하고 Google 동의 후 같은 상세로 돌아온다. |
| 2. 회원 관리 | 요청 복구·활성 회원 검색 수정 필요 | 관리자가 대상을 찾아 초대 상태를 확인하거나 권한·정지를 관리할 수 있다. |
| 3. 엔진 관리 | 엔진 재개 후 대화 상태 갱신 필요 | 관리자가 현재 설정과 변경 예정 값을 구분하고, 충돌 후 최신 상태에서 다시 선택할 수 있다. |
| 4. 대화 이어가기 | 전송 거절 시 원문 보존 필요 | 최근 대화, 미전송 초안, 현재 진행 중인 작업을 찾아 이어간다. |
| 5. 기억 편집 | 로컬 검증 완료 | 회원이 작성 중인 기억을 다시 열고 저장·수정 시점을 확인한다. |
| 6. 화면 이동 | 외부 동의 왕복 수정 · 실기기 확인 남음 | 뒤로·앞으로 가기와 새로고침 후 원래 화면이 열리고 회원 권한이 적용된다. |
| 7. 소스 공개 | 승인 대기 | GitHub의 공개 main에서 UI 커밋을 확인한다. |
| 8. 운영 배포 | 승인 대기 | 운영 게이트웨이가 검증한 웹 파일을 제공하고 운영 주소에서 화면 이동이 동작한다. |

## 작업별 워크로그

### 1. 서비스 연결

- 11월 20일 · 목록에 서비스별 연결 계정과 상태를 표시하고 상세에는 읽을 수 있는 범위를 표시했다. 설치 관리자는 Google 설정을 열고 기존 서비스로 돌아갈 수 있다.
- 합성 Google 동의 성공·취소, 응답 유실, 목록 열람 시 받은편지함을 읽지 않는 경로를 검사했다. 운영 Google 앱 등록 후 실계정 동의와 첫 조회가 남았다. [연결 절차](../../deployment/kiri/google.md)

### 2. 회원 관리

- 11월 20일 · 이름·이메일·상태로 회원을 찾고 초대 접수 번호를 복사할 수 있게 했다. 선택한 회원의 권한·정지 변경과 확인 결과를 한 흐름에서 볼 수 있다.
- 초대 응답 유실 후 동일 요청 확인, 마지막 관리자 보호, 키보드로 변경을 취소했을 때의 초점 복귀를 검사했다. [회원 관리 검증](../../web/src/PersonalAdmin.test.tsx)

### 3. 엔진 관리

- 11월 20일 · 현재 적용된 모델·추론 강도·요청 허용 상태와 저장할 값을 구분했다. 다른 관리자가 먼저 설정을 바꾼 경우 최신 값을 다시 읽는다.
- 관리자 설정의 저장·충돌 복구와 일반 회원의 엔진 주소 접근을 검사했다. [엔진 검증](../../web/src/PersonalEngineSettings.test.tsx)

### 4. 대화 이어가기

- 11월 20일 · 대화 목록을 날짜별로 묶고 미전송 초안을 표시했다. 대화 제목 옆에서 현재 작업을 확인한다. 작성 예시는 입력창에 넣은 뒤 수정해 보낼 수 있다.
- 목록 조회 실패 후 재시도와 예시 선택 시 자동 발송이 발생하지 않는 흐름을 검사했다. [대화 검증](../../web/src/PersonalPreview.test.tsx)

### 5. 기억 편집

- 11월 20일 · 기억 목록에 작성 중인 초안과 마지막 저장 시각을 표시하고, 상세에서 수정 이력별 시각을 확인할 수 있게 했다.
- 작성 도중 메뉴를 오간 후 초안을 다시 열고, 저장된 기억을 수정해 이력을 확인하는 흐름을 검사했다. [기억 검증](../../web/src/PersonalMemories.test.tsx)

### 6. 화면 이동

- 11월 20일 · 커넥터 상세·Google 설정·관리 탭을 브라우저 방문 기록과 연결했다. Google 동의 후 새로고침할 때 상세를 잃는 문제와 목록 복귀 시 진입 메뉴를 잃는 문제를 수정했다.
- Chrome의 360·390·1366px 화면에서 탐색을 확인했다. 통합 웹 테스트 724개, 타입 검사와 정적 빌드를 통과했다. 실물 iOS·Android에서 PWA 재진입을 확인하는 일이 남았다. [탐색 계약](../../openspec/changes/isolate-account-runtime/specs/account-runtime/spec.md)

### 7. 소스 공개

- 11월 20일 · 로컬 main에 UI 커밋 `9c116fa`를 반영했다. 자동 승인 검토에서 공개 저장소 전송에 대한 명시적 승인을 요구했다.
- 재개 조건은 해당 소스를 공개 GitHub에 보내는 데 대한 사용자 승인이다. 이후 원격 main에 UI 커밋이 포함됐는지 확인하고 이 항목을 닫는다.

### 8. 운영 배포

- 11월 20일 · Linux 게이트웨이 후보를 빌드하고 로컬과 서버의 웹 진입 파일 해시 일치를 확인했다. 운영 전환에는 게이트웨이 재시작 승인이 필요해 기존 버전이 서비스 중이다.
- 재개 조건은 운영 전환에 대한 사용자 승인이다. 전환 후 공개 HTTPS의 HTML·CSS·JS를 빌드와 대조하고 주요 화면을 확인한 뒤 배포 결과를 기록한다.

새 진행이 생기면 해당 작업에 **날짜, 달라진 결과, 확인 근거, 남은 일 또는 재개 조건**을 추가하고 표의 상태를 갱신한다. 여러 작업이 함께 받는 통합 검증이나 배포는 한 곳에 기록한다.


## 11월 20일 통합 점검

공개 main과 운영 게이트웨이 실행 파일은 `4fd6a01`이었다. 공개 HTTPS의 진입 HTML도 로컬 개편판과 달랐다. 724개 웹 테스트·타입 검사·빌드는 개편 당시의 통과 기록이다. 아래 재현은 개편판에서 합성 응답으로 별도 확인했다. [이전 운영 결과](2026-11-19-status-history.md) · [현재 운영 범위](../status.md)

### 다음 작업을 묶는 단위

| 이용자가 얻을 결과 | 현재 경계와 남은 완료 조건 |
| --- | --- |
| 회원이 맡긴 일을 다시 찾아 이어간다 | 개발 워크로그는 위 8개 작업을 추적한다. 제품 안의 회원별 업무 목록·장기 기록은 별도 제안이다. 첫 범위는 이미 실행되는 브라우저 업무로 잡는다. 목록에서 업무를 열어 요청·사용자 개입·재개·결과를 보고 원대화로 돌아간다. 재시작 후 같은 업무 링크, 과거 기록 페이지 이동, 두 회원 간 격리와 중복 실행 방지를 확인한다. 이후 표준 서버의 미션·예약 회차·후속 모니터를 연결한다. |
| 회원 초대부터 첫 Google 조회까지 마친다 | 웹 초대 접수 후 호스트에서 계정 준비·초기 비밀번호 전달이 남는다. Google 설정도 API 준비 후 동의 화면과 웹 클라이언트 등록이 필요하다. 두 회원이 각각 동의하고 각자의 자료를 읽고, 재시작·재인증·연결 해제 후에도 계정 경계와 실제 조회 결과가 맞아야 한다. |
| 관리자가 공급자 상태와 사용 여력을 판단한다 | Kiri에서 관리자 모델·추론 강도를 설정할 수 있다. 공급자 추가·첫 인증과 모델 목록 갱신 흐름, 공급자가 제공하는 잔여량·초기화 시각을 추적한다. 공식 수치가 없는 경우 확인 불가 상태와 공식 확인 경로를 표시한다. 내부 사용 집계는 별도로 표시한다. |
| 전 화면에서 무수리 디자인과 조작이 일관된다 | Muse 기준 1440px 화면의 탐색 폭은 72px이고 개편판의 넓은 화면은 176–232px이다. 문서의 조작 강조색과 개편판의 민트 사용도 다르다. 화면별 같은 크기에서 대조해 유지할 차이를 결정한다. 로그인·대화·기억·연결·관리에서 Astryx 컨트롤, 여백·한글·오류와 빈 화면을 확인하고 실제 iOS·Android에서 키보드와 PWA 복귀를 확인한다. |
