# Kiri 회원 업무 흐름 워크로그

**맡긴 일**은 원래 요청에서 실제 실행, 단계별 근거, 결과, 원래 대화로 이어진다. 저장된 검색 조건과 실행한 회차는 서로 다른 항목이다. 이번 개편은 운영 절체 전의 로컬 후보에서 진행했다. [회원 사용법](../member-tasks.md)

## 업무 기록과 화면 이동

| 시나리오 | Linux에서 확인할 결과 |
| --- | --- |
| TLOG-01 일반 대화에서 업무 열기 | 회원 브라우저·게이트웨이·SQLite에 같은 질문과 응답이 있고, 문맥 준비 단계를 선택하면 실제 이전 메시지 수가 보인다. |
| TLOG-02 모바일 단계와 직접 주소 | 360px에서 다시 열어 특정 근거를 읽고 타임라인으로 돌아오면 선택했던 버튼이 초점을 받는다. 원래 대화의 해당 턴을 다시 연다. |
| TLOG-03 회원 교체 | 두 번째 회원의 목록과 예약은 비어 있고 첫 회원의 주소는 열리지 않는다. |
| TLOG-04 이전 브라우저 이력 | 기존 작업과 시각이 남지 않은 과거 상태가 유지된다. 새로 읽은 응답은 그 단계에 연결하고 후속 응답으로 대체된 단계에서는 교체 사실을 보여 준다. |
| TLOG-05 Gmail 조회 | 동의 → 준비 → 요청 → 완료 이력을 보여 준다. 조회 결과는 원래 대화의 Google 연결 권한으로 연다. 연결을 교체하면 철회 상태가 따른다. |
| TLOG-06 목록 탐색 | 오늘·어제 그룹과 예약 5개 중 첫 3개의 미리보기, 모두 보기, 다음 페이지와 뒤로 이동을 확인한다. |

## 자료 조사 실행

| 시나리오 | Linux에서 확인할 결과 |
| --- | --- |
| TWORK-01 대화에서 기억 조사 | 회원이 저장한 기억을 실제 검색하고 읽는다. 업무와 대화 턴에는 같은 실행 ID가 남고 별도 모델 호출을 만들지 않는다. |
| TWORK-02 이전 텍스트 대화 | 일반 대화에 있던 질문과 답변을 검색하고 해당 항목의 근거를 연다. |
| TWORK-03 근거 철회 | 원래 기억을 잊은 뒤 같은 업무 주소를 열면 검색 당시 건수와 단계는 남고 본문은 철회된다. |
| TWORK-04 응답 유실 | 같은 요청 키로 재시도해 같은 업무 한 건을 돌려준다. 같은 키에 다른 검색 조건은 거절한다. |
| TWORK-05 결과가 없는 검색 | 결과 0건을 완료로 남기고 실제로 읽은 자료 단계는 생성하지 않는다. |

## 반복 실행과 권한

| 시나리오 | Linux에서 확인할 결과 |
| --- | --- |
| TSCHED-01 예약 등록 | 검색 범위·주기·다음 예정 시각을 저장한다. |
| TSCHED-02 일시정지와 수동 실행 | 일시정지 상태에서 지금 실행할 수 있고 재개하면 다음 회차를 새로 계산한다. |
| TSCHED-03 로그아웃 중 실행 | 브라우저를 로그아웃하고 격리한 시험 DB의 예정 시각만 당기면 실제 게이트웨이와 회원 서비스가 한 회차를 수행한다. |
| TSCHED-04 예약 해제 | 추가 회차는 중단하고 과거 완료 기록은 보존한다. |
| TSCHED-05 재시작과 동시 실행 | 놓친 주기는 최신 예정 시각 한 건으로 합쳐 두 타이머가 동시에 돌거나 회원 DB를 다시 열어도 중복되지 않는다. |
| TSCHED-06 권한·복원 | 이전 볼륨 세대의 실행은 거절한다. 설치 세션 세대가 변경되거나 복원되면 예약이 정지된다. 늦게 도착한 과거 타이머는 새 허가를 정지시키지 않는다. |
