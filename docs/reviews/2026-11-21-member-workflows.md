# Kiri 회원 업무 흐름 워크로그

**맡긴 일**은 원래 요청에서 실제 실행, 단계별 근거, 결과, 원래 대화로 이어진다. 저장된 검색 조건과 실행한 회차는 서로 다른 항목이다. 이번 개편은 운영 절체 전의 로컬 후보에서 진행했다. [회원 사용법](../member-tasks.md)

| TLOG-02 단계와 직접 주소 | 360px에서 다시 열어 특정 근거를 읽고 진행 기록으로 돌아오면 선택했던 버튼이 초점을 받는다. 1440px에서는 단계와 근거를 나란히 읽는다. 원래 대화의 해당 턴을 다시 연다. |
| TLOG-03 회원 교체 | 두 번째 회원의 목록과 예약은 비어 있고 첫 회원의 주소는 열리지 않는다. |
| TLOG-04 이전 브라우저 이력 | 기존 작업과 시각이 남지 않은 과거 상태가 유지된다. 새로 읽은 응답은 그 단계에 연결하고 후속 응답으로 대체된 단계에서는 교체 사실을 보여 준다. |
| TLOG-05 Gmail 조회 | 동의 → 준비 → 요청 → 완료 이력을 보여 준다. 조회 결과는 원래 대화의 Google 연결 권한으로 연다. 연결을 교체하면 철회 상태가 따른다. |
| TLOG-06 목록 탐색 | 오늘·어제 그룹을 접고 펼친다. 예약 5개 중 첫 3개와 모두 보기, 이전 페이지, 상세에서 목록으로 돌아온 뒤의 초점을 확인한다. |

## 자료 조사 실행

| 시나리오 | Linux에서 확인할 결과 |

| TWORK-01 대화에서 기억 조사 | 회원이 저장한 기억을 실제 검색하고 읽는다. 업무와 대화 턴에는 같은 실행 ID가 남고 별도 모델 호출을 만들지 않는다. |
| TWORK-02 이전 텍스트 대화 | 일반 대화에 있던 질문과 답변을 검색하고 해당 항목의 근거를 연다. |
| TWORK-03 근거 철회 | 원래 기억을 잊은 뒤 목록과 같은 업무 주소를 열면 검색 당시 건수와 단계는 남고 본문은 사라진다. 남은 근거가 있으면 그중 첫 발췌가 목록에 표시된다. |
| TWORK-04 응답 유실 | 같은 요청 키로 재시도해 같은 업무 한 건을 돌려준다. 같은 키에 다른 검색 조건은 거절한다. |
| TWORK-05 결과가 없는 검색 | 결과 0건을 완료로 남기고 실제로 읽은 자료 단계는 생성하지 않는다. |

## 최종 Linux 검증

Ubuntu 22.04 x86-64에서 제품 커밋 `286840b`를 빌드했다. 두 브라우저에서 같은 게이트웨이와 회원 실행 파일을 사용했다. SHA-256은 `e1ff945166442691095cc71a308def08c1bc4306ed3b02802e0fcf5e06aefc53`다. Linux의 빌드·시험 입력 1,104개와 기능 대장·검증기·Claude 평가기 3개가 이 커밋과 일치했다. [Linux 검증 자료](../../audit/runs/task-history-linux-2026-11-21.zip)

| 대상 | 결과 |
| --- | --- |
| 실제 회원 업무 | Chromium 12/12, WebKit 12/12. 기억과 이전 대화를 읽고, 로그아웃 중 예약을 실행하고, 같은 이름으로 새로 만든 예약과 해제한 예약의 회차를 각각 다시 열었다. WebKit 첫 시도에서 기억 삭제 확인 전에 이동한 시험을 고쳤다. 화면의 삭제 완료와 시험 DB 반영을 확인한 뒤 이동해 두 브라우저에서 재검증했다. |
| 실제 모델 대화 | 공식 Claude Sonnet 5.5 (`claude-sonnet-5-5`, `medium`)로 7/7. 최종 실행 파일에서 브라우저에 보인 답변과 회원 SQLite에 저장된 대화 턴을 대조했다. |
| 회원 웹·볼트 웹 | 회원 웹 777/777, 타입 검사와 빌드 통과. 볼트 웹은 앞선 Linux 실행에서 18/18 통과했다. |

| Linux 빌드·명세 | 파일시스템 용량 계산에서 대상 플랫폼의 정수 폭과 오버플로 오류를 보존했다. Kiri 관련 시험 23/23, Rustfmt, 전체 워크스페이스·모든 대상 Clippy, OpenSpec 엄격 검사 193/193, 계획·링크 검사와 웹 API 타입 대조를 통과했다. |

## 최초 통합판 검증

제품 소스 `7f085f6`을 Ubuntu 22.04 x86-64에서 Rust 1.89로 빌드했다. 브라우저가 접속한 게이트웨이와 두 회원 서비스에 사용한 실행 파일의 SHA-256은 `24ef0388eb91a4a34573b7fa6b8d96d037723181f1b53084d54100f1359ccacb`다.

독립 검토에는 Claude Sonnet 5.5 · medium에 합성 설계를 제시했다. 검토에서 제시한 피어·권한·세대 확인, 근거 철회와 남은 첫 발췌, 당시 건수, 중단 중 도래한 회차를 위 시나리오와 대조했다. 검토 대상은 설계였고 제품 소스 검증은 Linux 시험으로 수행했다.

전체 기능 대장에서 71개 기능 각각에 3~9개의 시나리오를 배정했다. 229개 중 통과 208, 부분 확인 9, 실환경 대기 9, 후속 범위 3이다. 외부 시험 계정·기기와 운영 절체가 필요한 항목은 해당 행에서 확인할 수 있다.
