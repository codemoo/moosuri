# Atticus에서 참고할 대화와 태스크 처리 방식

2026-11-24에 Atticus 2.0.1의 소스 `ec26aaa`와 무수리 회원용 Kiri 로컬판 `3ae0c87`을 대조했다. **원래 대화에서 여러 업무를 각각 맡기고, 다른 대화를 하다가 원하는 업무에만 조건을 보태고, 결과를 같은 자리에서 받는 흐름**을 우선 제안한다. [Atticus 검토 버전](https://github.com/SaarthurR/atticus-mac/tree/ec26aaa3ace49cc4140e4dffd0395c1fc57ad8a9) · [무수리 회원 업무](../member-tasks.md)

## 먼저 연결할 사용자 경험

“지난 출장 대화에서 정해진 일정을 찾아주고, 내 기억에서 준비물도 찾아줘”라고 하면 원래 메시지 아래에 **출장 일정**과 **준비물** 두 업무가 보인다. 대화 검색과 기억 검색은 이미 Kiri가 수행할 수 있다. “준비물은 전자기기만”이라고 하면 준비물의 워크로그에만 지시가 추가된다. “둘 다 어디까지 됐어?”에는 각 업무의 실제 상태가 나온다. 검색, 원문 읽기, 결과 정리처럼 한 결과를 만들기 위한 단계는 해당 업무 안에 모인다. [현재 회원 업무 범위](../../crates/moosuri-core/src/personal_browser.rs)

| 순서 | Atticus에서 확인한 처리 | 무수리에 적용할 내용 |
| --- | --- | --- |
| 1. 대화에서 업무 분리·인계 | 한 요청의 독립적인 일마다 인계 ID를 만든다. 이미 시작한 일은 수행한 도구와 결과를 먼저 저장한다. 자동 전환 기준인 15초에는 도구가 동작한 시간만 쌓이고, 쓰기 도구의 결과를 기다리는 동안에는 전환을 미룬다. [복수 업무](https://github.com/SaarthurR/atticus-mac/blob/ec26aaa3ace49cc4140e4dffd0395c1fc57ad8a9/tests/test_fix_flow.py#L143-L175) · [전환 판정](https://github.com/SaarthurR/atticus-mac/blob/ec26aaa3ace49cc4140e4dffd0395c1fc57ad8a9/atticus.py#L6487-L6537) | 원래 메시지와 독립적으로 완료될 각 태스크를 연결한다. 접수가 저장되면 대화 입력을 돌려주고 같은 요청을 다시 받아도 같은 태스크를 연다. 이미 실행 중인 업무는 기존 실행 ID와 확인된 단계를 이어 쓴다. 외부 작업의 결과가 불명확하면 기존 영수증을 먼저 조회한다. |
| 2. 후속 발화의 대상 결정 | 선택한 카드와 현재 대화가 만든 업무 ID를 다음 발화에 제공한다. 실행 중인 업무에 지시를 전달하고 끝난 업무도 같은 작업 문맥에서 이어갈 수 있다. [대상 선택](https://github.com/SaarthurR/atticus-mac/blob/ec26aaa3ace49cc4140e4dffd0395c1fc57ad8a9/atticus.py#L5290-L5315) · [실행 중 지시](https://github.com/SaarthurR/atticus-mac/blob/ec26aaa3ace49cc4140e4dffd0395c1fc57ad8a9/atticus.py#L5718-L5729) | “둘 다 어디까지 됐어?”는 조회로 처리한다. “준비물은 전자기기만”은 선택한 업무에만 기록하고 실제로 적용한 단계가 보이게 한다. “그거 멈춰”에 후보가 둘이면 그 둘을 제시한다. 현재 Kiri 일반 대화는 실행 중 후속 지시를 저장하고 사용자가 별도 메시지로 보낼 수 있으며, 브라우저 업무에는 전용 지시 경로가 있다. [텍스트 후속 지시](../../crates/moosuri-store/src/personal_text_preview/follow_ups.rs) · [브라우저 지시](../../web/src/PersonalChatComposer.tsx) |
| 3. 막힌 업무의 질문과 재개 | 판단이나 연결이 필요하면 업무에 질문과 선택지를 남긴다. 지난 질문에 달린 답은 현재 질문에 적용하지 않는다. 워커 종료 후에도 선택을 기다리는 태스크는 자리를 비우고 답이 오면 이어간다. [질문과 답 연결](https://github.com/SaarthurR/atticus-mac/blob/ec26aaa3ace49cc4140e4dffd0395c1fc57ad8a9/atticus.py#L6207-L6228) | **답변 필요** 카드에 “어느 출장인가요?”와 후보를 표시한다. 사용자는 다른 업무를 계속하고 나중에 카드나 대화에서 답한다. 서버가 회원·업무·현재 질문과 답의 연결을 확인해 한 번 재개한다. |
| 4. 완료와 산출물 전달 | 워커가 정상 종료해도 업무 결과 상태를 별도로 받는다. 도구가 보고한 생성 항목, 실제 작업 폴더의 파일, 참조 링크를 구분해 완료 카드를 구성한다. 산출물 후보에는 모델이 보고한 외부 링크도 들어갈 수 있다. [완료 판정](https://github.com/SaarthurR/atticus-mac/blob/ec26aaa3ace49cc4140e4dffd0395c1fc57ad8a9/atticus.py#L5835-L5869) · [산출물 수집](https://github.com/SaarthurR/atticus-mac/blob/ec26aaa3ace49cc4140e4dffd0395c1fc57ad8a9/atticus.py#L5429-L5473) | 기존 워크로그를 대화 안에서 열고 **결과 요약**, **만든 항목**, **읽은 근거**를 제공한다. 자료 조회는 읽은 기록으로, 파일·문서 생성은 회원 저장소나 연결 서비스의 생성 응답으로 확인한다. 사용자가 읽거나 입력하던 위치를 유지하고 완료한 회차마다 한 번 알린다. |

표준 서버에는 명시적 대화 위임, 선택을 통한 대상 확정, 정지한 업무의 조건 수정과 결과 검증이 이미 있다. Kiri에서는 이 계약과 회원별 SQLite 워크로그를 재사용하는 편이 적합하다. 짧은 답변과 기억·대화 검색은 현재 경로를 쓰고, 모델 판단이 필요한 경우에는 설치에서 지정한 Claude Sonnet 5.5 · medium을 쓴다. ## 후속 후보

- **진전 없는 반복 멈추기**. Atticus의 일반 대화 도구는 동일 행동과 실패 결과가 세 번 쌓이면 다음 시도 전에 멈춘다. 스크롤처럼 응답 문구가 같아도 화면이 바뀌면 진전으로 본다. 무수리 브라우저에서는 해당 태스크가 읽은 페이지·항목의 변화로 판단하고, 멈춘 이유와 이어갈 선택을 워크로그에 표시할 수 있다. [판정 코드](https://github.com/SaarthurR/atticus-mac/blob/ec26aaa3ace49cc4140e4dffd0395c1fc57ad8a9/atticus.py#L822-L869)
- **성공한 절차 다시 쓰기**. Atticus는 인계 전후에 실제 수행한 도구 결과를 맞춰 재사용 후보를 만든다. 무수리는 표준 서버에 검증된 개인 절차가 있으므로, Kiri의 완료 카드에서 같은 종류의 업무에 새 입력을 주는 흐름을 연결할 수 있다. 저장할 항목은 도구 종류·입력 조건·확인 기준이다. [Atticus 실행 근거](https://github.com/SaarthurR/atticus-mac/blob/ec26aaa3ace49cc4140e4dffd0395c1fc57ad8a9/atticus.py#L5476-L5519) · [무수리의 개인 절차](../learned-skills.md)

## Linux에서 실행한 검증

고정한 Atticus 소스에서 아래 24개 시험을 골라 Linux 서버의 네트워크가 차단된 컨테이너에서 실행했다. 24개 모두 통과했고 생략한 사례는 0개였다. 시험은 합성 워커와 임시 작업 저장소를 사용했다. 측정 범위는 태스크 처리 로직이다. 실제 Claude 응답 품질과 macOS 화면 조작은 이번 측정 범위 밖이다. [업무·결과 시험](https://github.com/SaarthurR/atticus-mac/blob/ec26aaa3ace49cc4140e4dffd0395c1fc57ad8a9/tests/test_agents.py) · [대화 인계 시험](https://github.com/SaarthurR/atticus-mac/blob/ec26aaa3ace49cc4140e4dffd0395c1fc57ad8a9/tests/test_fix_flow.py) · [반복 판정 시험](https://github.com/SaarthurR/atticus-mac/blob/ec26aaa3ace49cc4140e4dffd0395c1fc57ad8a9/tests/test_step_budget.py)

Kiri의 첫 통합 검증에는 ① 한 메시지에 맡긴 두 업무 중 하나만 완료되는 경우, ② 인계 응답을 잃고 같은 요청을 다시 보내는 경우, ③ 한 업무에 덧붙인 조건이 다른 업무에 섞이지 않는 경우, ④ 질문에 답하던 중 새로고침하거나 같은 답을 두 번 보내는 경우, ⑤ 모델이 문서 생성을 보고했지만 실제 문서가 없는 경우가 필요하다. 이 다섯 사례는 무수리 이식판의 수락 기준이다.
