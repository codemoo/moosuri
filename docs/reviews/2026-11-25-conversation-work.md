# 대화에서 이어가는 회원 업무 워크로그

## 복수 업무 접수와 대화 계속하기

회원 메시지, 자식 업무와 검색 조건을 한 트랜잭션에 저장한다. 접수 뒤 실제 자료 읽기는 회원 타이머가 수행한다. 독립 검토에서 찾은 두 문제를 수정했다. 브라우저가 확인을 받지 못해도 원래 조건을 보존하고, 예약 검색 하나가 실패해도 이미 처리한 독립 조사의 실행 기록은 남긴다.

| 시나리오 | 사용자 조작 또는 재현 조건 | 확인한 결과 |
| --- | --- | --- |
| H1 | 대화에서 지난 출장 일정과 기억 속 준비물을 한 문장으로 맡긴다. | 원래 메시지 하나에 업무 두 개가 생기고 출장 조건이 수업 일정을 걸러 낸다. |
| H2 | 복수 업무를 접수한 직후 같은 대화에서 별도의 인사말을 요청한다. | 대화가 답변을 받고 두 조사도 회원 타이머에서 완료된다. |
| H3 | 게이트웨이 저장 직후 응답을 끊고 대화를 새로고침한다. 같은 요청도 재전송한다. | 원래 턴·업무 ID와 조건이 유지되고 같은 ID로 본문을 바꾸면 거절된다. |
| H4 | 접수 후 회원 DB를 닫았다 열고 타이머 두 개를 동시에 호출한다. | 각 업무의 실제 읽기는 한 회차이며 다음 호출의 추가 실행은 0건이다. |
| H5 | 접수 후 회원 권한·호스트 세대를 바꾸거나 다른 볼륨 세대로 원래 업무를 조회한다. | 기존 실행 권한이 만료되고 다른 세대는 원래 업무를 열 수 없다. |
| H6 | 서버 도착 전에 복수 업무 전송을 끊고 새로고침한 뒤 ‘동일 요청 다시 확인’을 누른다. | 수동 재시도 전 접수는 0건이다. 재전송 본문·ID·견학 조건이 같고 새 업무 묶음은 하나다. |

## 후속 지시와 회차별 워크로그

상태 질문은 현재 실행 기록을 읽는다. 조건 변경과 취소는 선택된 업무와 현재 버전에 연결한다. ‘맡긴 일’에서 같은 업무를 한 줄로 열고 과거 회차의 근거와 처음 요청한 대화로 이동한다.

| 시나리오 | 사용자 조작 또는 재현 조건 | 확인한 결과 |
| --- | --- | --- |
| S1 | ‘준비물은 전자기기만’이라고 지시한다. | 준비물만 두 번째로 실행되어 2건이 1건으로 줄고 출장 일정의 회차는 그대로다. |
| S2 | ‘둘 다 어디까지 됐어?’라고 묻는다. | 화면에 두 업무의 상태가 뜨며 조회 전후 실행 수와 모델 호출 수가 같다. |
| S3 | 답을 기다리는 업무가 둘일 때 ‘그거 멈춰’라고 한 뒤 기억 검색을 선택한다. | 선택 전에는 둘 다 대기한다. 선택한 업무만 취소되고 다른 업무는 계속 답을 받을 수 있다. |
| S4 | 조건을 두 번 좁힌 뒤 ‘맡긴 일’에서 두 번째 회차와 원래 대화를 차례로 연다. | 목록에는 해당 업무 한 줄이 남는다. 각 회차의 근거와 원래 대화의 카드를 다시 연다. |

## 질문 대기와 재개

검색어가 비어 있으면 업무에 질문을 저장한다. 카드와 대화 입력창에서 답할 수 있다. 서버가 현재 질문 번호와 업무 버전을 확인하고, 답을 기다리는 동안에도 다른 업무를 실행한다.

| 시나리오 | 사용자 조작 또는 재현 조건 | 확인한 결과 |
| --- | --- | --- |
| Q1 | 검색어가 없는 일정 조사와 검색어가 있는 승차권 조사를 같이 맡긴다. | 일정 조사에는 질문 번호가 생기고 승차권 조사는 독립적으로 완료된다. |
| Q2 | 새로고침한 후 대기 카드에 ‘일정’이라고 답한다. 다른 대기 업무에는 대화 입력창으로 답한다. | 두 입력 경로 모두 해당 질문이 속한 업무를 재개하고 형제 업무 이력은 유지된다. |
| Q3 | 접수된 질문 답변을 같은 내용으로 다시 보낸다. | 서버가 기존 답을 인정하고 해당 업무의 실행 회차는 하나다. |
| Q4 | 이미 쓴 답변의 질문 번호를 바꾸거나 다른 회원 세션으로 답한다. | 오래된 질문에는 충돌을 반환하고 다른 회원은 첫 회원의 업무를 변경할 수 없다. |

## 결과·근거·보고서

보고서 번호는 완료된 회차에 귀속된다. 열 때마다 회원 권한과 원본의 현재 버전을 읽는다. 완료 알림을 상단 버튼에 모아 모바일에서도 카드를 조작하고 다른 초안을 계속 작성할 수 있게 했다.

| 시나리오 | 사용자 조작 또는 재현 조건 | 확인한 결과 |
| --- | --- | --- |
| R1 | 대화와 기억에 서로 다른 자료를 넣고 조건 변경 전후의 결과를 연다. | 카드에 실제 조회 건수와 발췌가 표시되고 첫 회차에서 읽은 두 자료도 다시 확인할 수 있다. |
| R2 | 보고서를 만든 뒤 같은 요청을 재전송하고 후속 조건을 추가한 다음 과거 회차를 연다. | 저장된 문서 한 건이 원래 회차에서 열리고 존재하지 않는 문서 주소는 404로 응답한다. |
| R3 | 보고서의 근거가 된 기억을 수정한 뒤 잊고 원래 회차의 보고서를 다시 연다. | 이전·수정 본문 모두 과거 보고서에 나타나지 않고 당시 확인한 건수와 철회 안내가 남는다. |
| R4 | 검색 두 개를 맡기고 새 대화에 초안을 쓰는 동안 완료를 기다린다. | 입력 초점과 초안이 유지되고 상단 완료 목록에 각 회차가 한 번씩 표시된다. |
| R5 | 다른 회원으로 로그인해 첫 회원의 업무 목록과 보고서 주소를 연다. | 문서 본문을 받을 수 없고 두 번째 회원의 실행 기록도 늘지 않는다. |

## 브라우저 반복 중단과 이어가기

읽은 제목·본문·선택 영역·허용된 다음 링크로 관찰을 비교한다. 진전이 없을 때는 회원에게 이유를 표시한다. 새 지시 또는 직접 조작 후 같은 업무에서 계속한다. 이 경로는 Linux 회원 런타임과 시험용 페이지·모델 소켓으로 검증했다.

| 시나리오 | 사용자 조작 또는 재현 조건 | 확인한 결과 |
| --- | --- | --- |
| B1 | 브라우저 업무에서 같은 관찰을 반복한다. | 다음 추론을 요청하기 전에 원래 업무에 반복 중단 이유가 남는다. |
| B2 | 제목이 같은 페이지의 본문 또는 읽을 수 있는 문서 선택지를 바꾼다. | 내용이나 허용된 선택지가 달라지면 작업을 계속할 수 있다. |
| B3 | 멈춘 업무에 새 지시를 주고 페이지를 이어 읽은 뒤 같은 진행 요청을 재전송한다. | 원래 업무에서 한 번 진행한다. 직접 조작 후 달라진 선택 내용도 반영된다. |
| B4 | 서로 다른 브라우저 업무에서 똑같은 내용을 관찰한다. | 업무별로 반복 여부를 판정하고 다른 업무의 이전 관찰은 합산하지 않는다. |

## 검증된 검색 절차 재사용

읽을 수 있는 근거가 남은 완료 카드에서 새 검색어를 받는다. 원래 자료 범위를 사용해 새 업무를 접수하고 그 업무가 직접 자료를 읽는다.

| 시나리오 | 사용자 조작 또는 재현 조건 | 확인한 결과 |
| --- | --- | --- |
| P1 | 완료된 준비물 카드에서 ‘새 검색어로 다시’를 누르고 ‘기차표’를 입력한다. | 같은 기억 범위에서 별도 업무와 새 회차가 생긴다. |
| P2 | 새 기차표 업무를 열어 원래 준비물 조사 결과와 비교한다. | 새 기억의 좌석 정보가 표시되고 이전 충전기 발췌가 따라오지 않는다. |
| P3 | 답변 대기·취소 상태 또는 근거가 철회된 업무의 절차를 다시 실행하려 한다. | 새 검색이 접수되지 않고 근거 철회 후 카드의 재사용 버튼도 사라진다. |
| P4 | 같은 재사용 요청을 다시 보낸다. | 같은 새 업무를 반환한다. 같은 키로 검색어를 바꿔 보내면 충돌한다. |
