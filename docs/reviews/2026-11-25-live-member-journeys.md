# Linux 회원 화면 실사용 시나리오

2026년 11월 25일 Linux Chromium의 일반 회원 화면에서 25개 사례를 통과했다. 처음 정한 5개 흐름 22개와, 날짜 정정 중 발견한 오류에서 파생한 3개다. 회원이 보낸 메시지는 44건이었다. 공식 Claude CLI에서 Sonnet 5.5(`medium`)의 모델명과 사용량을 확인한 호출은 요청 해석 41회, 대화 답변 34회였다. 긴 대화를 채우는 여덟 차례의 후속 질문에도 같은 모델이 답했다. [실행 집계](../../audit/runs/kiri-live-member-journeys-2026-11-25.json)

각 묶음은 새 회원 볼륨과 HTTPS 게이트웨이에서 시작했다. 입력·자료는 합성이고 모든 쓰기는 회원 화면에서 했다. 답변은 화면과 회원 SQLite 원문을, 추천은 모델로 간 기억과 사용한 버전을, 맡긴 일은 원본·검색 회차·보고서가 가리키는 ID를 대조했다. 한 Linux UID로 두 회원을 번갈아 로그인할 때는 활성 브로커 바인딩을 바꿨다. 두 회원은 같은 설치 레지스트리와 게이트웨이를 사용하고 각자의 대화·기억·모델 원장을 유지했다. [재현 방법](../../deployment/kiri/linux-vm-smoke/README.md#chat-work)

## 실행에서 고친 문제

- “마시는 게 좋아”라는 말을 평소 선호로 저장하지 못했다. 선택을 직접 밝히는 표현을 인식하고, 물음표를 생략한 질문·조건부 조언을 저장하지 않도록 했다. 같은 커피 발화로 저장·임시 예외·정정까지 재검증했다.
- “수요일로 바뀌었어요. 최종 요일과 시간을 다시 알려 주세요”가 반복 감시를 등록했다. 바뀌었다는 설명과 앞으로 바뀔 때 알림을 달라는 지시를 구분했다. 동일 발화로 날짜 정정을 확인했고, 실제 감시 요청도 등록·중지했다.
- 앞선 열차 요금에서 한 명을 뺀 합계를 물으면 요청 해석기가 추가 설명을 요구했다. 일반 대화의 이전 발화를 답변 단계가 읽는다는 점을 해석 지침에 명시했다. 인원과 단가를 다시 입력하지 않고 계산을 마쳤다.

검증기에서도 같은 OS 사용자로 모의 설치에 접속할 때 생긴 브로커 연결 충돌과, 내용이 이미 채워진 기억 편집기의 필드 선택을 바로잡았다. 처음 막힌 실행과 디버깅 재시도는 위 통과 수에서 제외했다. Linux에서 관련 Rust 서버 시험 19개와 웹 감시·브리핑 시험 15개, TypeScript 검사와 웹·Rust 빌드를 통과했다.

이 기록은 격리된 Linux 개편판의 결과다. 운영 회원 데이터, 실계정 메일 배달과 실기기 알림은 이번 실행 범위 밖이다. 기존 선호 회상 9개와 업무 시나리오 73개의 실행 기록은 각각 보관한다. [기존 선호 회상](../../openspec/changes/recall-member-preferences/tasks.md) · [기존 업무 시나리오](2026-11-25-member-work-from-chat.md)
