# Claude 구독 해제·재연결 검증

공개 b9596bb0의 관리자 구독 연결에 명시적 **구독 연결 해제**와 중단 복구를
추가하는 단위다. 기존 Rust 게이트웨이·설정 기록·호스트 정리와 React 화면을
재사용한다. 운영 dee84754는 유지한다. 전체 61개 주요 여정 중 M05/M06의
LC01·LC02·LC08을 보강하며 실제 인증·추론 성공으로 집계하지 않는다.

## 구현 경계

새 해제 요청 ID와 지울 연결 revision을 별도로 보관한다. 현재 관리자 세션과
전체 소유자 정보를 잠금 안에서 확인하고, 정확한 설정의 해시를 먼저 저장한 뒤
설정 파일을 내리고 디렉터리를 동기화한다. 이후 같은 연결의 루트 기록을 정리
단계로 전환한다. 서비스 종료·로그인 환경 제거는 레지스트리 잠금 밖에서 수행한다.
루트 정리 확인과 종료 기록 저장이 끝난 뒤에만 화면에 해제 완료를 표시한다.
해제한 연결의 공용 모델 목록도 내린다. 과거 revision 기록은 유지해 늦은
브로커 등록이 해제된 연결을 되살리지 못하게 한다. 새 연결의 목록은 보존한다.

읽을 수 없거나 변경된 설정, 정확한 해제 의도가 없는 파일 부재는 정리를 보류한다.
늦은 상태 저장은 먼저 저장한 설정 해시를 지우지 못한다. 서버 재시작 뒤 같은
소유자의 새 로그인 세션에서 기존 정리를 재개한다. 기존 v2 연결 기록을 계속
읽으며 해제 기록만 명시적 mode·target을 가진 v3으로 저장한다.

관리 화면에서 완료를 확인하면 API 키·내 구독 선택으로 돌아간다. 재연결은 같은
소유자의 준비 환경을 재사용하고 새로운 로그인 환경을 만든다. 다른 회원 등록,
세대 변경에 따른 전체 자원 회수, API로 즉시 교체하는 기능은 후속 범위다.

## 현재 검증 상태

호스트 16개, 모델 설정 47개, UI 26개와 모델 목록 회수 저장소 여정 1개가
통과했다. typecheck·web build·native build도 통과했다. 두 테스트 코드의
소유권/clone 컴파일 오류를 수정한 뒤 해당 검사를 실행했다. 제품의 실제 첫 실패는
설정 손상 시 작업 조회가 503을 반환해 복구 화면이 사라지는 문제였다. 독립 검토와
설치 재현 뒤 API·화면을 고쳤으며, 같은 실패 상태에서 D04–D06을 재개해 통과했다.

후속 설치 확인은 연결 파일을 지운 뒤에도 공용 모델 목록이 남는 문제를 발견했다.
정확한 목록 회수와 늦은 재등록 차단을 추가하고 별도 저장소 여정을 통과했다.
독립 공식 Claude Sonnet 5.5/medium 검토는 초기 24턴, 복구 수정 21턴, 목록 회수
8턴이며 지적한 결함은 모두 닫혔다. 검토자는 실행을 하지 않았고 Linux 실행 결과는
메인에서 별도로 확인했다.

최종 native SHA는 `4aaa322523bd01e3956807184f335cf5fb9f21f49a15538c0c6498e81f8eb5f6`이다.
이 실행본으로 실제 모바일 Chromium DU01–DU03이 통과했고 화면을 확인했다.
목록 회수 경계가 변경되어 같은 실행본의 D01–D06도 다시 실행했고 모두 통과했다.

초기 D01–D03은 2ba26531, 복구 D04–D06은 e7e2e113의 증거이며 이전 실패를
별도 결과 파일로 보존했다. 준비·Active 합성 지정·실제 인증의 범위를 섞지 않는다.

실제 구독 인증·추론, 같은 Kiri의 인증 화면, 두 실회원, 최종 소스의 빈 설치·재부팅과
