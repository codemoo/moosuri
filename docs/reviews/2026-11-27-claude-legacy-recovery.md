# 기존 Claude 연결 교체와 해제 복구

빈 설치의 모델 설정뿐 아니라 기존 설치를 갱신하는 관리자도 화면에서
다음 연결을 준비할 수 있어야 한다. 수동 등록한 외부 워커의 설정에는
무수리가 만든 관리 기록이 없을 수 있다. 이 경우 해제를 먼저 요구하면
설정을 지운 뒤 끝나지 않는 정리 작업에 갇힐 수 있었다.

수정본은 외부 연결을 새 로그인이 검증된 뒤 같은 리비전 조건으로 교체한다.
기존 외부 로그인은 삭제하지 않는다. 관리형 연결은 정확한 회원·요청·워커
기록의 잠금을 얻은 뒤에만 해제 의도를 저장하고 설정을 내린다. 의도 저장
전에 확정적으로 거절된 작업은 기존 연결을 보존한 실패로 끝난다. 의도가
이미 저장됐다면 응답을 잃었어도 정리 의무를 유지한다.

## 사용자 여정

실제 Linux Chromium → HTTPS → 설치된 게이트웨이로 다음 여정을 실행한다.
설정과 중단 기록만 합성 자료로 준비하며 API 응답을 모킹하지 않는다.
기존 공개 `2608a12e` 설치 위에 수정 게이트웨이를 적용하는 진단 검증이다.
이것은 수정 소스의 빈 설치나 실제 Claude 인증을 대신하지 않는다.

| ID | 조건과 조작 | 완료 조건 | 결과 |
| --- | --- | --- | --- |
| LR01 | 관리 기록 없는 외부 구독으로 관리자 화면 열기 | 기존 설정을 보존하며 교체 폼 표시; 해제 강제 없음 | Linux 설치 화면 통과 |
| LR02 | 모바일에서 새로고침하고 다른 회원으로 같은 화면 열기 | 관리자만 교체 가능; 설정 불변, 화면 넘침 없음 | Linux 설치 화면 통과 |
| LR03 | 화면을 연 뒤 다른 관리자가 연결을 교체; 오래된 폼 제출 | 409로 거부하고 현재 연결 조회 후 복구; 로그인 시작 없음 | Linux 설치 화면 통과 |
| LR04 | 관리형 경로지만 대상 관리 기록이 없는 연결 해제 | 412와 원인 안내; 설정·로그인·작업 기록 불변 | Linux 설치 화면 통과 |
| LR05 | 해제 의도 저장 전에 중단; 재시작 후 정리 재시도 | 설정 보존, 실패 종료, 다음 설정 차단 해제 | Linux 설치 화면 통과 |
| LR06 | 해제 의도 저장 뒤 중단; 관리 기록 누락 상태에서 재개 | 정리 대기와 저장된 의도 유지; 재진입으로 소실되지 않음 | Linux 설치 화면 통과 |

실제 인증 후 교체 완료와 연결된 워커 재부팅은 M05/M06의 열린 조건으로
유지한다. 시작부터 취소까지의 화면 검증은 기존 Kiri 인증 여정도 참고한다.

## 소스 검증과 독립 검토

- Linux 게이트웨이 검증 56개와 관리 기록 검증 18개 통과.
- 화면 검증 45개, 타입 검사·웹 빌드와 Linux 네이티브 빌드 통과.
- 응답 유실 회귀 검증은 수정 전 실패했다. 최종 실패 기록을 저장하지 못했을
  때 이전 메모리 값으로 디스크 의도를 덮는 경로를 기존 병합 저장으로 고쳤다.
- 공식 Claude Sonnet 5.5 / medium의 독립 검토가 같은 결함을 지적했고,
  수정 후 한정 재검토에서 남은 중대 결함을 찾지 못했다. 검토는 정적 분석이다.
- 첫 재개 검증은 오래된 Linux 소스 경로를 선택해 실패했고 중단했다.
  최종 실행은 후보 소스 2,684개 파일의 해시를 대조한 경로를 사용했다.
  웹 빌드 중 Rust 자산 참조가 바뀐 실행도 실패로 남기고 순차 빌드로 수정했다.

진단 실행본 SHA-256:
`f0e28c363672a51620e2a86cd1783aac81e68b7ced9efbae518f3cf58b75ff0a`.
운영은 `dee84754`이며 이 기록만으로 운영 전환을 완료 처리하지 않는다.

## 실제 설치 결과와 제한

LR01–LR04는 두 번째 실행에서, LR05–LR06는 그 실패 기록의 해시를 참조하는
재개 실행에서 통과했다. 첫 실행은 합성 설정을 넣은 직후 아직 갱신되지 않은
모델 목록을 읽어 실패했다. 두 번째 실행의 LR05는 시험용 게이트웨이 재시작
직후 502 화면을 열어 실패했다. 실제 설정 리비전의 목록 반영과 HTTPS 응답을
기다리도록 시험 준비를 고쳤으며 제품 동작을 통과시키기 위한 API 모킹은 없다.
이미 통과한 LR01–LR04는 반복하지 않았다. LR06은 전체 정리 재시도 시간보다
오래 관찰한 뒤 의도와 차단 상태를 확인했다. 마지막에 합성 설정을 제거하고
원래 종료된 작업 기록을 복구했다. 실패 기록과 화면은 보존했다.

첫 네 여정의 결과는 실행 당시의 오버레이 기록에 연결되며, 각 결과 행에
별도 실행 파일 해시를 저장하지는 않았다. 재개 실행은 실제 프로세스의 해시를
다시 기록했고 위 진단 실행본과 같았다. 이것을 독립적인 전체 설치 증명이나
실제 계정 인증 결과로 확대하지 않는다.
