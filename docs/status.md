운영 Linux는 공개 소스 **e5038af8 / Kiri 0.2.2**의 전체 묶음으로 전환했다.
이전에 나누어 반영했던 새 창 처리·고정 오류 진단·인증 자원 한도·Google 설정 UI를
게이트웨이·회원·볼트·일반/인증 브라우저에 함께 반영했다. 기존 Ubuntu22와 커널,
회원·볼륨·암호화 볼트·키·모델 설정·Google 권한·서비스 격리 정책을 보존했다.
기존 Kiri 로그인과 Google 연결이 유지됐고 실제 받은편지함5건 조회·단일 저장,
다른 회원을 주장한 요청401, 새로고침 후3개 조회 기록과 자동 재조회0회를 확인했다.
[설치·운영 전환·실계정 결과](reviews/2026-11-27-current-source-acceptance.md)
추가로 실제 조회 응답을 유실시킨 뒤 GWS 외부 통신을 잠시 중단해도 같은 요청이
저장된 결과를 그대로 반환하는 것을 확인했다. 중복 저장은 없었고 통신 서비스는
복구했다. 새로고침은 자동 조회 없이 네 번째 기록을 표시하고 기존 초안을 유지했다.

같은 공개 e5038af8을 아무 도구나 제품 상태가 없는 별도 Ubuntu24에서 받아 실제
터미널로 설치했다. 빌드 복구나 실행 파일 교체 없이 두 회원 웹 가입, 각자의8자
암호화 볼트·브라우저, 실제 재부팅, 격리, Claude U01–U03, 첫 메일 FM01–FM03과
기존 연결 복구 LR01–LR06을 한 실행에서 통과했다. TLS와 메일·모델 응답은 합성이며,
실제 ACME·계정 인증·추론 성공은 포함하지 않는다.

운영 대화창의 “최근 받은 메일5개 확인해줘”는 여전히 모델 연결 불가422로 멈춘다.

자동 발급·복구와 두 회원의 개별 동의는 미완료다. 아래 기록은 그 과정에서 관찰한
실패와 수정 근거이며, 합성 검증이나 기존 권한 조회로 이 여정을 완료 처리하지 않는다.

때문에 실패했다. 공개 설치기의 정책에 맞춘 뒤 공식 실행 파일 다운로드와
전용 실행 환경 준비, 같은 Kiri의 실제 Claude 로그인 화면까지 도달했다.

후속 한 번의 진단에서 Google 창이 원래 Claude 창의 자식으로 열렸지만
인증 컨트롤러에 연결되지 않은 상태를 확인했다. 새 창 표시·복귀와 입력·콜백

회원·세션 격리, 중복 입력 거부, 취소·재시작·로그아웃도 통과했다. 운영 전환은
완료했지만 첫 실제 UI 재시험은 Google 버튼 뒤 다시 실패했다. 계정 입력은

계정 입력 화면과 입력 전달이 정상 작동했다. 이메일 제출 뒤 Google이 안전하지
않은 브라우저/앱이라며 거절했고, 취소 후 인증 컨테이너가 사라진 것을 확인했다.
이전의 간헐적 종료 원인은 재현되지 않아 미확인으로 유지한다. 별도의 공식 Claude

## Google 실계정 확인 — 2026-11-27

기존 운영 설치에서 회원 볼트 계정 재사용 → 새 Kiri Google 로그인 → 연결된
Z Flip5 기기 승인 → 같은 브라우저의 Gmail 동의 → 연결 완료를 확인했다.
새 무과금 프로젝트의 External·에이전트용 웹 OAuth 클라이언트를 실제 Console에서
생성하고 관리자 화면으로 설치에 등록했다. 앱은 Testing이며 해당 테스트 계정만
검증했다. 비밀값은 Linux에서 처리했다.

실제 GWS 경로로 받은편지함 5건을 조회하고 같은 대화의 저장 기록이 새로고침 후
표시되는 것을 확인했다. 다만 “최근 받은 메일 5개 확인해줘”라는 자연어 요청은
업무 해석 단계에서 실패했다. 이후 API 조회 성공으로 이 문제를 완료 처리하지
않는다. 응답은 HTTP 422 `personal_text_model_unavailable`이며, 설치 설정이
가리키는 Claude 워커 소켓과 실행 서비스가 없다. 대화 해석 계약에도 받은편지함

## 회원 UI 개편과 검증 범위

회원은 채팅에 “지난 출장 때 몇 시에 출발했는지랑 챙길 것, 한 장으로 정리해 줘”라고 보낼 수 있다. 개편판은 대화와 기억을 따로 조회하고, 같은 채팅에 출처와 저장한 보고서를 보여준다. 날짜가 다른 동명 출장이면 날짜를 묻고, 한 일의 조건만 바꾸면 그 일만 다시 실행한다. **맡긴 일**에서 원래 요청, 각 회차와 결과를 다시 연다.
