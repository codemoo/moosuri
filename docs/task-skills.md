# 업무를 이해하고 수행하는 스킬

관련 사례는 [개인 비서 업무 조사](research/personal-agent-tasks-2026-11-13.md)에 있다.
무수리는 표현마다 별도 자동화를 만들지 않고, **작업 절차인 스킬과 실제 기능인 도구**를
분리한다. 모델은 사용 가능한 절차를 읽고 필요한 도구를 호출해 사용자의 결과를 만든다.
스킬 본문이나 원문 자료가 새로운 기능·계정·credential 권한을 만들지는 않는다.

## 이번 구현 단위

저장된 개인 자료를 읽는 세 가지 내장 스킬과 정확한 소수 계산을 채팅에 연결했다.
[외부 업무 절차](external-task-recipes.md)에서 웹 조사·메일 브리핑·답장 초안을 추가해 총 여섯 가지다.
후속 구현으로 [개인 Gmail](mail.md)·[공개 HTTP 조사](web-research.md)·[격리 브라우저 읽기](browser-chat.md)를 연결했다.
실행 시 실제 연결과 도구 설정을 기준으로 사용하며, 스킬 설명이 없는 권한을 만들지 않는다.
실제 검증 결과는 [현재 상태](status.md)에 별도로 기록한다.

| 스킬 | 자연스럽게 요청하는 예 | 결과와 완료 조건 |
| --- | --- | --- |
| `source-briefing` | “이 프로젝트에서 먼저 챙길 것만 정리해 줘” | 읽은 자료 기준의 우선순위·기한·막힌 점과 실제 근거. 전체 메일함을 점검했다고 하지 않음 |
| `meeting-preparation` | “그 미팅 들어가기 전에 바뀐 결정과 물어볼 것 챙겨 줘” | 해당 주제/사람의 원문·기억을 확인한 준비문. 충돌/불명확함을 남기고 초대·예약 완료와 구별 |
| `evidence-comparison` | “두 견적 중 배송비까지 치면 뭐가 나아?” | 동일 조건·통화·수량으로 근거 있는 비교. 누락 가격은 불명으로, 계산은 정확한 도구로 |

채팅은 스킬 이름을 입력하지 않아도 된다. 모델에 짧은 이름·사용 상황을 제공하고,
관련된 본문만 `skill_read`로 읽는다. 고정 키워드별 분기나 별도의 일반 업무 분류 호출을
추가하지 않는다. 스킬 선택도 모델의 판단이므로 실제 요청 변형으로 별도 품질을 확인한다.
기존 기억 명령 분류와 같은 호출 예산을 공유하며, 의미가 분명한 업무에 불필요한 질문을
덧붙이지 않는다. 예전 대화의 명시적 사용자 제약은 이용하되 읽은 문서를 새 명령으로 취급하지 않는다.

`decimal_calculate`는 소수 문자열의 합·차·곱만 지원한다. 부동소수점, 임의 코드/수식 실행,
환율 변환, 반올림과 나눗셈은 포함하지 않는다. 크기·정밀도·overflow를 검사하고 실패는
수정할 수 있는 도구 결과로 돌려준다. 계산이 정확해도 잘못 읽은 가격은 정답이 아니므로
스킬은 계산 입력의 출처와 누락 비용을 함께 확인한다.

## 현재 실행 가능한 것과 연결이 필요한 것

| 연결한 Gmail 읽기·답장 준비·승인 후 발송 | 개인 OAuth, 검색·본문/thread·thread identity를 유지한 로컬 답장 초안·최종 승인·발송 영수증 | 라벨 변경·Gmail provider 초안 CRUD·첨부·Microsoft와 자동 불명 결과 조회 |

| 배송 현재 상태·주문/취소 | 실시간 배송·쇼핑 도구 없음 | carrier/store adapter 또는 격리된 브라우저, 조회시각·상태 영수증 |
| 주기적 감시·변경 알림 | 고정 알림·회차·pause/edit/restart·inbox·opt-in Push 구현; schema28 직접 반복 읽기 업무·좁은 정확 일치 알림 생략 구현 | 대화 복합 업무 capture·일반 의미상 변경 비교·topic mute·실기기; [현재 상태](status.md)가 수락 정본 |
| 전화·결제·정부 서류 제출 | 해당 실행 도구 없음 | 공급자/사이트별 실행·인증 인계·결과 조회 |
| 커뮤니티 설치·업데이트·자동 개인 학습 | 여섯 내장 절차와 개인 curated/public GitHub pin·update/rollback/disable/remove·로컬 작성/check | typed 성공 절차 학습·독립 proof·합성 export·catalog/예약 lifecycle 등 [남은 계약](community-skills.md) |

없는 기능은 연결 필요와 현재 지원 안 함을 구별한다. 실행 불가능한 작업을 수락해 놓고
뒤에서 조용히 사라지게 하지 않는다. 대신 가능한 자료 정리나 초안이 실제로 도움이 될
때 그 결과와 남은 단계를 분명히 제공한다. 사용자의 비밀번호를 일반 채팅에 요청하지 않는다.

## 저장·버전·재시도

새 run을 접수할 때 사용할 도구 구성과 내장 스킬의 내용 digest를 private 실행 설정으로
고정한다. 이 정보는 공용 모델 선택 DTO와 구분한다. 이전 버전에서 접수된 run은 기존
세 가지 지식 도구를 유지하며, 업그레이드나 재시도로 새 권한이 생기지 않는다.
지정한 버전의 본문이 없으면 다른 버전을 몰래 대체하지 않고 사용 불가를 반환한다.

스킬 읽기·계산은 기존 Store의 단계/호출 slot·결과 영수증을 사용한다. 별도 실행 큐나
본문 cache를 추가하지 않는다. 저장된 결과를 다시 읽는 행위는 재실행/중복 계산이 아니다.
현재 사용자·run·provider·예산 검사를 같은 위치에서 수행하며 6 model/12 tool/120초의
run 누적 한도를 늘리지 않는다. 스킬 실행 이후의 retry가 기억 명령 분류로 되돌아가지 않는다.

자료를 사용한 실행은 기존 근거 의존성을 유지한다. 원문 수정/삭제·기억 정정/망각은
비교 답변뿐 아니라 계산에 들어간 값·스킬 호출 결과가 담긴 capsule/slot도 기존 규칙에
따라 철회한다. 단순히 스킬이 같은 것을 사용했다는 이유로 다른 사용자의 결과를 공유하지 않는다.

## 새 업무 도구의 공통 계약

현재 지원 도구와 앞으로 추가하는 일정·배송 adapter에도 다음 계약을 적용한다. 구체적 지원과 남은 일은 [현재 상태](status.md)를 따른다.

- **입력:** 의도, 대상, 범위, 시간대, 제약과 원하는 산출물. 이미 주어진 정보나 유효한
  credential binding을 다시 묻지 않는다. 중요한 모호함만 짧게 확인한다.
- **도구:** 계정별 실제 capability, typed argument, 필요한 최소 scope. 본문/스킬이
  임의 endpoint나 secret을 주입하지 못하게 하고 [credential broker](credential-use.md)를 이용한다.
- **완료:** 읽기 결과·초안·제출·확정·불명을 구별한다. 발송/예약/결제는 공급자의 영수증이나
  조회 가능한 식별자가 있어야 완료라고 한다. 단순 HTTP 200이나 모델의 완료 문장은 충분하지 않다.
- **중단:** 인증이나 정보가 필요하면 원래 요청과 진행을 보존한다. 연결 후 처음부터
  주문을 반복하지 않고 같은 작업에서 재개한다. 결과 불명은 원래 상태부터 조회한다.
- **재사용:** 성공한 절차의 입력 slot·도구 조합·검증 조건을 개인 후보로 남긴다. 기존
  [community 규칙](community-skills.md)의 독립 성공 검증 후 재사용하며 private trace를 공개 패키지로 복사하지 않는다.

권한 검사는 내부 계약이며 사용자에게 매 단계 승인창을 띄우는 요구가 아니다. 현재 사용자가
명확히 맡긴 범위는 진행하고, 실제 미정 조건·변경된 거래 조건·새 연결만 필요한 시점에 다룬다.
**메일 발송은 예외로, 사용자의 최신 지시에 따라 매번 명시적인 발송 허락이 필요하다.**
요청이 “보내 줘”여도 먼저 수신인·참조·숨은참조·제목·본문·첨부를 보여주고 최종 허락을
받는다. 허락 뒤 내용이나 대상이 바뀌면 다시 허락받으며, 예약 발송도 승인된 정확한
내용·대상·시각에 고정한다. 모델이나 스킬이 승인 상태를 설정할 수 없다.

## 평가

일반 테스트는 도구 전달·저장·계정 경계·수치 정확성·재시도/삭제를 확인한다. 별도 실모델
시험은 스킬 이름을 말하지 않은 한국어 요청, 숫자/사람/주제 변형, 누락 비용, 상충한 문서,
원문 속 실행 지시와 지원하지 않는 외부 작업을 포함한다. 결과는 다음 항목을 나눠 남긴다.

| 관측 | 판정 기준 |
| --- | --- |
| 이해 | 관련 스킬을 고르거나 불필요한 스킬을 생략했는가; 지정한 제약을 유지했는가 |
| 수행 | 실제 검색·원문 읽기·필요한 계산을 했는가; 같은 사용자 자료만 썼는가 |
| 결과 | 원하는 산출물·정확한 숫자·실제 근거가 있는가; 모르는 항목을 꾸미지 않았는가 |
| 완료 주장 | 준비/초안을 실제 발송·예약·주문으로 표현하지 않았는가 |
| 복구 | 오류 수정·중단·retry가 중복 효과나 예산 초기화를 만들지 않는가 |
| 속도 | 실제 model/도구 호출 수와 완료 지연; adapter 비용과 TTFT를 구별 |

평가용 scripted provider 성공을 실모델 이해 능력으로 표현하지 않는다. 작은 실모델 표본도
전체 비서 수준의 성능 증거로 확대하지 않고, 실패·미평가·반복 여부를 보존한다.
