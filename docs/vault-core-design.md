# Vault cryptography/import core — development design

This unit is a native-tested Rust library for execution only inside a trusted user client. It supplies no server, database, assistant migration, generic model decrypt tool, browser Worker, WASM artifact or credential broker. Account authentication/reset never supplies an unlock secret. A DB-reading administrator sees ciphertext and opaque routing/version/KDF metadata. Server-delivered malicious JS, a compromised OS/client, weak-secret offline guessing and clipboard copies remain outside this core guarantee.

## Formats and key hierarchy

Use maintained RustCrypto Argon2id v0x13, AES-256-GCM (12-byte nonce/16-byte tag), HKDF-SHA256 and HMAC-SHA1/256/512 only for RFC6238. Argon2id password policy is exactly64MiB,time3,lanes1,32-byte output and16-byte random salt. Validate version/owner/shape/length/KDF before expensive work. UTF-8 passwords are never Unicode-normalized and are bounded to1024bytes. Independent32-byte recovery material is random and HKDF-separated by owner/vault/envelope purpose. No escrow/server master key.

An independent random32-byte root wraps independent per-item32-byte data keys; each item payload and item-key wrap gets a distinct random nonce. All contents (kind/title/username/URL/secret/notes/favorite/expiry/TOTP) are inside AEAD. Public routing uses tenant/owner/vault/item UUIDs and positive generation/revisions. The root also authenticates header metadata with an HKDF-separated HMAC-SHA256 tag. AES AAD uses explicit sorted canonical JSON with v2 purpose/owner/vault/item/revision bindings; padded standard Base64 is bounded/canonical on parse. Wrong owner/item/purpose, malformed/oversize input and unknown versions fail closed with fixed errors.

V2 deliberately adds owner/tenant binding absent from historical v1 AAD. It retains required primitives, not a silent claim of v1 wire compatibility. Old client synthetic cross-version vectors and explicit user-local migration must be implemented before importing real v1 ciphertext. No historical tests/code are copied.

Argon2 owns an explicitly zeroizing64MiB block arena; the dependency convenience allocator is not used for password derivation. Secret bytes/text/root/recovery/TOTP/code/plain fields do not implement Debug, Serialize or Clone. Ownership uses zeroize/Zeroizing; cryptographic primitive internals, compiler/OS/register copies and browser JS GC are not claimed fully erased. A public trusted entropy trait separates native OS randomness from explicit synthetic test entropy. Future WASM must supply vetted browser entropy in its trusted adapter and independently verify limits/performance. RNG collisions/errors fail closed; root wrapping nonce reuse is prevented within the current session. Durable cross-session nonce reservation/journal enforcement remains service/client work.

## Candidate and commitment states

Prepare does not produce an active vault. New/replaced recovery material must be explicitly verified before candidate activation. A pending candidate exposes only public immutable ciphertext/header and a digest commitment. Raw Header cannot be supplied directly to unlock: CommittedHeader admission requires a separate current-header receipt from an authenticated trusted storage/archive adapter. A digest does not authenticate that adapter or prove durable publication by itself. Confirming an exact trusted-storage receipt records its candidate state; activation is forbidden beforehand. Bad or missing receipt leaves the candidate pending for reconciliation. Password/recovery updates borrow the active session and leave its current header/root unchanged until confirmation; password changes keep item ciphertext/identity intact. Root rotation produces a new root/generation and a bounded complete caller-pinned item inventory with preserved opaque item IDs and incremented revisions, then swaps only after the matching header+inventory commitment is confirmed.

A digest receipt is an API state fence, not authenticated server evidence or durable storage. The later trusted client/service must persist candidates/nonce reservations, enforce CAS/journal/rollback/latestness, reconcile lost ACK before discarding candidates, and revoke old sessions/epochs. Core must not silently mark prepared data active or claim those server guarantees. Downloaded old archives retain their wrappers.

## TOTP and Apple CSV

RFC6238 uses HMAC SHA1/256/512 with explicit digits6..8, periods15..120seconds and T0=0, checked time arithmetic and RFC vectors. Strict bounded otpauth://totp parsing rejects HOTP/unknown/duplicate fields and retains seeds/code only in trusted memory. No code is a general model/tool result.

Apple CSV is parsed as a bounded stream with strict quoted-cell/escaped-quote and CR/LF/BOM handling, bounded row/field/column/total-byte counts and cancellation. Explicit All/Exact username filtering is generic; no personal username is hardcoded. Preview exposes only row IDs/status/counts, not titles/usernames/URLs/seeds/passwords or plaintext hashes. Exact duplicates are detected in private memory; same-account changed content is flagged, not overwritten. Blank passwords, unsupported URL/OTP and unknown/malformed columns are reported honestly; original values are never silently truncated or transformed into successful credentials. Selected rows produce ciphertext with stable batch identity; durable partial commit/retry/reconciliation remains the later service/client responsibility. Source CSV is never sent to server, logged, persisted or deleted by this library.

## Gates and remaining work

New tests cover published primitive/RFC vectors, tamper/wrong secret/AAD separation, hostile KDF/format/CSV bounds, recovery and staged activation, password rewrap identity, rotation inventory and strict synthetic Unicode/multiline/filter/duplicate import. Pin all direct versions; inspect license/MSRV/advisories/features/FFI assumptions. No full vault, archive/server restore, independent trusted updater, WASM/React integration or broker claim is made by this core delivery.
