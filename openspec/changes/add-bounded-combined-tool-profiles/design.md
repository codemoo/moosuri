# Design

The shared protocol validator accepts at most48 definitions, covering the current
maximum40 with bounded headroom. Normal Store admission enables conversation recall,
all bundled skills, and (when compiled) terminal credential and native-mail vocabulary.
Usable private recipes add one executor regardless of recipe count. Native mail
admission supplies its typed scope even when binding choices are empty; actual
execution still resolves the owner's separate grant. Shared and personal foreground
chat use the same admitted composition.

All dialects use the validator, including the fixed personal `moosuri` namespace.
No definition is removed. Retain64KiB aggregate schemas/descriptions,16KiB per-schema
validation, depth8, closed schemas, name/capability rejection,12 per-round calls,
16KiB arguments/results,256KiB private checkpoints,512KiB requests, and the existing
six-dispatch cumulative fence. Owner pins, proof admission, credential handling,
mutation grants, model/effort and final human mail approval do not change.

Tests accept48/reject49 in every encoder and retain aggregate-size/unknown-call
rejection. Production builders compose all32 default or40 broker-enabled definitions,
including recall, bundled public-page and usable private-recipe metadata. Every
supported encoder validates that composition with default text capabilities. Owned
loopback plan/shared-compatible providers observe all exact definitions, strict
schemas and pinned connections on both sides of a two-round decimal continuation.
This is transport coverage, not a full Store admission or external execution claim.
