# Design

The browser chooses a real MediaRecorder MIME it supports, previews the actual resulting Blob, then decodes only bounded locally recorded input and resamples it through Web Audio. A Worker packs mono16000Hz signed16-bit little-endian PCM into a closed44-byte WAV envelope. Failure to record/decode/normalize is an explicit unsupported/failure state. A client stopwatch or compressed header is never the server audio-duration oracle. Browser decoding is not a hostile-file memory sandbox.

Rust validates all exact RIFF/PCM/data lengths before creating a durable dispatch commitment. Installation OpenAI API credentials are used only at the fixed Audio API origin with DNS pinning/no redirects/proxies/retries. Current model transport's reviewed public-address predicate is shared without changing existing model behavior. The transcript never goes through an agent tool. The separate configurable/probed transcription model is initially gpt-4o-mini-transcribe; no plan token or personal subscription path is accepted.

The administrator provides a <=15s audio clip of a fixed public sentence. The server checks recognizable words after an actual response and never supplies expected words in the provider prompt. Synthetic loopback tests use generated nonspeech PCM and prove HTTP/configuration/state behavior only, not recognition quality.

Temporary jobs pin account/tenant/session digest/auth epoch, UUID/input digest, provider revision/model and nonce. A prior attempt never causes another automatic dispatch, including a lost ACK or processing restart. Its unknown result conservatively retains its duration reservation. The minimum one-second reservation bounds daily job growth as well as usage. At most4096 compact receipts/account remain as permanent UUID tombstones; no old UUID becomes a new bill after a retention cutoff. Transcript/audio bodies are excluded from those tombstones. Current implementation bounds are120s/audio;1 account and2 global processing jobs;600s/account/UTCday and3600s/installation/UTCday. The job expires120s from admission; transcript max24KiB; provider response64KiB/60s. Raw audio is memory-only. SQLite temporary transcripts are erased on delete/expiry/invalidation/restart/restore; expired jobs are swept on access/admission and while a job runs, rather than promising exact-time physical page erasure. An encrypted backup can contain temporary text already present in its source database; restore clears it before enrollment. Browser storage/caches contain no audio or unpublished transcript. Inserted literal text may use existing exact-session tab draft recovery.

The account RequestScope synchronously disposes microphone/preparation owners before React unmount. An irreversible generation fences late microphone permission, normalization, HTTP and polling results. Changing threads interrupts recording but preserves its original slot; new-thread creation explicitly migrates that slot. Transcript insertion checks the latest target draft and8192-byte chat bound, appends once, and does not submit. There is no added tool authority until the user explicitly sends their edited message.

This worker's schema33 migration/restore registration intentionally has an isolated schema32 gap. Root owns combined migration32→33 and its full native/Linux/independent storage/auth review. Do not archive this change from isolated tests alone.

## R3 independent-review repairs

Audio authority has a permanent monotonically increasing generation, independent of provider revision and retained while disabled. A probe captures it at authenticated admission and verifies it before dispatch, while pending, and by compare-and-set in the final writer transaction. Each successful configuration/disable advances it and atomically cancels every ready/processing job and erases unpublished transcripts. Jobs pin that generation at dispatch; alive/status/finish reject a mismatch. Re-verifying the same provider/model never revives prior jobs. Restore advances authority too. Schema33 is still an unaccepted development unit, so its authoritative migration includes the new generation table/column directly; this is not an upgrade recipe for a deployed v2 schema33 database.

An ambiguous upload acknowledgement or status poll retains the original canonical Blob and UUID in current-screen memory. **결과 확인** performs GET under that identity; a missing receipt can resend only the exact same UUID/Blob to backend dedup. It never DELETEs the uncertain attempt or allocates a fresh attempt as network recovery. A returned cancelled/expired/unknown result closes that attempt with honest wording and no automatic action. Only explicit re-record/new recording creates a new identity. Reload still does not recover local audio/attempt bodies; no private offline queue was introduced.

Executable regressions reproduce v2's ready-transcript revival and lost-ACK/poll identity loss before repair. Real HTTP then verifies held probe→disable/replace→release, ready→disable→same-binding reverify and processing retirement; SQLite verifies monotonic authority across disable/reopen and rejects authority deletion/rollback. UI verifies GET recovery without a second upload, exact same UUID/Blob reupload after404 and closed unknown outcomes. Root artifacts retain actual-red and green runs; independent re-review remains required.
