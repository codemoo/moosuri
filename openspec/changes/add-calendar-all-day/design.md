# Date-only events through the existing effect lifecycle

CalendarFields already stores provider date-only reads. Strict date-pair validation distinguishes them from RFC3339 timed values without a schema change. Date-only writes use null time_zone and provider date objects. Observations reject mixed/dual shapes, preserve date strings, and apply existing primary/organizer/solo/nonrecurring eligibility. Timed/all-day conversion is rejected independently at Store admission and connector dispatch. Reconciliation requires the same date shape, exact dates and operation/digest marker.

Forms and current-request interpretation use inclusive start/last civil dates. Store validates exact grounded date quotes with the frozen reference/IANA zone, adds one civil date for the API exclusive end, and preserves the prior civil-day count on a date move. A single explicit all-day date is one day; incomplete multi-day ranges clarify. No UTC timestamps or elapsed-hour event durations are synthesized. Existing typed JSON plans and bounded continuation freeze the new nullable fields, with default null for older decisions. Same-thread applied receipts identify only the exact existing event; current user intent and fresh unchanged ETag remain required.

Date-only events are shown as dates without local-time conversion. The editing form keeps the observed kind and advances ETags only from acknowledged receipts. Existing action UUID/digest/session/connection/app fences, cancellation/revocation and unknown lookup-only recovery are unchanged. Long provider all-day events remain readable but outside the bounded write scope.
