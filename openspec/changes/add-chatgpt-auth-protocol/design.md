# Design

A fixed-origin client is constructible publicly only after runtime discovery validation. Typed non-cloneable attempts hold private state, nonce, verifier and exact loopback redirect. Callback validation consumes attempts on every outcome; pending redemption exposes only the issued non-secret registration for persistence before exchange, then consumes the code. Issued-client attempts retain the pending client when callback client_id is absent and reject any supplied mismatch. Retained incomplete IssuedRegistration carriers can be consumed to start fresh reauthorization after code rejection/expiry, without dynamic re-registration or fabricating a verified identity. Known identities use the returning path with subject pinning. Verified identities carry issuer/subject/client/host identity without using email or opaque workspace metadata as authority.

Private transport owns bounded DNS-pinned HTTP without proxies, redirects, retries or configurable production origins. Private JWT validation owns key selection and RS256 cryptography before claims are exposed. Token response scopes independently establish plan permission. Secret bundles are immutable and nonserializable; explicit sealing views and plan-gated access are sensitive caller boundaries.

Refresh returns replacement state; caller leases/CAS/atomic storage remain mandatory. Optional ID-token/scope omission retains the verified previous values. Optional earliest-refresh metadata remains opaque. Revoke returns only confirmed remote success or a sanitized failure, leaving local revocation orchestration to the application. See docs/chatgpt-authentication.md for exact bounds and unsupported integration.
