## Why

This bounded increment supports [R04/R05/R11](../../../docs/requirements.md) and the [provider contract](../../../docs/providers.md); it does not complete their personal-authentication requirements.

The ordinary OpenAI API encoder sends fields and flat tools that the official SIWC plan route rejects. A future personal binding needs an explicit protocol foundation without enabling subscription login through shared providers.

## What Changes

- Add an opt-in plan client at the fixed official API origin and account-specific SIWC catalog parsing.
- Add supported text encoding and fixed namespace tool rounds with dialect-pinned private continuation.
- Preserve sanitized known plan errors, partial observations, clean EOF and no replay/fallback behavior.
- Verify with synthetic state machines and real loopback HTTP; retain ordinary API behavior.

## Impact

Only connector protocol/transport, provider implementation bounds and this specification change. No auth, store/schema/core/UI, shared provider, dependency, account or live inference changes. Personal OAuth/ownership and actual model capability proof remain dependent increments.
