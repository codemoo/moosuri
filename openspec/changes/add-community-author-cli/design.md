## Boundary

The CLI handles author filesystem IO before resolving an installation path. A public pure facade shares the installer's exact bounded content validation; ordinary installer errors retain their existing InvalidInput behavior. No Store is constructed and no source identity or installed pin is generated by checking local files.

## Filesystem discipline

Normal repository parents are allowed. Traverse existing directories through nofollow descriptors, reject parent traversal and installation markers in ancestors, and never chmod another tree. Check inventory and four bounded UTF-8 nonexecutable single-link regular files through the pinned directory descriptor. Diagnostic strings identify compatibility rules without echoing input text.

Init writes exactly four files inside a new private sibling staging directory, fsyncs files/directory, uses Linux/macOS native no-replace rename and syncs the parent. Destination conflicts cannot overwrite even an empty existing directory. Cleanup checks tracked device/inode identity, unlinks only created files and removes only an empty owned staging directory. Unknown contents or replaced paths remain untouched. A parent-sync failure after publication can leave a complete destination, which the author can inspect/check.

## Compatibility and limits

Validation keeps the same strict sidecar/frontmatter/license/examples/capability subset and digest framing. Template license text is the repository's full standard Apache-2.0 text. No template is derived from private data or installed instructions. Compatibility is not safety, license-rights or task-quality certification. Git actions remain explicit contributor work; UI installation still validates and pins immutable public GitHub snapshots without granting tools.
