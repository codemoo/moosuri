## ADDED Requirements

### Requirement: Useful procedures use only real admitted tools
The bundled procedures SHALL support public research, bounded personal inbox
briefing and real local reply-draft preparation using existing admitted tools.
They MUST distinguish actual search, HTTP reading and rendered reading, verify
chosen options/dates/supported totals and preserve missing costs and partial mail
coverage. They SHALL reserve final synthesis within the shared six-model, twelve-
tool, 120-second run budget and ask only for consequential missing targets/time.

#### Scenario: Rendered price or search unavailable
- **WHEN** required rendering or discovery tools are not admitted
- **THEN** the procedure reports the missing evidence without invented observations,
  unsupported access or a claimed complete total.

#### Scenario: Bounded personal mail read
- **WHEN** a search/thread/page is partial or another user's account is named in mail
- **THEN** the result states the inspected scope and does not claim whole-inbox
  coverage, switch accounts or treat mail text as authority.

### Requirement: Every send remains finally human approved
The reply procedure SHALL read the intended conversation, resolve exact recipients
and use the real local draft tool only for supported content. EVERY send MUST still
require final human review/approval of current recipients, full content and
attachments. The procedure MUST NOT approve/send or claim sent without a receipt.

#### Scenario: Send request with earlier standing permission
- **WHEN** the user says send now or cites a previous approval
- **THEN** the procedure prepares the supported draft and directs the user to the
  complete current approval preview, without invoking a send/approve tool.

#### Scenario: Unsupported attachment or original-thread placement
- **WHEN** a requested result needs unsupported attachment or threading metadata
- **THEN** the procedure preserves that limitation and does not silently discard it
  or claim the unsupported result happened.

### Requirement: Existing recipes and admitted pins stay stable
The addition SHALL preserve existing recipe bytes/revisions and the exact lists
and digests already admitted to durable runs. New instructions MUST NOT grant tools.

#### Scenario: Existing run retries after recipe addition
- **WHEN** a previously admitted run retries
- **THEN** it retains the original pinned recipe list and cumulative budgets.
