# Design

The frozen personal model source constrains the existing mission_chat envelope to Calendar or fully-null no_command; Store enforces this at decision recording, preflight and effect application. Personal selected mission targets are rejected, and historical runs without an admitted envelope do not acquire one. Shared mission behavior remains unchanged.

The classifier reuses P4 ready_client and actual plan-dialect preflight before durable first-step admission. It sees only current text and frozen Calendar profile. The runner passes the same CalendarService to initial resume and post-classification execution; normal construction retains the official fixed IO. Existing sealed Calendar resume precedes fresh model-client construction. Typed action UUID, ETag/ownership, private withdrawal, minimum receipt and unknown-outcome no-resend contracts are unchanged.

A private cfg(test) constructor attaches existing counted Calendar IO to the actual signed personal OAuth Store/owner; no production endpoint override, schema, dependency, capability probe or approval flow is added. Synthetic proof does not establish actual account acceptance or semantic accuracy.


## Personal disconnect during a resumed Calendar effect

A sealed Calendar command resumes before a fresh ChatGPT client/classifier. This early path must not rely on the fresh-classifier failure finalizer to retire a command. Beginning personal disconnect atomically retires unfinished Calendar plans/origins frozen to the exact tenant/account/binding/revision, withdraws their origin and purges private payload/event/output through the existing execution invalidation contract. Already committed external effects retain their original minimum receipt, and late settlement cannot restore private data. Retry/reconnection cannot reclassify or resend the retired command. Completed Calendar history remains under the existing history contract.

The running-origin private settlement/read guard separately requires the current frozen personal binding; completed origins preserve the existing branch. Calendar completion commits a guard's terminal transition even when returning an error. Regression coverage includes signed held-IO sealed resume, completed-history retention and binding-replacement guard failure, plus a Store-only metadata lifecycle test inspecting raw payload/event/origin/run/effect ledger state. The Store-only test creates no fake session/cipher or verified identity; the signed agent fixture independently establishes authentication and actual routing. Root integrated Linux gates and independent review are required before acceptance.
