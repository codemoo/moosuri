# Design

Use fixed `api.github.com` public REST requests with redirects, proxy inheritance, retries, cookies and authorization disabled. Pin public DNS results for the acquisition. Resolve a branch/tag once through the commits API, or inspect a supplied full SHA through the Git commit API; follow only exact nonrecursive tree and blob object IDs thereafter. Walk at most six directory components, fetch exactly four regular non-executable files, validate decoded size and Git blob object SHA-1, then apply the existing strict instruction/sidecar/license/synthetic-example validator. Never execute package content.

Acquisition is outside the SQLite actor. Preview revalidates the opaque current UserContext after download, stages immutable public bytes and returns the current private activation revision. Installation is a separate single explicit user action against that exact digest and revision; Store revalidates the account and CAS again. Preview never creates an installation or run.

The version2 external envelope stores canonical repository, directory, full commit, slug and four original files. Its SHA-256 has a domain/version prefix and length-framed identity/content. External stable IDs hash length-framed repository and directory; names and versions do not define identity. Old curated envelopes, hashes and run pins retain their original parser/format. Only curated source identities may replace bundled twins. Both kinds use existing per-user active/previous/enabled/hidden/tombstone state and immutable run metadata. No migration is required.

Bounds:30-second acquisition,12 requests,2MiB combined HTTP bodies,256KiB commit JSON,512KiB tree JSON,2048 tree entries,64KiB blob JSON,32KiB decoded per file and64KiB package total. At most two HTTP acquisitions run concurrently; at most64 external identities are retained per user including tombstones. Public cached snapshots currently have no GC or refresh scheduler. Rate limits/network/validation failures keep old installations unchanged.

The React parent owns every full-catalog mutation, including importer activation. A synchronous in-flight owner and shared busy state serialize lifecycle/import actions. Beginning a mutation increments catalog generation and aborts older list requests; initial and manual-refresh responses are admitted only for their current generation. The importer owns preview/source-edit generation only and cannot independently replace the catalog snapshot. Account scopes remain the transport/lifetime fence.
