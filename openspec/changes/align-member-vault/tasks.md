## 1. 구현

- [x] 생성·변경·보호 키 교체에 같은 글자 수와 바이트 한도를 적용하고 과거 암호문을 여는 경로를 검증한다.
- [x] 생성·복구·보관함·상세·편집·설정·가져오기에 회원 페이지의 시각 요소를 적용한다.

## 2. 운영 검증

- [x] Linux 브라우저에서 합성 회원의 저장·재개·실패 흐름과 작은 화면의 조작을 확인한다.
- [x] 검증한 볼트 실행본을 배포하고 공개 파일과 관리자 볼트의 초기 상태를 확인한다.

합성 회원의 두 출처를 실제 Rust 서비스로 실행하고 Chromium에서 VWEB-01–12를 수행했다. 비밀번호 7자 거부와 8자 생성·변경·보호 키 교체, 복구 키 재발급·철회, 데이터 편집·검색·삭제, TOTP, CSV 선택 가져오기·중복, 예전 백업 열기, 연결 끊기 실패와 재시도를 확인했다. 320·390·1440px 너비에서 화면 넘침을 검사하고 390·1440px 이미지를 검토했다. [실행 시나리오](../../../vault-web/tests/browser-fullstack.py)

공개 화면 설정과 글꼴이 인증 작업과 동시에 로드될 때 간헐적으로 503이 발생했다. 공개 파일과 설정이 개인 작업의 두 동시 실행 자리를 사용하지 않도록 수정하고, 슬롯을 모두 사용 중인 상황을 Rust에서 재현했다. 이전 버전에서 허용된 한글 네 글자 비밀번호로 기존 헤더와 암호화 백업이 열리는 것도 확인했다. [서비스 검증](../../../crates/moosuri-vault-service/src/http.rs) · [호환성 검증](../../../crates/moosuri-vault-core/src/crypto.rs)

11월 26일 운영 Linux에 볼트 서비스 실행본을 교체했다. 배포 후 HTML·자바스크립트·WASM·CSS·글꼴·아이콘·라이선스·Chrome 확장까지 공개 파일 9개의 해시가 빌드 결과와 일치했다. 로그인한 관리자 Kiri에서 7자와 8자 입력으로 만들기 버튼의 상태를 확인한 뒤 제출하지 않고 닫았다. 운영 DB에는 관리자 한 명, 볼트 0개, 항목 0개가 있었다.
