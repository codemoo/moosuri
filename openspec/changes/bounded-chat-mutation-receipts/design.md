## Decisions
RequestScope accepts an explicit optional timeout for foreground mutations; the existing default GET deadline remains. The single timer covers connection and body consumption. Caller/account abort settles promptly even when the transport ignores cancellation. An owned reader and late-response cancellation prevent a timed-out receipt from publishing results later. No transport helper retries writes.

Chat send expiration follows the existing uncertain path and canonical history reconciliation. Explicit resubmission reuses the original request UUID, text, attachments and selected contexts; the next draft stays independent. Canonical admission clears the pending identity before aborting its redundant HTTP transport, so its abort catch cannot resurrect uncertainty. Cancel/retry expiration refreshes canonical history and releases the action lock; expected_attempt remains its concurrency fence.

POST /threads accepts an optional request_id UUID. Schema71 retains a narrow owner-scoped receipt containing its UUID, original canonical-title digest and created thread ID. The owner foreign key fences account lifetime; the thread ID has no deletion cascade, so an admitted deletion cannot turn replay into a fresh thread. Reusing the same owner/UUID/title returns the current summary for that same thread, a different original canonical title conflicts 409, and a deleted target returns404 while keeping the receipt. Omitted keys preserve old-client creation behavior. No new GET endpoint is introduced.

Both the empty New conversation button and composer-first send hold one creation UUID/title until its receipt resolves. Unknown creation refreshes inventory without automatically posting again. Explicit recovery first reuses that creation identity, then submits the original immutable message identity if the user chose message retry. A button-only recovery never sends the message automatically. If its admitted target already has another draft or unresolved message, a local collision fence retains both slots and original identities until the user finishes that target; migration never overwrites them. Receipt completion atomically migrates pending.new and its separate next draft before clearing the creation carrier; changing threads while waiting does not overwrite or select away from the user's other draft.

The carrier uses the existing authenticated sessionStorage lease, 8-hour TTL, 16-slot and 128 KiB envelope limits, exact-key parsing and account/public-session scope. Recovery restores creation/message statuses only as uncertain and never dispatches automatically. Definitive creation errors clear the unusable carrier; composer-first failure restores unsent text without generating another ID or sending.

## Limits
Timers can be delayed by browser suspension. Synthetic transport/UI evidence is not a real-provider latency claim. Binary uploads, long-running administrative probes and unrelated mutations retain their existing timing. Backend/store integration evidence and browser smoke are recorded by the parent integration work, separately from frontend checks.
