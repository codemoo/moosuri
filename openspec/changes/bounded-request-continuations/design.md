# Design

Schema0042 adds a per-chat-run sidecar with an optional typed request continuation and actual Calendar receipt target. Admission snapshots only an immediately preceding completed run with the same thread/account/session/epoch/model, a maximum30-minute original window and at most four literal answers. Clarification keeps already supplied fields in a partial typed decision. The next isolated interpretation sees that bounded explicit request and current answers, not arbitrary conversation history. Recorder freezes existing fields and requires newly supplied quotes to originate in the current answer; split mission civil phrases may quote the current answer clock. Both recorder and actual schedule rule application independently validate the full bounded request+answers, preserving incomplete original weekday/date scope without duplicating long tasks into the1024-byte persisted quote. A supported explicit timezone answer can complete frozen civil fields.

Calendar pins must match and remain current. Original civil anchor/zone and selected task target are preserved across clarification. Personal ChatGPT still uses only the existing foreground Calendar profile and the no-mission sentinel. Restore deletes sidecars; Calendar private-data purge deletes related sidecars. Current action UUID/digest/ETag dispatch and uncertainty contracts are unchanged.

A current explicit deictic Calendar update/delete resolves only the immediately preceding same-thread applied create/update receipt. Store snapshots the actual owned event and connection; typed service reads that exact ID and Store requires the saved ETag, existing primary/solo/timed ownership and provider If-Match. Named source events retain bounded full-list uniqueness. Destination date is distinct from source date. Date-only moves retain prior civil start (including seconds) in the admitted IANA zone; start/date moves preserve the actual elapsed event duration unless explicitly replaced, rejecting civil DST gaps/folds.
