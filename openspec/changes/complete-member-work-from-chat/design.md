# Member conversational work

## One request and one result

The member can ask in ordinary language, continue another conversation, and return to the result. A short question receives an answer. A requested outcome that needs work gets an identity, completion criteria and a history in its member volume. Steps needed for a single deliverable are recorded under that deliverable. A missing decision asks for the smallest piece of information that distinguishes the possibilities.

## Existing execution boundaries

The personal runtime resolves the current utterance, visible order, task and pinned occurrence for the authenticated member. The installation engine can propose a bounded interpretation. The member service validates the proposal against capabilities, scope, permissions and revision before committing an operation. Source content supplies evidence. Explicit user instructions and the applicable domain action grant supply authority. The member can request a report on creation or after receiving a result. A report reopens its authorized sources even after a reload or later correction. Use the established request, work, action, receipt and effect persistence paths.

An external reply, application or purchase has preparation, member input when needed and provider confirmation. The user may take over the existing browser for authentication or final input. An interrupted result must preserve its prior receipt or uncertainty. Private credentials and payment fields go only through the established member-controlled path. Scheduled observations use the existing member timer and deliver meaningful changes within the granted scope.
