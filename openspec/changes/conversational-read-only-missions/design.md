## Current-request semantics

Normal noncandidate chat adds zero mission classifier calls. Broad Korean/English time/delegation/control cues and an explicit selected mission route candidates through at most one completed function decision before artifact/memory planning. Cue matches are cost routing only. The isolated request includes current owner text and trusted frozen anchor/timezone/selected kind; it excludes history, retrieved/media/tool content, target IDs, credentials and private mission contents.

The strict decision supplies action plus literal current-message task/constraint/time/target/instruction quotes and a bounded civil-time proposal. Exact quotes establish origin, not semantic authorization. The reviewed isolated planner pattern, deterministic current session/lease/CAS constraints and adversarial semantic evaluations are complementary; they do not establish perfect arbitrary-language intent security. Explicit fixed-reminder shells retain zero-call literal precedence. Unsupported actual delivery/writes must not be silently removed from acceptance.

## Storage and apply

Schema29 records the typed decision in the same transaction as its completed model step. Unknown/partial/preview calls cannot apply. Restart/explicit retry loads the same decision; no-command and clarification also persist without reclassification. The original UUID/text/zone/target digest and model/effort/read profile remain fixed. Admission also pins the exact original session digest and authentication epoch. Planning, acknowledgement, apply and pending-plan Retry validate that capability; a replacement login cannot resurrect a revoked unapplied command. Passed ordinary-chat plans retain ordinary Retry behavior.

Apply guards the exact current source run, verifies no source/media/tool execution context and loads the pinned original source session. Shared mission helpers preserve owner capacity, original scope/profile, CAS, budget, unknown/expiry and parent/restore fences. Mutation, actual outcome receipt, terminal source-chat confirmation and event commit together. An inner action savepoint rolls any rejected partial action back before concrete clarification is committed. For one-off resume/steer, a separate preflight transaction verifies the source decision/lease/original capability and the exact owned target/revision before committing execution-guard effects only. Apply rechecks source authority and target CAS afterward. No action writes occur in preflight, and its target expiry/revocation survives even failed source confirmation. Target budget expiry and authority withdrawal are not described as admission capacity.

Civil time normalization compares complete supported hour/minute/meridiem, exact weekday sets and today/tomorrow/ISO dates against the frozen anchor and local date, then reuses the existing Once/Interval/Daily/Weekly IANA clock oracle. Explicit UTC/IANA tokens in the current request override browser metadata; conflicting/unknown zones, offsets and abbreviations clarify. This bounded component check is not the old whole-reminder grammar and does not prove arbitrary-language semantics. Relative times retain the original admission anchor. Missing clock/zone, ambiguous names and unsupported start/event semantics clarify; no guessed default clock. Name lookup is exact owned full task/title or actual selected typed target/revision. A selected pronoun uses target_kind=selected; an explicit full name must resolve to that same selected identity. Same-kind/cross-kind conflicts mutate neither target and return current owner cards; stale revisions retain CAS rejection. History delete, changes-only edits and session-only conversational delegation are outside this first action set; direct forms retain their existing capabilities.

## Privacy and lifetime

Outcome receipts contain actual identity/status/next slot and current candidate labels, never copied result evidence or model trace. Receipt projection does not revive deleted/quarantined results. Source-chat deletion before apply removes its capability; deletion after durable save leaves the independently authorized task. Restore quarantines unapplied plans, pauses recurring grants and quarantines unfinished missions. Account reenrollment alone does not execute an old plan.

## Validation limits

Synthetic loopback decisions establish isolation/protocol/transaction behavior and call counts, not language understanding. A worker-visible10-case wording packet was frozen before implementation; the first independent16-case set recorded 11/13 candidate hits, two misses, and two unrelated bypasses. The implementer later saw its inline probe patch, so those cases are now regression evidence. The separate fresh eight-case set contained four positive candidates, two ordinary cases and two temporal negatives. Initially2/4positives routed; after fixes4/4route, both ordinary cases bypass and both temporal negatives enter interpretation. Those disclosed cases are now regressions too. The cue repair generalizes spacing/counter/control families rather than granting authority from matches. No paid/live provider evaluation or latency benchmark was run. Real model paraphrase accuracy, cue recall/false positives and candidate p50/p95/token overhead require separately budgeted opt-in measurement. No model performance claim follows from fixtures.

## Explicit target resolution and civil boundaries

A control without a current exact owned-name quote or actual selected target SHALL clarify and show current target cards, even when only one task exists. Owner count is not evidence that an omitted name meant that task. Explicit ISO dates are parsed before whitespace compaction of the clock; the date cannot be converted into part of the hour or silently discarded to create recurrence. Date/clock cues, Korean delegation stems and English task-reactivation word families are routing hints only; they grant no authority.
