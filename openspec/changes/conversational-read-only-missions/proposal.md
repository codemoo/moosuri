## Why

Owners should ask naturally in Korean/English to delegate a read-only task or control its schedule, without learning command syntax. Existing fixed reminder text must stay literal, and model interpretations must never supply account, target or execution authority.

## What Changes

- Add a cue-gated current-text-only semantic mission interpreter to existing supervised chat.
- Persist each completed typed decision atomically with its model receipt, then apply real existing mission/template/control primitives under the current real session.
- Add actual admission/control receipts and typed owner target cards; no repeated approval for complete requests.
- Use existing UTC/IANA time/occurrence oracle, pinned model/read profile and original mission budgets.

## Impact

Schema29 adds bounded current-request plan/outcome sidecars. Rust core/store/agent/HTTP and React chat integrate them. No new dependencies or scheduler, mail/browser/vault write authority, live model calls or CI enablement. Independent boundary review and integrated synthetic/browser acceptance passed. Real-model unseen-language evaluation and broader clarification remain follow-up, so the change is not archived.
