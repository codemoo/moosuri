# Design

The model quotes query/prefix/scalars from the current user message. The server
requires unique literal matches, resolves disjoint UTF8 spans and parses strict
current scalars. Existing search/read tools return actual private receipt
addresses. A bound arithmetic request references earlier same-run completed
receipts and requires an unfiltered source search with exactly one untruncated
current identity/revision plus a complete byte0/max4096 read. It rechecks
uniqueness and current full source text, locates the fresh prefix exactly once,
and derives its immediately adjacent plain decimal and range itself.

A canonical plan stores only source/current input origin kinds and a typed1–4
operation arithmetic graph. All inputs/steps contribute; only explicit earlier
result references create edges. Existing exact arithmetic evaluates and records
each operation as a child receipt. Finalized proof re-resolves origins, verifies
actual children and terminal final-answer source/field/number/result adoption.
Distinct canonical parameter and source subject hashes are required twice.

Fresh learned reuse composes the existing source primitive with strict uniqueness
inside the existing executor, recording search/read children followed by arithmetic
children. Maximum6-unit headroom and actual charge, same-slot idempotency and
existing6model/12tool/time limits remain. Missing/ambiguous current evidence is
input handling, not a learned arithmetic defect. Existing dependencies/uses and
owner/session fences enforce withdrawal and late-output rejection. Missions do
not gain this primitive or private learned execution.

Generation3 and an additive false-default profile capability fence old persisted
runs; disposable eligibility indexes follow existing schema drift cleanup while
private original evidence remains. Reconstruction-only sharing reads the plan,
generates a separate synthetic source precondition and inputs, uses the existing
four-file package checker and transfers neither private parameters nor proof.
