# Evidence-bound exact calculation

## Why
Existing saved-source and exact-calculation receipts prove their individual
operations but do not bind an operand to a particular current source field.
Mixed successful tool traces must not become learned procedures through semantic
extraction or coincidentally equal numbers.

## What Changes
- Add a common source-bound arithmetic primitive with explicit receipt origins,
  fresh current-user quote parameters, strict source/field uniqueness and an
  exact1–4-step graph.
- Learn structure only from two distinct finalized source/parameter examples,
  reuse fresh source reads in the existing learned executor, and reconstruct
  structural-only synthetic sharing files.
- Admit native toolset generation3 only to fresh profiles; preserve old-run
  vocabulary and existing drift, owner, withdrawal and budget contracts.

## Impact
Core private types, Store execution/learning/sharing and Agent tool schema/runtime
receipt addresses. No new runner, database migration, provider/URL adapter, public
API/UI, dependencies, CI or operational data changes.
