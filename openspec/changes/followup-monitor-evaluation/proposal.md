## Why

Saved-source follow-up is useful only when unchanged input is free of inference,
a changed source produces one grounded child, and the owner's stop continues to
hide notifications after restart. One complete return-status lifecycle makes
those boundaries observable beyond isolated monitor primitives.

## What Changes

- Add one reusable synthetic return-status scenario through HTTP, Runtime and SQLite.
- Reuse the existing stage/budget observer; expose only narrow sibling helper access.
- Observe exact policy/source scope, child receipts/publication and persisted notification suppression independently.
- Add five required tampered-observation controls and explicit monotonic synthetic scheduler time metadata.

## Impact

Only the Rust public evaluator and scoped documentation change. No product
schema, product source, React UI, live model, external connector, mail authority,
production/legacy store or CI changes. Synthetic source events are newly authored.
