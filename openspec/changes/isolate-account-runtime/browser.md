# Kiri 회원 채팅의 작업 브라우저 구현 계획

첫 출시에서 회원은 채팅으로 웹 조사를 맡기고, 필요할 때 같은 탭에서 직접 조건을 바꾼 뒤 **완료**를 누른다. 무수리는 변경된 화면을 읽고 원래 요청에 답한다. 회원별 작업 공간, 뷰어, 직접 조작과 업무 재개, 여러 탭의 공개 링크 탐색을 구현했다. 설치·사용 방법은 [브라우저 안내](../../../deployment/kiri/browser.md), Linux 검증과 운영 적용 범위는 [현재 상태](../../../docs/status.md)에 기록한다.

## 한 요청이 실행되는 경로

1. **개인 채팅이 실행을 소유한다.** 개인 런타임이 요청을 접수해 대화와 업무 ID를 고정한다. 정적 조회는 기존 읽기 도구, 현재 서비스에 맞는 공식 커넥터가 있으면 해당 커넥터, 화면 탐색·사용자 개입이 필요하면 지속 브라우저를 고른다. 도구가 설치되지 않았으면 실제 가용 상태를 카드에 표시한다. 공용 엔진은 모델 호출을 수행하고 개인 런타임이 도구 선택을 검증·실행한다. 모델의 완료 문구만으로 사이트 조회 성공을 기록할 수 없다.
2. **회원이 실제로 쓸 때 워커를 띄운다.** 개인 컨테이너의 네트워크 차단을 유지하고 회원 전용 Unix 소켓으로 Rust 브로커를 호출한다. 프로비저너가 초대·재시작 때 소켓을 준비한다. 브로커는 peer UID와 설치 레지스트리의 회원·볼륨·세대를 대조해 전용 Chromium 작업 공간을 띄운다. Docker 제어와 원격 디버깅 주소는 설치 측에 둔다. 쿠키·프로필은 회원의 브라우저 전용 저장공간에만 두고 세션 간 공유 범위는 기존 수명 정책을 따른다. [프로비저닝](../../../apps/moosuri/src/kiri_provision.rs) · [기존 워커](../../../crates/moosuri-connectors/src/browser/capsule/workspace.rs)
3. **브라우저를 담당하는 도구 루프가 관측한다.** 첫 버전은 공개 URL 열기, 현재 문서 읽기, 사용자에게 넘기기만 노출한다. 기존 AX와 보이는 레이아웃 텍스트를 재사용해 출처·변경된 내용·잘림 여부만 모델에 전달한다. 업무 예산과 기한 안에서만 다음 동작을 고른다. 같은 문서의 변화 없는 재관측과 반복 모델 호출을 줄인다. 로그인 입력값·쿠키·CDP·프레임은 모델 문맥에 넣지 않는다. [기존 실행 계약](../../../docs/browser-workspaces.md) · [Chromium 접근성 프로토콜](https://chromedevtools.github.io/devtools-protocol/tot/Accessibility/)
4. **게이트웨이는 현재 회원에게만 뷰어를 연결한다.** 인증된 세션에서 개인 라우트를 선택하고, 회원 서비스가 대화·업무·작업 공간의 소유 관계를 다시 확인한다. 개인 SQLite에는 업무와 탭의 식별자, 상태, 버전, 재개 지점과 처리 영수증을 저장한다. 프레임은 인증된 별도 응답으로만 전달하고 HTTP·PWA 캐싱에서 제외한다. 상태 이벤트와 이미지 전송을 분리해 채팅 스트리밍과 입력을 막지 않는다. [개인 게이트웨이](../../../apps/moosuri/src/personal_gateway.rs) · [기존 프레임 계약](../../../crates/moosuri-core/src/browser.rs)
5. **완료하면 같은 업무가 새 화면을 읽는다.** 사람에게 넘기기 전에 다음 안전한 실행 지점을 개인 DB에 남긴다. 제어권 발급 전에 진행 중인 에이전트 조작이 끝났는지 확인하고, 결과를 확정할 수 없으면 ‘결과 확인 필요’로 남긴다. 사람이 조작하는 동안 모델 관측·입력은 멈춘다. 완료 요청은 업무·탭·문서·제어권 버전을 대조해 한 번만 접수한다. 같은 업무 ID와 남은 예산으로 재관측한 뒤 답한다. 그 사이 들어온 ‘오전만 봐줘’ 같은 지시도 다음 단계에 반영한다. 기존의 새 대화 턴 생성과 선택 페이지를 원래 읽기 업무에 넘기는 경로를 구분하고 후자의 영수증·재개 의미론을 재사용한다. [선택 페이지와 업무 재개](../../../docs/selected-browser-missions.md)

### 기존 구현에서 풀어야 할 세 가지 의존성

- **개인 서비스에 업무 러너와 브라우저 라우트를 함께 연결한다.** 현재 개인 서비스는 채팅·텍스트 실행 경로를 사용한다. 게이트웨이 허용 목록, 개인 서비스의 라우터, 브로커 소켓까지 한 단위로 변경한다. 상태·프레임은 각각 크기·응답 기한을 제한한다. 설치 전체 워커 한도는 호스트 브로커에서, 대화별 상태와 세부 내용은 개인 런타임에서 관리한다. [개인 런타임 기동](../../../apps/moosuri/src/account_runtime.rs) · [개인 대화 경로](../../../crates/moosuri-server/src/personal_threads.rs)
- **프로필과 조작권의 수명을 분리한다.** 첫 출시에서는 대화 작업 공간마다 프로필을 배정한다. 같은 회원의 모든 대화가 로그인 쿠키를 공유하지 않는다. 기존 복구 경로는 원래 앱 로그인 세션에 묶여 있다. 휴대폰에서 이어받으려면 이미 로그인한 같은 회원·같은 세대인지 확인하고, 명시적인 ‘직접 조작’ 요청에서 활성 작업 공간의 제어권을 원자적으로 재발급한다. 이전 기기 입력과 복구용 권한은 즉시 폐기한다. 이 전환이 검증되기 전에는 다른 로그인 세션에서 기존 프로필을 복구하지 않는다. [기존 세션 검사](../../../crates/moosuri-store/src/browser.rs)
- **현재 페이지를 근거로 넘기는 것과 브라우저를 계속 운전하는 권한을 구분한다.** 기존 선택 페이지 경로는 대기한 읽기 업무에 자료를 붙이며 같은 실행 ID와 남은 예산을 보존한다. 3단계는 이 경로를 개인 저장소에 연결하고 업무·탭 매핑을 유지해 선택 절차를 줄인다. 인증된 탭에서 임의 클릭까지 자동 재개하는 기능은 별도 동작 계약이 필요하다. [선택 처리](../../../crates/moosuri-store/src/browser/selected.rs) · [기존 업무 재개 테스트](../../../crates/moosuri-store/src/missions/tests/selected_browser.rs)

## 구현 순서와 각 단계의 인수 조건

| 단계 | 구현 범위 | 다음 단계로 넘어가는 조건 |
|---|---|---|
| 1. 회원 채팅에서 실제 페이지 읽기 | 개인 채팅의 모델 응답에 검증된 도구 실행과 업무 대기를 연결한다. 기존 Linux 이미지·공개망 프록시·Chromium 샌드박스를 재사용한다. 먼저 Kiri 시험 서버에서 회원별 워커와 최소 라우트를 연결한다. | 새로 초대한 합성 회원 A·B가 같은 URL을 동시에 열어도 서로의 쿠키·프레임·업무가 섞이지 않는다. 공개 페이지의 실제 값으로 원래 대화에 답한다. 워커가 꺼지면 읽기 실패를 표시한다. |
| 2. 카드와 읽기 전용 뷰어 | 기존 React 뷰어에서 세션 상태와 프레임 로딩을 분리해 개인 채팅에서 재사용한다. 카드는 최신 스냅샷과 짧은 상태를 표시한다. 뷰어에는 도메인, 활성 창, 링크 복사, 패널 닫기와 중지를 제공한다. | 데스크톱에서 뷰어를 열고도 채팅을 보낼 수 있다. 모바일에서 키보드·회전·PWA 재진입 후 위치와 작업이 유지된다. 패널을 닫으면 프레임 전송만 멈추고 중지를 누르면 워커가 멈춘다. [기존 React 제어기](../../../web/src/BrowserWorkspace.tsx) |
| 3. 직접 조작과 원래 업무 재개 | 현재 프레임에 묶인 입력, 한 명의 조작권, 완료 요청 중복 제거를 연결한다. 뷰어를 다시 열면 서버에서 현재 상태를 받는다. | 합성 시간표 사이트에서 사람이 ‘오후’를 ‘오전’으로 바꾸고 완료하면 원래 업무가 오전 결과만 답한다. 두 기기 동시 조작·완료 응답 유실에도 중복 입력·새 업무·중복 답변이 없어야 한다. 여기까지가 첫 시범 출시다. |
| 4. 여러 창과 탐색 범위 확대 | 워커를 단일 페이지에서 한 프로필의 제한된 여러 탭으로 확장한다. 사이트가 연 창을 탭 목록에 반영하고 전환·닫기·마지막 창 종료를 정의한다. 공개 읽기 업무에 한해 의미가 확인된 링크 탐색부터 추가한다. | 상세 페이지가 새 탭에서 열리는 비교 업무를 마친다. 탭 전환 후 늦게 도착한 프레임·클릭은 이전 창에 적용되지 않는다. 로그인 이후 모델 재탐색 제한은 유지하고, 사이트별 민감 동작은 해당 커넥터의 승인 경로를 쓴다. |

**전송과 성능.** 첫 버전은 현행 인증 프레임 방식을 쓴다. 보이는 뷰어만 프레임을 갱신하고 한 번에 한 캡처만 진행하며, 느린 접속에서는 오래된 프레임을 버리고 최신 것을 표시한다. Linux에서 워커의 첫 기동과 재사용을 나눠 카드 표시, 첫 유효 화면, 입력 후 화면 반영의 p50/p95와 회원당 메모리·전송량·모델 토큰을 측정한다. 측정값이 직접 조작을 방해할 때 프레임 인코딩·빈도나 스트리밍 전송을 비교한다. 단일 화면 시범에 별도 영상 서버를 선행 조건으로 두지 않는다.

**재접속과 종료.** PWA의 패널 상태, 작업의 실행 상태, 사람의 조작권을 각각 관리한다. 패널을 닫거나 네트워크가 끊겨도 업무와 서버 세션은 기존 수명 안에서 유지한다. 조작권이 만료되면 확인 대기로 돌아간다. Chromium이 죽으면 제출·클릭을 재생하지 않고 확인 필요 상태로 둔다. 선택한 배포의 프로필 복구는 기존 빈 화면 복구 계약을 따른다. 당시 탭을 복원했다고 표시하지 않는다. 로그아웃·대화 삭제·회원 세대 교체 시 프레임 접근과 제어권을 철회한다. [복구 검증](../../../docs/reviews/2026-11-15-browser-recovery.md)

**출시와 후속 범위.** 격리된 Linux에서 실제 Chromium, 서로 다른 두 회원, 합성 사이트로 1–3단계를 통과한 뒤 설치별 기능 스위치로 시범 활성화한다. 중단 시 새 실행을 막고 활성 업무에는 상태를 남긴 후 회원 전용 워커를 정리한다. 계정·대화·개인 볼륨은 보존한다. 볼트 자동 입력은 Kiri 회원 인증 인계와 도메인별 credential binding을 검증한 후 별도 단계에서 연결한다. 메일 발송은 계속 최종 수신인과 본문을 보여주고 허락을 받는다. 결제·예약 확정에는 대상·금액·결과 영수증을 확인하는 전용 계약이 필요하다. Google 커넥터 설치 자동화는 이 계획의 의존성이 아니다.

### 등록된 회원의 Kiri 로그인 후속 작업

같은 Kiri를 사용하도록 설치한 경우, Google이 확인한 등록 회원의 계정과 Workspace 연결 탭은 한 임시 Chrome 프로필에 속한다. 회원 창의 주소는 게스트의 설치 설정으로 정한다. 게스트 소유자는 작업 UUID로 해당 탭을 다시 열거나 작업을 종료할 수 있다. 로그인 확인 전의 프로필과 만료·종료된 작업은 재개할 수 없다. 볼트 잠금 해제와 Google 동의는 각각 회원의 기존 인증 절차를 따른다.
