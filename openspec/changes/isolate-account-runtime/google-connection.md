# 회원 Google 연결

Gmail, Drive, Docs, Slides, Sheets의 연결 버튼은 먼저 볼트에서 등록된 회원 이메일과 accounts.google.com에 해당하는 로그인 항목을 찾는다. 항목이 없으면 볼트 안에서 비밀번호를 받아 암호화 저장한다. 같은 계정의 항목이 여러 개면 회원이 하나를 선택한다. 항목 선택이 끝난 뒤에만 회원 Kiri에서 새 Google 세션을 열고 로그인을 시작한다. 서비스 연결에는 해당 서비스의 OAuth 동의와 서버에서 확인한 계정이 필요하다.

## 실행 경계

- 게이트웨이는 현재 세션, 회원, 설치, 볼륨, 세대와 권한 epoch를 검사하고 탭마다 독립적인 일회용 식별자와 회원 이메일을 예약한다. 이 단계에서는 Kiri를 열지 않는다. 볼트가 항목을 선택하거나 새 항목 저장을 마치고 식별자에 묶인 암호문을 전달해야 Kiri의 검증 도우미를 시작한다. 아직 전달되지 않은 예약은 회원마다 최대 8개, 완료 영수증을 포함한 보관 작업은 회원마다 최대 16개다. 9번째 대기 요청은 같은 세션의 가장 오래된 대기 예약만 교체하며, 다른 세션의 예약은 축출하지 않는다. 16개 한도로 새 요청을 받을 수 없으면 기존 예약과 아직 확인하지 않은 영수증을 변경하지 않고 잠시 후 다시 시도하도록 거절한다. 같은 작업 식별자로 재시도한 `Start`의 서비스나 읽기 의도가 원래 요청과 다르면 충돌로 거절한다. 형식 오류·식별자 충돌·용량 초과로 거절할 `Start`는 기존 작업을 변경하지 않는다. 다른 유효 세션의 볼트 예약과 완료 영수증은 새 `Start`가 삭제하지 않고 회원 한도를 함께 적용한다. 다른 세션에서 Kiri가 진행 중이면 임의 종료하지 않고 충돌로 거절한다. Kiri가 Chrome을 폐기한 뒤 보낸 명시적 종료 상태만 게스트 정리 확인으로 사용한다. 브라우저 폐기 실패, 취소, 권한 철회, 타임아웃처럼 정리 확인이 없는 종료에서는 회원의 활성 표식을 180초 동안 유지한다. 이 시간은 Kiri 헬퍼의 제한된 브라우저 생성·CDP 호출·폐기 상한을 합쳐도 덮으며, 그동안 새 Kiri를 시작하지 않는다. 브라우저 생성 직후에도 연결 생존을 다시 확인해 이미 닫힌 요청은 탭을 열지 않는다. Kiri 접속부터 종료까지 전체 구간에서 세션·권한·이메일을 주기적으로 재확인하고 철회되면 게스트 소켓을 닫는다. 실행 작업 자체가 비정상 종료돼도 독립적인 강제 만료가 활성 표식을 해제한다. 취소는 같은 탭의 진행 작업을 취소하되 이미 저장된 완료·거절 영수증은 덮어쓰지 않는다. 취소·만료 같은 종료 상태에서는 이후 단계 전이를 모두 거절한다. 진행 작업 충돌과 정리는 같은 회원 안에서만 판단한다. 작업 식별자 충돌도 같은 회원 범위에서만 판단한다. Kiri가 현재 프로토콜 버전을 확인하고 암호문을 검증하면 게이트웨이는 세션·권한과 정확한 작업을 다시 확인한 뒤 `proceed`를 보낸다. Kiri는 그 뒤 한 번만 시작하며, Google 계정 홈에서 일치하는 로그인이 확인된 뒤에만 같은 세션의 다른 볼트 대기 예약을 정리한다. 동일 작업의 같은 암호문 전달이 재시도되면 두 번째 Kiri를 시작하지 않고 현재 영수증을 돌려주며, 다른 암호문은 충돌로 거절한다. 전달 응답이 유실된 화면은 직전 `vault` 상태만으로 취소하지 않고 새 상태 조회가 성공할 때까지 볼트 창과 선택을 유지한다. 조회 결과가 계속 `vault`면 같은 선택으로 다시 전달할 수 있고, 더 진행된 상태가 확인된 뒤에만 창을 닫는다. 서버가 전달을 명시적으로 거절하면 볼트 창과 선택을 유지하고 실제 오류를 표시한다. 전달 시점부터 클라이언트와 서버에 같은 Kiri 실행 창을 적용하며, 실행 중 재인증도 예약한 이메일과 일치해야 한다. OAuth 콜백뿐 아니라 취소·거절·차단·본인 확인 필요를 포함한 모든 종료 결과에는 기존 실행 제한을 줄이지 않는 120초 영수증 회수 시간을 부여해 실행 제한 끝에 완료돼도 화면이 결과를 받을 수 있게 한다.
- 볼트는 자체 서버에서 확인한 회원 Kiri 공개 키로 선택 항목을 암호화한다. Kiri 도우미는 암호문이 해당 식별자·회원·이메일에 실제로 묶였음을 복호화하고 `verified`를 반환한다. 게이트웨이는 그 뒤 현재 회원 문맥과 정확한 작업·challenge를 다시 확인하고 `proceed`를 보내며, Kiri는 이 응답을 받은 뒤에만 Chrome을 만든다. 그 전에는 연결 화면도 검증 중으로 표시한다. 새 프로필의 Google 비밀번호 양식에 표시된 계정이 일치할 때만 비밀번호를 사용한다. 로그인 완료는 Google 계정 홈의 계정 표시로 확인한다.
- OAuth 콜백을 받은 게이트웨이는 기존 PKCE 흐름과 회원별 권한을 검사한다. 시작한 회원 세션에서 서비스 연결 영수증을 확인한다. Google의 추가 확인 요청, 차단, 설치 앱 미등록은 각각 별도 결과로 표시한다.
- Linux 운영 설치는 볼트에 등록된 회원 한 명과 전용 Kiri VM을 사용한다. 게스트의 기존 kiri-chrome 도우미 옆에 google_connection.py와 enroll_google_connection.py를 설치한다. 등록 도구의 공개 출력을 볼트 서비스의 --kiri-recipient-file에 지정한다. 수신 소켓은 root 전용이다. 소켓 서비스의 사용자와 SSH 실행 파일은 해당 VM 운영 계정에 맞춘다. SSH 실행 파일이 systemctl --user를 호출하는 설치는 서비스 환경의 XDG_RUNTIME_DIR와 DBUS_SESSION_BUS_ADDRESS를 해당 사용자의 실제 Linux UID에 맞춘다.

## 검증

Linux 브라우저 시나리오는 vault-web/tests/browser-google-connection.py, 연결 화면 시나리오는 web/src/kiri-google-connection.test.ts, Kiri 로그인 및 실패 경계는 deployment/kiri/test_google_connection.py에서 관리한다. 실제 운영 로그인과 GWS 동의는 각 단계의 공급자 결과를 기록한다.
