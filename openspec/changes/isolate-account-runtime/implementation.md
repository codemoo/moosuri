# dev.30에서 사용자별 런타임으로 옮기는 구현 계약

이 문서는 [전체 설계](design.md)를 실제 코드에 적용할 때 지켜야 할 경계와 작업 순서를 정한다. 아래 상태 이름과 인터페이스는 구현 제안이다. 기준 소스는 dev.30, Kiri 후보는 v0.2.1이다.

## 로그인·관리자 권한

이메일은 기존 계정 생성과 같은 정규화·유일성 규칙으로 설치 라우팅 인덱스에 기록한다. 비밀번호와 세션 digest는 개인 볼륨에 둔다. 게이트웨이가 신뢰하는 프록시에서 얻은 IP로 로그인 시도를 제한하고, 개인 런타임은 비밀번호와 세션을 검증한다. 존재하지 않는 계정과 잘못된 비밀번호는 같은 공개 오류를 쓴다. 로그인 후의 라우팅 쿠키는 대상만 고른다. 현재의 HttpOnly 세션 쿠키와 계정 대조를 개인 API에서 계속 검사하며, 로그아웃과 계정 전환은 앞선 SSE·접수 중 요청·브라우저 개인 상태도 정리한다. [인증과 쿠키](../../../crates/moosuri-server/src/lib.rs)

관리자 권한과 대상 계정 상태의 정본은 설치 DB다. 관리 요청마다 개인 서비스에서 현재 세션의 유효성을 확인하고, 설치 DB의 같은 트랜잭션에서 요청자 권한 버전·대상 버전·마지막 사용 가능 관리자 조건을 검사한다. 개인 서비스가 관리 권한을 자체 발행할 수 없도록 관리자 세션 증명은 등록된 해당 관리자의 서비스 신원·현재 세대·요청 목적에 묶는다. 각 계정은 중앙에 비밀번호 변경 필요/복구 중/준비 완료 상태의 버전만 알린다. 초기화·복원·통신 단절로 확인할 수 없는 계정은 마지막 관리자를 대체할 수 없다.

정지·강등·초기화는 요청 ID로 중앙 의도를 기록하고 해당 권한과 세대를 먼저 차단한 후, 개인 서비스가 목표 버전에 맞춰 로컬 세션 철회 등 필요한 변경을 한 번 적용한다. ACK 전까지 관리자 화면에 처리 중으로 표시한다. 중앙 차단 후 개인 런타임이 오프라인이어도 이전 세대는 관리·모델·외부 작업 게이트를 통과할 수 없다. 암호 재설정 응답이 유실되면 이전 임시 비밀번호를 복원해 보여주지 않는다. 필요시 새 요청으로 새 비밀번호를 발급하고 이전 것을 무효화한다. 확인은 관리자 A·B 동시 강등, ACK 직전 서비스 종료, 강등 전 A의 볼륨 복원으로 한다. [현행 마지막 관리자와 권한 철회](../../../crates/moosuri-store/src/accounts.rs)

## Google OAuth와 볼트의 라우팅

Google은 Gmail과 Calendar가 공유하는 고정 콜백으로 돌아온다. 현행은 브라우저의 Strict 쿠키 없이도 콜백이 코드를 **임시 접수**하고, 웹의 같은 출처 POST에서 원래 로그인 세션을 확인한 뒤 토큰을 교환한다. 이 두 단계는 보존한다. [콜백과 교환](../../../crates/moosuri-server/src/mail.rs) · [개인 연결 상태](../../../crates/moosuri-store/src/mail.rs) · [웹 완료 처리](../../../web/src/MailConnections.tsx)

1. 개인 런타임이 기존 방식으로 일회성 state와 PKCE verifier를 만들고 세션 digest·권한 범위·앱 버전을 보관한다. 설치 서비스는 호출한 런타임 신원을 확인하고 그 계정·세대·Gmail/Calendar 목적·만료·내부 state를 묶은 불투명한 외부 state를 발급한다.
2. 게이트웨이는 콜백에서 외부 state를 검증해 원래 소켓에만 전달한다. 개인 런타임만 code를 임시 보관하고 일회성 handle을 반환한다. 리디렉션은 미리 정한 무수리 경로만 사용하며, 콜백이 현재 탭의 계정이나 로그인 쿠키를 바꾸지 않는다. URL 쿼리와 OAuth 비밀은 프록시·오류 로그에서 제외한다.
3. 원래 계정의 인증된 완료 요청만 handle을 소비한다. 세션·세대·앱 버전·PKCE·동의 scope 검증 후 개인 연결을 저장한다. 설치 공용 웹 클라이언트 secret은 좁은 Google 교환/갱신 서비스만 읽는다. 이 서비스는 등록된 공급자 엔드포인트와 호출 런타임만 허용하고 결과를 그 런타임에 반환한다. 사용자 토큰 보존·갱신 잠금·철회는 개인 런타임 책임이다. 공용 서비스가 교환 중 토큰을 일시 취급하는 경계를 명시한다. 한 계정이 시작한 흐름에 다른 계정으로 돌아오거나, 앱·세대가 바뀌면 원래 계정에서 연결을 다시 시작한다.
4. 메일 연결 완료와 채팅 재개를 별도 영수증으로 구분한다. 현재 대화의 적격한 읽기 요청만 원래 연결 ID·버전으로 한 번 이어간다. 설정에서 단독 연결한 경우나 읽기 뒤에 새 지시가 들어온 경우에는 이전 작업을 실행하지 않는다.

볼트 서비스의 기존 handoff와 grant는 불투명하며 단독으로 개인 DB를 고를 수 없다. 서버 전용 어댑터가 발급 시 설치·계정·세대·목적에 묶인 라우팅 봉투를 붙이고, 검증한 뒤 해당 개인 Store에 내부 토큰을 전달한다. 실제 세션·epoch·origin·커밋 허가 검증은 소유 Store가 한다. 별도 도메인과 암호문/복구 키 형식은 유지한다. 설치 서비스에는 삭제·철회 명령 및 볼트 ACK를 저장한다. 컨테이너 제거 뒤에도 삭제 의도가 살아 있어야 하며 ACK 유실은 같은 이벤트 ID로 처리한다. A의 토큰을 B에 제시한 경우, 폐기된 세대의 grant, 삭제 도중 재시작을 검증한다. [어댑터 프로토콜](../../../crates/moosuri-vault-protocol/src/lib.rs) · [볼트 권한](../../../crates/moosuri-store/src/vault_authority.rs)

## 공용 호출과 구버전 차단

- 호출 키는 소유 계정·런타임 세대·작업·모델 호출 순번으로 고정하고 선택 모델/강도/연결 버전과 요청 내용의 키 기반 지문을 결합한다. 같은 키·같은 내용은 기존 상태를 반환하고, 다른 내용은 거절한다. 로그·공용 DB에 프롬프트를 저장하지 않는다.
- 원장은 예약, 외부 전달 시작, 정산 완료, 결과 불명을 구분한다. 전달 직전 의도를 영속화한다. 응답을 잃고 공급자 영수증도 없으면 결과 불명으로 남기고 자동 재호출하지 않는다. 브라우저 재접속은 개인 이벤트 스트림을 이어받는다. 새 모델 요청은 사용자가 새로 의도한 경우에만 별도 호출로 접수한다.
- 모든 유료 호출·메일 발송·외부 쓰기는 현재 세대를 확인할 수 있을 때만 새로 시작한다. 정지 시에는 이미 열려 있는 전송도 drain하고 결과를 대조한다. 앱 내부의 플래그 한 개로는 외부 통신을 막을 수 없다. 호스트에서 개인 런타임의 일반 통신을 통제된 출구로 제한하는 것이 전제다. 사용자 지정 로컬 모델 주소는 설치자가 정의한 해당 모델 어댑터의 목적지로만 허용한다. 개인 브라우저나 스킬에 호스트 관리망 접근을 열지 않는다.

## 이전 데이터와 복구 기준점

검토 중 공개된 81개 마이그레이션을 빈 SQLite에 순서대로 적용했다. schema 81의 main에는 **업무 테이블 202개**가 있다. 가상 FTS 테이블을 포함하고 SQLite 내부·FTS shadow 테이블은 제외한 수다. 그중 **34개에는 tenant_id와 account_id 컬럼이 둘 다 없다.** 예를 들어 초대 전달 영수증, 자격 증명 바인딩, FTS, provider 증명은 이름만 보아서는 공용인지 사용자의 자식 데이터인지 판정할 수 없다. 컬럼이 있는 테이블도 개별 소유 관계를 검증한다. [마이그레이션 원본](../../../migrations/assistant)

이전 도구의 첫 산출물은 실제 schema에서 생성한 목록이다. 항목마다 소유자 추적 키 또는 부모 조인, 공용/개인/재생성/재인증 분류, 키 변환, 검증식, 처리 불능 시 조치를 지정한다. DB 밖 파일과 저널도 포함한다. 분류 없는 테이블이나 소유자가 모호한 행은 dry run에서 오류로 보고한다. 새 스키마 버전이면 목록을 재생성한다. 보고서에는 수량·지문·사유만 남긴다.

현행 인증·삭제 저널과 백업 수신자는 순서·이전 해시·설치 ID·기준 백업에 묶여 있다. 사용자별 행을 발췌해 기존 해시 체인으로 취급할 수 없다. 쓰기를 차단한 시점의 원본 일관 스냅샷과 전역 저널 끝을 고정하고, 각 사용자의 복구 기준점을 새로 만든다. 이전 증명에는 원래 설치·소유자, 이전 세대, 원본 체크포인트, 소유자별 상태·삭제 표식의 커밋값, 신규 저널 첫 기록 및 새 암호화 백업 지문을 넣는다. 독립 복구 수신자가 이 전환을 기존 신뢰 기준으로 인증하고 새 기준을 영속 승인해야 쓰기 권한을 넘긴다. 과거 전역 저널은 복구 보관소에 한 번 보존하며 개인 볼륨에 다른 사람의 기록을 복사하지 않는다. 재시도는 동일 이전 ID와 소유자 체크포인트로 귀결된다. 구 형태의 수신자가 새 기준을 인식하지 못하면 해당 계정의 절체를 중단한다. [해시 체인](../../../crates/moosuri-store/src/journal.rs) · [삭제 증거](../../../crates/moosuri-store/src/destructive_intents/journal.rs) · [백업 수신 계약](../../../crates/moosuri-store/src/backup/live.rs)

필수 리허설에서는 A/B 작업과 삭제가 교차한 원본을 분리한다. 원본 서버 없이 A만 복구해 삭제한 자료가 되살아나지 않는지, B 자료가 없는지, 미확정 발송이 재전송되지 않는지, 공용 지출이 되감기지 않는지 확인한다. A가 새 쓰기를 받은 후에는 구 DB로 라우팅만 되돌릴 수 없다.

## 구현 순서

| 묶음 | 병합 가능한 결과 | 통과 기준 |
|---|---|---|
| 1. Linux 격리 실험 | 고정 릴리스·체크섬, 실제 Linux에서 A/B 컨테이너와 전용 볼륨을 만드는 재현 가능한 실험 | 허용한 공용 모델 소켓과 각자 데이터만 접근한다. 엔진/호스트/타 계정에 접근할 수 없다. 재부팅 후 A가 한 번만 살아난다. 설치 전후 기존 Docker 소켓·서비스 경로를 확인한다. 실패하면 운영 구현으로 승격하지 않는다 |
| 2. 초대부터 독립 로그인까지 | 신설 계정에 한해 프로비저닝, 라우팅 및 개인 세션을 연결한다. 공용 관리 작업은 위의 요청/ACK 계약을 쓴다 | 중복 초대, 생성 중 종료, 두 탭 계정 전환, 마지막 관리자 보호를 합성 계정으로 검증한다 |
| 3. 한 번의 실제 사용자 여정 | 공용 모델 호출과 서버 Google OAuth를 연결한다. 일반 웹 입력에서 Gmail을 연결하고 원래 읽기 요청을 이어간다 | A/B가 같은 모델로 각자 받은 메일을 읽는다. OAuth 취소·계정 전환·재시작·중복 완료·전송 승인 경계를 검증한다 |
| 4. 나머지 기능·이전 | 기존 기능표에 각 런타임 소유자를 매핑하고 볼트·Telegram·푸시·수집·스케줄·복구를 연결한다. 동시에 사용자별 이전 목록과 수신자 전환을 구현한다 | 한 계정 독립 복구, 발송 중 절체, 오프라인 계정 삭제, 실제 기간을 대표하는 백업 크기와 이전 시간을 측정한 뒤 시범 전환한다 |

처음 세 묶음은 새 설치 또는 합성 계정으로 개발할 수 있다. 기존 사용자 전환은 네 번째 묶음의 독립 복구 증거가 나온 뒤에 시작한다.
