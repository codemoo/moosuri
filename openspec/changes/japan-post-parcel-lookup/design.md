# Bounded official latest-summary lookup

The official English input page currently exposes GET `/services/srv/search`,
`requestNo1`, locale=en and image-submit coordinates. Current synthetic all-zero
11-digit lookup returns a table with seven exact summary headers and an explicit
not-found row. The official notices document international2letters+9digits+2letters
and exclude U-prefixed untracked labels, ordinary mail and out-of-scope formats.

`parcel_track(carrier=japan_post,tracking_number=string|null)` is a new WebToolRequest
under the existing authenticated external-slot/public-HTTP execution path. A new
bundled recipe pin gates admission, so existing serialized profiles without that
pin retain their vocabulary. Read configuration is still mandatory/current at
admit, IO polling and result commit. No schema or execution budget changes.

Connector uses a fixed HTTPS host/path/query builder, existing public-DNS address
pinning, no ambient proxy/auth/cookies/retries, bounded response/parser work and no
redirect following. It recognizes only the established exact summary headers,
matching requested tracking-number row and explicit not-found message. Matching
positive six-cell summary returns one latest event with raw provider date/status/
office and a raw visible excerpt. Other markup returns provider_changed with no
events. A raw date without offset is not converted into UTC; date-only ISO fields
normalize only an unambiguous explicit year. Full history/positive live acceptance
remain unestablished and are not claimed.

Store binds an initial number to literal current user text and an explicit Japan
Post carrier phrase. Null (or repeated matching number) can reuse the most recent
unique completed typed lookup in the same owned thread, within32turns. Reuse reads
actual persisted tool/dispatch receipts, never model/source IDs; ambiguous/latest
multi-number results require the number again. Current and original number-source
request/run IDs are stamped by Store in the completed result. Generic failures
without a completed receipt do not invent reusable identity. Thread/account and
existing cancellation/logout/provider/restore fences remain authoritative. A
follow-up performs a fresh bounded read; an old status is not presented as current.

Existing web-evidence DTO/UI shows the actually observed official source link/time;
no new browser DTO/schema/frontend flow is needed. Scripted loopback provider and
model exercise actual connector parsing, external permits, receipt/provenance and
chat final responses. Fixture transport is available only through the existing
explicit test-fixtures Cargo feature; production has no private-address override.
