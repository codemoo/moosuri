# Reuse bounded public-page collection procedures

## Why

Public HTTP reads and saved reports exist, but a successful multi-page procedure
cannot become a private recipe or run with fresh explicitly delegated mission
inputs. Repeating a saved URL or collecting pages without their receipts would
not satisfy F26/F27/F67.

## What Changes

Add `public_pages_collect` for two to four explicitly supplied public HTTP targets,
with exact current-task input validation, per-page dispatch/receipt/budget and
bounded individual observations/failures. Learn only count/collection structure
after two distinct actual finalized adopted inputs; reuse performs new reads on
fresh foreground or explicitly delegated mission URLs. Reconstruct portable
instruction packages with invented examples and no private values/proofs.

Schema55 stores child dispatch identities only; child contents reuse private
receipt storage and inherit original run/step/owner/deletion fences. Additive exact
bundled pins keep historical runs from gaining this tool. Existing route schema
and arithmetic/source qualifications are not retired.

## Impact

F24/F26/F27/F67, P4/P5/P6. No arbitrary DAG or semantic-success claim; no new provider,
credentials, browser, mail/Calendar effects, external writes, public publishing or
automatic target discovery. Existing explicit mission request supplies background
authority and exact accepted task text, including revised acceptance handling.
