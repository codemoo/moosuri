# Bounded local signed bundle management

The first installer consumes a local directory containing an exact Ed25519-signed JSON manifest, detached raw signature and one native moosuri binary with embedded React assets. The operator supplies an explicit32-byte public-key pin; there is no invented official key, downloader, service manager or arbitrary archive extraction. Signed metadata fixes product, format, SemVer, monotonically increasing release sequence, exact build target, Store schema and binary basename/size/SHA256. A verified executable's public self-info probe must agree and report embedded assets before copying it into a new owner-private runtime prefix. Data is a separate absolute private root; runtime/data overlap, symlink components, unrelated existing runtime entries and path traversal reject.

The runtime uses immutable release directories and a small fsynced activation state. A staged update records its old/new releases before replacing the active state atomically. Explicit finish/keep-old recovery handles a crash at that boundary. Managed server startup refuses a pending activation, and recovery checks the active record against the journal. Immutable old binaries remain until explicit uninstall; this is a reversible binary choice before serving, not an old SQLite snapshot rollback promise.

Updates are intentionally same-Store-schema only. They hold the existing stopped-installation writer lock continuously through existing integrity/journal verification, an encrypted stopped export and activation. A minimal public Store maintenance handle reuses existing Offline capture/export rather than opening a second lock or migrating the live DB. Backup setup is required. Export limitations remain: it protects the existing SQLite/journal image but is not a full arbitrary historical/media restore primitive. Cross-schema forward updates remain an explicit release gate until a concrete compatible recovery flow exists.

Generated Linux user-service and HTTPS/Tailscale command examples are reviewable files under the private prefix; no system service, DNS, Tailscale Serve/Funnel, vhost or running process is changed. A stable manager command runs the selected signed release and reuses existing init's hidden/password-file flow. Default uninstall requires the data writer to be stopped, removes only recorded managed regular files/directories that still match expected identity/content, retains data and unrelated entries, and never recursively removes a home/data root.

Synthetic focused tests cover verified fresh install/init/served shell where embedded assets are available, exact signature/hash/path/target refusal, active writer lock refusal, interrupted activation recovery, and unrelated-file/data preservation. Official keys/artifacts, Linux arm64 acceptance, stable release, service activation and full P10 acceptance remain pending.


Independent-review repairs: private descriptors use the native broker ACL policy (no entries); trusted ancestry uses the existing skills deny-only macOS policy and rejects grant/default extended ACLs. These checks run before reads/writes and after creation without stripping operator ACLs. HTTPS service templates trust only Nginx’s overwritten single X-Real-IP. Direct Tailscale-mode templates omit proxy-header trust entirely, safely ignore possibly chained X-Forwarded-For and use actual loopback peer+email login buckets. No per-tailnet-client IP attribution is claimed.
