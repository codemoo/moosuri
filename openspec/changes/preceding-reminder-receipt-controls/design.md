# Receipt-backed fixed reminder continuity

Fixed reminder admission precedes mission interpretation. The parser represents
the deictic noun phrase as a distinct target; existing control actions and civil
time parsing remain shared. An explicit selected reminder keeps its existing
owner/revision validation. Without selection, only the immediately preceding
completed run in the same thread, owner, original login and authentication epoch
may provide its durable reminder receipt, bounded to thirty minutes. The current
owned reminder must retain the receipt revision and remain unrevoked. A separate
selected domain cannot donate an implicit reminder target. A missing, stale or
ambiguous target asks for the reminder name/selection without a write or model
call. Existing generic and named reminder resolution are unchanged.

All writes and confirmation receipts remain in the existing atomic admission
transaction. Original request UUID replay returns the original result. Existing
source, attachment, deadline and authority checks remain in force.
