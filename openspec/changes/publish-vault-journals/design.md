# Source capture, streaming receiver and independent pin

The worker uses the exact Arc<Mutex<Database>> passed to HTTP. It calls existing capture_snapshot under that mutex; the guard ends before prepare_publication opens frozen files for full DB/journal semantic replay and before SSH. Source root and private capture directory are disjoint. The baseline snapshot/head is independently copied to explicit empty target roots; source uses the matching head hash and public journal recipient. No source seal or authority change occurs.

Fixed OpenSSH argv takes restricted alias/target tokens, strict host-key verification, BatchMode, no PTY/forwarding, connection/keepalive limits and60second transport deadline. Dedicated process-group kill/reap and bounded stdout join handle transport cancellation, timeout and descendant pipe retention. This deadline/cancellation starts only at SSH transfer, not during source preparation. Source capture, journal scan/replay, table comparisons and digesting are file-size bounded, with no overall elapsed-time limit or cancellation guarantee. Existing partial capture checks do not bound the entire preparation. Shutdown waits for admitted preparation to drain and may wait for an extended period; cancellable/deadline-checked preparation is a future operational improvement. Once transfer starts, shutdown cancels/reaps it. Receiver streaming separately checks its60second processing deadline, and its CLI has a65second watchdog for stalled stdin. Filesystem stalls/fsync are not hard realtime. Periodic idle waiting makes no calls.

Receiver holds its independent lock and pins source/baseline/public recipient. Distinct MVJP0001 framing supplies bounded metadata and the complete source journal. It validates typed intent framing and every hash-chain step, source prefix, baseline boundary, final head/sequence/digest and the exact SHA256 of the previously accepted byte prefix. It streams into the existing historical MVJC0001 age archive directly, so no raw journal is written at rest. No private key is generated or read. The receiver validates codec/chain/prefix; source and existing historical restore perform DB/journal semantic validation independently.

Each immutable generation has only journal.age and head.json. Fsync generation/parent precedes no-overwrite atomic publication of a linked independent ledger receipt; only that receipt makes it accepted/current. Unchanged captured content excludes attempt UUID from its fingerprint and returns the original checkpoint/receipt after ACK loss. Pre-receipt encrypted artifacts can survive as orphans; current corruption fails closed. Status revalidates current artifacts and returns exact trusted_head_sha256 plus baseline/journal paths for existing restore-historical.

Periodic publication leaves a gap; ordinary writes never synchronously await receiver durability. Receiver latest means its accepted local chain only. Rollback of every target artifact/ledger and independent pin is outside local detection. No world-latestness, zero-loss, anti-fork execution, remote infrastructure/retention setup or real deployment claim is added. Public recipient/baseline changes require a new explicitly initialized target.
