# 설계

일반 입력창의 기존 Claude 해석이 지속 선호와 개인화할 질문을 식별한다. 선호 본문은 회원이 직접 쓴 말에서 확인하고 기존 기억 변경 경로에 저장한다. 무엇을 고를지 묻는 질문에서는 대상과 가능한 선택지를 검색어로 제안한다. 회원 SQLite가 최대 세 낱말로 현재 유효한 기억을 찾는다. 검색어로 나온 선택지는 회원의 선호로 저장하지 않는다. 해석 결과에는 요청과 연결된 기억 ID와 버전만 남긴다. 일반 답변을 보낼 때 다시 검증하고, 참고 자료는 사용자 데이터로 전달한다. 원문과 답변의 연결은 기존 정정·철회 처리에 참여한다.

회상과 평소 대화는 같은 입력창을 쓴다. 검색이나 외부 실행 권한, 모델 호출, 저장소, 회원 설정을 추가할 필요가 없다. 과거 업무·대화의 명시적 검색은 기존 업무 흐름에서 처리한다.

“통로”라고 말한 회원이 나중에 “좌석”을 물을 수 있다. 선언을 해석할 때 선택의 종류를 나타내는 짧은 단어도 받아 기존 SQLite 검색 색인에 같은 버전으로 기록한다. 이 단어는 자동회상에서만 검색하고 답변 근거로는 회원이 직접 말한 문장을 보낸다. 기억 수정과 망각은 이전 색인도 같은 트랜잭션에서 지운다. 기존 기억, 기억 화면에서 수동으로 고친 항목, 원문에서 색인을 다시 만드는 이전 절차를 거친 항목은 제목과 본문으로 찾는다.

LangGraph Store에서 참고한 점은 대화가 바뀌어도 사용자 단위로 기억을 조회한다는 것이다. Kiri에서는 회원 SQLite가 이미 이 역할을 맡는다. LongMemEval에서 다루는 여러 세션에 걸친 회상, 이전 정보의 갱신, 근거가 없을 때의 응답을 회원 화면 시나리오에 반영했다.
