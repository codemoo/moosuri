# 회원 선호 자동 회상

- [x] 회원이 직접 밝힌 평소 선호를 기존 기억으로 저장하고 이번 요청의 예외를 구분한다.
- [x] 답변에 사용한 기억과 그 버전을 기록하고, 정정·망각·만료 이후의 답변과 후속 대화, 다른 회원의 접근, 입력 예산을 Linux에서 검증한다.
- [x] Linux의 일반 입력창, 회원 SQLite 및 지정 Claude에서 장기·새 대화와 예외를 검증하고 제품 상태를 갱신한다.

## 회원 화면에서 확인할 동작

| 시나리오 | 회원 동작과 판정 |
| --- | --- |
| REC-01 | 첫 대화에서 좌석 추천을 부탁하면 저장된 기억 없이 일반 답변을 받는다. |
| REC-02 | “기차는 통로 쪽이 편해”라고 하면 기억 한 건이 생기고, 회원이 기억 화면에서 열어 수정할 수 있다. |
| REC-03 | 새 대화에서도 통로를 추천한다. 새로고침하면 같은 답변을 다시 읽고 호출과 기억 버전은 늘지 않는다. |
| REC-04 | 통로를 추천받고 “이번엔 창가로”라고 하면 창가를 고른다. 같은 대화에서 다음 여행을 물으면 다시 통로를 추천한다. |
| REC-05 | 인사 한마디에는 일반 답변만 돌아온다. |
| REC-06 | 한 대화에서 9왕복 뒤 좌석을 물으면 최근 8왕복과 저장된 선호를 써서 통로를 추천한다. |
| REC-07 | 파스타 삶는 시간을 물으면 좌석 선호를 전달하지 않는다. |
| REC-08 | 두 번째 회원이 로그인하면 첫 회원의 기억과 대화는 보이지 않는다. |
| REC-09 | 평소 선호를 창가로 바꾸면 새 버전을 사용한다. 잊어 달라고 한 뒤에는 저장 내용과 추천 근거에서 빠진다. |

일반 입력창을 통해 보낸 뒤 회원 화면의 답변, 해당 회원의 SQLite, 모델에 전달한 기억을 대조한다. [Linux 실행 방법](../../../deployment/kiri/linux-vm-smoke/README.md#chat-work) · [시나리오 실행기](../../../deployment/kiri/linux-vm-smoke/member_preference_recall.py)

## 2026-11-25 Linux 실행 결과

격리 회원 두 명의 Chromium에서 REC-01~09가 합성 모드와 Claude Sonnet 5.5(`medium`) 모드에서 각각 9/9 통과했다. 실제 모델 모드에서 해석 11회와 답변 9회는 지정 Claude의 사용 영수증을 확인했다. 최근 문맥을 채우는 인사 9회는 고정 응답을 썼다. 회원에게 표시된 답변은 SQLite 원문과 같았고, 모델로 간 일반 답변 요청 18개 중 4개에 관련 기억이 들어갔다.

처음에는 회원이 “통로”라고 한 기억을 질문의 “복도”로 찾지 못했다. 기존 색인에 선택의 종류인 “좌석”을 남겨 해결했다. 만료된 항목이 유효한 항목을 밀어내던 경우도 고쳤다. 회원 대화 서버 19개, 대화 저장소 22개, 일반 기억·검색 회귀 18개가 통과했다. 기존 입력창의 명시적 기억 저장·수정·망각과 업무 재개는 SUP-01~10으로 확인했다.
