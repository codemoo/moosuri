# Equality, authority and uncertainty

The irreversible send commitment remains the only source of a send carrier. Its transaction stores schema31 evidence (original account/auth and connection epochs, action revision/digest, private dispatch nonce, RFC ID, reply thread, commitment time and v1 SHA256 fingerprint) before dropping raw bytes. Unknown actions purge content; restart preserves bounded evidence and never reconstructs a payload. Legacy rows get oracle_version0 with no fingerprint and can never acquire an oracle from a fetched message.

The v1 oracle operates on complete bounded frozen/raw MIME, never ParsedMail. It accepts a single text/plain MIME part, rejects encoding problems, attachments, unsupported or duplicate headers and wrong RFC IDs. It preserves all complete supported header values (From/To/Cc/Bcc/subject/reply metadata, MIME/transfer encoding) and the entire encoded body. Only CRLF versus LF, header folding and the generated Date header are normalized. It deliberately does not normalize charset/encoding transformations, address order or added transport headers. Such provider changes, including missing Bcc, stay unresolved. A hash match is application equality evidence, not provider attestation or idempotency.

A private Store permit carries the original action and a random 90-second read lease. Every credential fetch, refresh save and observation CAS reloads immutable evidence and exact action nonce/revision/digest plus active account, auth epoch, password/recovery/temporary expiry, owner-scoped active connection/epoch and readonly scope. It does not manufacture UserContext. App pins and credential revision fence refreshes. Network IO is outside SQLite. Revocation or withdrawal discards late lookup observations; a real late send-response receipt keeps its existing original-nonce accounting semantics.

Automatic budget and next due persist before IO; crashes cannot reset four attempts. Manual checks are authenticated owner actions, at most one per 60 seconds, and share the same mailbox lock. Each lookup uses at most one list GET (max5 candidates) and one raw GET only if the list is complete and unique. Zero, duplicates/multiple, any next-page token, wrong returned IDs/thread/SENT label, unsupported MIME or unequal fingerprint remain unknown. Total transport timeouts and read-lease expiry bound execution; no resend path exists.

Lookup status is a sidecar. `matching_sent_observed` leaves `outcome_unknown` and provider-response receipt columns untouched. Observations never erase an existing match; send-response receipt is authoritative and conflicting IDs are exposed as a receipt conflict. Restore nulls leases/next due and quarantines lookup rows while existing token quarantine disconnects all restored mailboxes. Old grants cannot be reused.

A non-default connector `test-fixtures` feature supplies only a hidden numeric loopback SocketAddr constructor for cross-crate actual-service tests. Agent enables it only in dev-dependencies. There is no runtime host setting, environment flag, CLI override, redirect, proxy or network retry. Default production dependency resolution must not enable the feature.
