# Admission before durable mission-round recording

The Runtime checks the validated ToolRound outcome before recording mission
proposal text or typed calls. Completed output and validated tool continuations
retain the existing path. Incomplete output settles as incomplete/output_limit;
refusal settles as refused. Neither path creates a candidate, input wait or
report. Failed/refused tool rounds already fail in the transport decoder; actual
Runtime cases ensure that no tool from those rounds executes.

No schema, provider fallback, automatic retry, authority, mail approval or budget
change is needed. Prior completed read/calculation receipts and observed token
usage remain; non-successful text never becomes a resumable completed capsule.

Every new capsule also stores its validated terminal marker in that transaction.
Recovery rejects missing/invalid proof before plan/action admission, unfinished
tool replay, final verification or a clarification wait. Legacy ambiguous pending
work becomes unknown without inference; already completed receipts remain. The
local-final capacity exception requires an explicitly completed marker.

The foreground cost gate treats explicit answer/explanation continuations as
ordinary conversation when their only trigger was a generic Korean continuation
verb. All other date/delegation/control cues remain independent; explicit UI
selection and original bounded clarification continue before the gate. A shared
core helper recognizes only complete generic continuation forms and also prevents
the preceding task receipt from inferring a target for those forms. Unknown or
named-task phrases retain their existing path.
