## ADDED Requirements

### Requirement: Qualified local recipe admission
New delegated missions SHALL admit only their owner's currently qualified local recipe pins without widening saved authority.

#### Scenario: New task with proven private procedure
- **WHEN** the owner creates a one-off or recurring mission
- **THEN** eligible source/exact arithmetic/workflow/evidence recipes retain their exact pin and metadata
- **AND** parcel/external writes/credential execution remain unavailable and old saved profiles gain no pins.

### Requirement: Fresh bounded execution and evidence
A mission SHALL execute local recipes with fresh accepted-task inputs, current evidence and original receipt/budget checks.

#### Scenario: Source-bound procedure reused in a mission
- **WHEN** a source-bound learned recipe executes
- **THEN** literal parameters resolve only in the current accepted task/constraints and the source is read again
- **AND** request metadata, verification values and replaced history are not parameter authority.

#### Scenario: Successful exact result and replay
- **WHEN** an admitted recipe completes and the same slot is retried
- **THEN** the stored receipt is returned without duplicate charge; exact graph/evidence results can satisfy decimal checks and appear in result receipts
- **AND** the mission creates no new learning proof and semantic conditions still need user review.

### Requirement: Actual recurring dependency lifecycle
Recurring missions SHALL track actual private recipe use and require explicit recovery after a dependent recipe becomes unavailable.

#### Scenario: Direct execution without reading instructions
- **WHEN** a recurring child executes an admitted recipe directly
- **THEN** its exact pin becomes a dependency, even without an earlier skill read.

#### Scenario: Disable, withdrawal and explicit recovery
- **WHEN** a used recipe is disabled, removed or loses its proofs
- **THEN** used output and late execution are fenced and dependent schedules pause while discovery-only schedules continue
- **AND** enabling the exact qualified recipe does not automatically resume the schedule.

### Requirement: Exact recurring comparison
Changes-only notifications SHALL compare verified current values and source identity without treating fresh receipt addresses as content changes.

#### Scenario: Repeated local recipe result
- **WHEN** adjacent successful occurrences have the same rendered result, calculation values and source ID/revision/literal within the same schedule revision and account epoch
- **THEN** existing exact-result suppression can omit the duplicate notification while retaining both execution records.
