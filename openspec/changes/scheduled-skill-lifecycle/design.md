The immutable recurring model's agent_profile remains the original discovery upper
bound. A separate private used_skill_pins JSON member accumulates exact successful
SkillRead pins within the same writer transaction as the tool result. Retained
successful typed child receipts backfill older parents once; advertised metadata
and skill preflight do not count as use. A concrete stored call denied by a racing
withdrawal records only that attempted admitted pin for exact recovery.

Enabled installations permit their exact active and retained previous snapshots.
Update/rollback never substitutes a newer revision. Once an old used pin is no
longer retained, disable or remove makes it ineligible. Managed bundled twins are
also excluded. Each new occurrence filters the original profile to eligible pins;
newly installed/updated skills cannot expand it. General foreground disable keeps
admitted-run behavior; remove preserves existing revocation for admitted ordinary
runs and actual used/stored-read recurring runs. Discovery-only recurring children
are not dependencies and are not broadly revoked.

Lifecycle mutation, occurrence admission, actual read and mission authority guard
check the applicable exact dependencies. Existing paused state with needs_skill
reason retires queued/claimed occurrences and unfinished children, retaining
accounting and tool receipts. Re-enable never resumes. Explicit resume requires
all exact dependencies and uses the existing next-future time oracle; misses and
old children do not replay or receive fresh budgets. Private learned executable
routes remain excluded from missions, so this unit adds no private route scheduler.

No migration is required: recurring model JSON already preserves immutable private
execution metadata, and existing schedule reasons are extensible text. Restore
retains the JSON/receipts and existing schedule/mission quarantine remains binding.

GC runs only during explicit lifecycle mutations, deleting at most8 public package
rows. Any active/previous installation across users, historical chat profile, tool
input/result/checkpoint, recurring original profile/used pin or cached catalog
reference retains the snapshot. Conservative substring checks can retain extra
bytes rather than guessing about references. Tombstones and receipts are never
collected. This bounds deletes, while reference reads scale with retained history;
there is no general historical GC or periodic scan/LLM. An uncatalogued uninstalled
preview has no durable execution pin and may become a cache miss; it must be
re-previewed at its exact identity, never installed from substituted bytes.
