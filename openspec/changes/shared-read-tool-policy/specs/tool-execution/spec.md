## ADDED Requirements

### Requirement: Shared closed tool classification
The assistant MUST use a single closed built-in capability contract for model
exposure and durable admission in live guidance, missions and task monitors.
Unknown tools MUST fail closed. The contract MUST NOT replace current contextual
authority, evidence, profile, account or lifecycle checks.

#### Scenario: Mission tool drift is rejected before exposure
- **WHEN** a broad profile includes parcel history, browser or terminal native reads
- **THEN** ordinary mission definitions omit those unsupported tools
- **AND** explicitly delegated Gmail/primary Calendar reads retain their current guards

#### Scenario: Live guidance cannot introduce effects
- **WHEN** a live read channel exists before guidance, after guidance is applied or after its receipt cap
- **THEN** Store rejects artifact writes, mail draft effects, mission effects, browser and terminal native requests at tool admission
- **AND** admitted saved reads, recipe guidance and exact calculation continue within the original budget
- **AND** a failed argument parse remains a bounded error receipt for model repair

#### Scenario: Recipe classification preserves nested authority
- **WHEN** an admitted learned recipe is invoked
- **THEN** its current pin, route and literal argument checks still apply
- **AND** a compound draft/report route still requires its original separate effect/report contract

#### Scenario: Task monitor keeps exact-source bounds
- **WHEN** a monitor child requests a read
- **THEN** only the current exact source/revision with the accepted range and aggregate budget is admitted
- **AND** ordinary search, source calculation, recipes and external reads are excluded

### Requirement: Rejected mission work settles the current run
A mission driver MUST convert Store admission/execution failures through the
existing failure mapping and terminal transition. It MUST NOT silently leave the
current dispatched round active or claim a verified result.

#### Scenario: Valid rounds exhaust the original tool budget
- **WHEN** an individually valid second tool round exceeds the original run-wide tool budget
- **THEN** the mission becomes partial through the existing budget failure mapping
- **AND** no extra inference or restart is needed to settle it
- **AND** no verified result is published

#### Scenario: Committed local work fails during restart replay
- **WHEN** a current committed local slot fails its Store budget check after reopening
- **THEN** the same failure mapping settles the resumed mission partial
- **AND** no verified result or additional model dispatch is produced
- **AND** successful local replay retains its original receipts and continuation behavior
